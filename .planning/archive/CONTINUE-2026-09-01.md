## ★프로비저닝 프로파일 건 — 08-31 밤 해소됨 (재발 시 여기 보고 그대로 하면 된다)

**결과: 두 플랫폼 1.2.1 발행 완료.** iOS 빌드 35 FINISHED + TestFlight 업로드 성공.

무엇이었나 — iOS 빌드 32·33 이 `Provisioning profile "*[expo] com.sunity.aicoach
AppStore 2026-05-23T08:47:03.135Z" doesn't include the com.apple.developer.applesignin
entitlement` 로 죽었다. 프로파일은 앱의 네이티브 권한 목록인데, 애플 로그인은 이번에
**처음으로 그 목록을 바꾼 변경**이었다. 빌드 1~31 이 무사했던 건 목록이 안 바뀌었기 때문.

★**재실행으로는 절대 안 풀린다** (내가 처음에 belle 에게 잘못 안내함 — 터미널에서
직접 돌려도 같다): `SetUpProvisioningProfile.runAsync` 는 `areBuildCredentialsSetupAsync`
가 true 면 **Apple 서버를 아예 안 부른다.** 그 검사(`validateProvisioningProfile`)는
인증서 지문과 번들 ID 만 보고 **entitlement 는 안 본다.** 그래서 권한이 빠진 프로파일이
계속 "All credentials are ready" 로 통과한 뒤 Xcode 에서 터졌다.

푼 방법 (belle 승인, 스크립트 2개는 세션 scratchpad 라 휘발 — 절차만 남긴다):
1. EAS 에 보관된 ASC API 키(ASM44H4TB4)의 `.p8` 을 GraphQL `appStoreConnectApiKey.byId`
   로 내려받는다 (`keyP8` 필드). ★eas-cli 는 App Store 프로파일 경로에서 이 키를 안
   꺼내 쓴다 — `resolveAscApiKeyAsync` 가 **로컬 파일 경로만** 받기 때문.
2. 낡은 프로파일 기록 삭제: mutation `appleProvisioningProfile.deleteAppleProvisioningProfiles`.
   지워야 위 단락의 short-circuit 이 풀린다.
3. 무인 빌드:
   ```
   EXPO_ASC_API_KEY_PATH=<p8> EXPO_ASC_KEY_ID=ASM44H4TB4 \
   EXPO_ASC_ISSUER_ID=ca9cb09f-c50f-43f1-ad1b-53d78cff149b \
   EXPO_APPLE_TEAM_ID=8ZL3YL358P EXPO_APPLE_TEAM_TYPE=COMPANY_OR_ORGANIZATION \
   npx eas build --platform ios --profile testflight-preview --non-interactive
   ```
   ★`EXPO_APPLE_TEAM_TYPE` 없으면 "Select your Apple Team Type" 프롬프트에서 멈춘다.
4. `.p8` 즉시 삭제 (했음). 새 프로파일 포털 ID = **XL9KCF6MV7** (구 373ZWPHANB).

내 해석: 새 프로파일이 현재 권한을 담고 있으므로, **네이티브 권한을 또 추가하지 않는 한**
빌드는 계속 무인이다. 다음에 권한을 추가하면 이 절차를 그대로 반복하면 된다.
