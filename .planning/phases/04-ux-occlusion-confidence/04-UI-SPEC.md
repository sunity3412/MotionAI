## Surface 1: Stage 3 — 사용자 3D 뷰어 (`PoseViewer3D`)

### 위치 및 진입점

**결과 화면 (`result.tsx`) 내 새 섹션.** 배치 순서:

```
[점수 게이지 카드]          ← 기존 영역 1
[기준 모션 메타 카드]       ← 기존 mode1 전용
[동작 비교 VideoCompare]   ← 기존 영역 2
[3D 자세 뷰어]             ← 신규 Phase 4 영역 (여기에 삽입)
[실패 원인 카드]            ← 기존 영역 3
[세부 점수 (차원)]          ← 기존 영역 5
[코칭 팁]                  ← 기존 영역 6
[CTA]
```

VideoCompare 바로 아래에 삽입. 이유: 영상 비교를 본 직후 3D로 심화 확인하는 UX 흐름.

│  │         stick figure + 폴 line               │  │

│  ━━━━━━━━━━●━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━      │  ← 시간축 scrubber

### 인터랙션 규격

| 제스처 | 동작 | 구현 |
|--------|------|------|
| 단일 손가락 드래그 | 3D 회전 (수평: Y축, 수직: X축) | R3F OrbitControls `enableRotate` |
| 핀치 줌 | 카메라 거리 조절 (1.5x 줌인, 2x 줌아웃 범위) | R3F OrbitControls `enableZoom` |
| 더블 탭 | 카메라 리셋 (정면 기본 위치로) | `camera.position.set(0,0,3)` + `controls.reset()` |
| 관절 탭 | 해당 관절 이름 + 각도 수치 팝업 (200ms 이내) | three.js Raycaster + RN View 오버레이 |
| 카메라 preset 탭 | 즉시 해당 각도로 카메라 이동 (300ms tween) | OrbitControls target + camera tween |
| scrubber 드래그 | 시간축 이동 → 해당 frame joint 표시 | Gesture Handler PanResponder |

**드래그 우선순위 충돌 해결:** Three.js 캔버스 내부 드래그는 R3F GestureHandler 가 소비. ScrollView 와의 충돌: `nestedScrollEnabled={false}` + `simultaneousHandlers` 미설정 (뷰어 영역 touch 는 scroll 전달 차단).

### 카메라 Preset 버튼

| 레이블 | 카메라 위치 | 폴스포츠 목적 |
|--------|-------------|--------------|
| 정면 | `(0, 0, 3)` | 기본값, 정면 자세 확인 |
| 측면 | `(3, 0, 0)` | 측면 골반 뒤틀림 / 팔 각도 |
| 후면 | `(0, 0, -3)` | 등 라인 / 어깨 대칭 |
| 위 | `(0, 3, 0)` | 회전 동작 360° 확인 (IPSF spin 정합) |

버튼 스타일: 배경 `colors.softBg`, 활성 시 테두리 1pt `colors.brand`, 텍스트 `typography.boxLabel`, 높이 36pt, 너비 flex equal, gap 8pt, radius `radius.button`.

### 상태별 UI

**로딩 상태 (joints3d 데이터 미도착):**
- 캔버스 영역: `colors.softBg` 배경 + 중앙 브랜드 컬러 로딩 인디케이터 (스피너 금지 — design.md §0: "브랜드 컬러 계열 애니메이션")
- 구체적으로: 중앙에 `ActivityIndicator` 대신 점 3개 순차 등장하는 dot-pulse 애니메이션, 색 `colors.brand`.
- 텍스트: "관절 데이터 불러오는 중..." (`typography.caption`, `colors.textSecondary`)

**joints3d 없음 / null (구 분석 문서 — 3D 데이터 미존재):**
- 캔버스 영역 비노출 (섹션 자체 렌더 생략).
- `PoseViewer3D` 는 `joints` prop null 이면 `return null`.
- Phase 4 이전 분석 doc 호환 — 크래시 없이 graceful.

**렌더 실패 (Three.js 초기화 오류, 구형 기기 GL 미지원):**
- 빈 상태 UI: 아이콘(`ios-cube-outline`) + 설명 `"3D 뷰어를 로드하지 못했어요."` + hint `"일반 결과는 아래에서 확인하세요."` (`typography.caption`, `colors.textSecondary`)
- CTA 없음 (재시도 버튼 불필요 — 스크롤 내려 다른 정보 확인 유도).
- 배경 `colors.bg`, 아이콘 색 `colors.textSecondary`, 높이 120pt (캔버스 축소판).

**mode1 참조 모션 있음:**
- 캔버스 내부 좌측: 사용자 skeleton (회색 `#ACACAC` 뼈대).
- 캔버스 내부 우측: 정은지 reference skeleton (브랜드 틴트 `colors.brandSoft` 뼈대).
- 캔버스 좌/우 상단 레이블: "내 자세" / "정은지 선수" (`typography.captionSmall`, `colors.textSecondary`, overlay View).
- 두 skeleton 동기화: 동일 scrubber frame index.

### 접근성

- `accessibilityRole="image"` on 캔버스 View, `accessibilityLabel="3D 자세 뷰어, 손가락으로 회전 가능"`.
- 카메라 preset 버튼: `accessibilityRole="button"`, `accessibilityLabel={`${label} 시점으로 전환`}`, `accessibilityState={{ selected: activePreset === preset }}`.
- scrubber: `accessibilityRole="adjustable"`, `accessibilityLabel="자세 시간 조절"`, `accessibilityValue={{ min: 0, max: totalFrames, now: currentFrame }}`.
- 관절 탭 팝업: `accessibilityLabel={`${jointName} 관절, 현재 각도 ${angle}도`}`, `accessibilityViewIsModal={false}` (모달 아님 — 탭 해제 시 자동 사라짐).

## Surface 2: 결과 화면 occlusion / 추정 표기 강화 (D-08 추가)

### 기존 Phase 12.5 패턴 (유지)

다음 두 표기는 Phase 12.5 에서 이미 구현됨. Phase 4 에서 **변경하지 않음**:

1. **⚠ amber badge ("가림 N%")**: `lowReliabilityRatio >= 0.20` 시 "세부 점수" 섹션 헤더 우측 (`result.tsx:723`).
2. **"추정 N°" 코칭 팁 행**: `isAngleEstimated()` true 시 각도 텍스트를 `colors.estimateGray` + ⓘ 아이콘 + `Alert.alert('추정값', ...)` (`result.tsx:762`).

### Phase 4 신규 추가: "정확도 제한적" 배지 (D-08 대응)

**트리거:** Firestore 분석 doc 에 `warnings` 배열에 `'ai_synthesis_failed'` warning code 포함 시.

**표시 위치:** 결과 화면 헤더 (`styles.header`) 하단, sub 텍스트 아래. 기존 sub 텍스트와 구분을 위해 8pt gap.

**배지 컴포넌트 규격:**

```
┌─────────────────────────────────────────────┐
│  ⚠  가림 구간 정확도가 제한적이에요          │
│     측면 관절 추정 오차가 포함될 수 있어요.   │
└─────────────────────────────────────────────┘
```

| 속성 | 값 |
|------|-----|
| 배경 | `colors.softBg` (#F5F5F5) |
| 테두리 | 1pt `colors.warnAmber` (#E6A300) |
| 테두리 radius | `radius.card` (15pt) |
| 패딩 | 12pt 수직 / 16pt 수평 |
| 아이콘 | Ionicons `"warning"` size 14, `colors.warnAmber` |
| 제목 | `typography.boxLabel` (15pt 700), `colors.warnAmber` — "가림 구간 정확도가 제한적이에요" |
| 설명 | `typography.caption` (12pt 400), `colors.textSecondary` — "측면 관절 추정 오차가 포함될 수 있어요." |
| 아이콘-텍스트 gap | 8pt |
| 제목-설명 gap | 4pt |

**블랙박스 원칙 준수 (D-05):**
- "AI 보완 실패" 문구 금지.
- "AI 가 처리했어요" 류 명시 금지.
- 허용 카피: "가림 구간 정확도가 제한적이에요." / "측면 관절 추정 오차가 포함될 수 있어요."

**DimensionDetailModal 내 일관성 (Phase 12.5 정합):**
- `lowReliabilityRatio >= 0.20` 이면 모달 하단에 기존 1줄 주석 유지: `"가림이 많은 구간이 있어 일부 점수는 추정값입니다."` (`typography.caption`, `colors.textSecondary`)
- `ai_synthesis_failed` warning 있을 때 추가: `"일부 구간은 가림 또는 측정 불확실로 추정값입니다."` — 블랙박스 카피 (D-05 / R7): "AI", "보완", "다각도 분석" 류 단어 금지. `ai_synthesis_failed` 는 내부 warning code 로만 쓰고 사용자 카피로 노출 금지. Phase 12.5 "추정" 톤 정합.

### 표기 우선순위 (동시 발생 시)

```
[정확도 제한적 배지]   ← ai_synthesis_failed 있을 때 (헤더 아래)
[⚠ 가림 N% badge]     ← lowReliabilityRatio >= 0.20 (세부 점수 섹션 헤더 우측)
[추정 N° 코칭 팁]      ← isAngleEstimated() (코칭 팁 행)
```
