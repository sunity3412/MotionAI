# Phase 08.1: axis-metric-redesign - Context

**Gathered:** 2026-06-09
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 8 의 axis distance metric (pelvis/chest distance from pole axis) 이 IPSF 도메인에서 거짓 가정 위에 박제됐음을 research 가 확정 — "축 이탈 글로벌 deduction" 자체가 IPSF Code of Points 에 존재하지 않음. distance 차원을 **3-way lockstep 으로 제거** + tilt-only metric 으로 전환 + 정은지 5영상 분포 + IPSF tolerance 매핑 기반 threshold calibration. Phase 9 (ForceDirectionPattern) 은 본 phase 종료 기다리지 않고 tilt + stability + contact 위에 평행 진입.

**Scope IN**:
- AxisDeviationMetric schema 변경 (distance 필드 + scale_denominator + coordinate_space 제거)
- tilt metric 재설계 (shoulder/hip 이미 산출 중 — 활용 + threshold 박제)
- 정은지 5영상 tilt 분포 (P25/P50/P75/P90) 산출
- IPSF tolerance 카테고리 (예: "±20°") 매핑 → medium/high threshold
- pipeline rewire (compute_axis_deviation 호출 정합)
- 3-way lockstep 동행 (TS interface + Python dataclass + docs §9)
- 정은지 5영상 재sweep + 분포 변경 evidence 박제

**Scope OUT** (Deferred):
- "기술 조건부 distance" 평가 (Iron X "body 90° to pole" 등) → Phase 11 (Gemini 기술 인식기 + GeometricCriterion)
- ForceDirectionPattern 추론 → Phase 9 (평행 진입)
- contact / jerk / jitter / phaseBoundaries 차원 → Phase 8 본체 정상 산출, 손대지 않음
- 5트랙 채점 시스템 → Phase 16

</domain>

<decisions>
## Implementation Decisions

### Distance 필드 처리 — Hard Break (D-01)

- **D-01**: AxisDeviationMetric 에서 `pelvis_distance_from_pole_axis`, `chest_distance_from_pole_axis`, `scale_denominator`, `coordinate_space`, `deviation_direction` 필드 **전부 제거**. 남기는 필드: `phase`, `shoulder_tilt`, `hip_tilt`, `severity`, `confidence`, `warnings`.
- **Why**: research 가 IPSF 에 "축 이탈 글로벌 deduction" 자체가 없음을 확인. 정은지 distance 분포 2.65~3.80 은 RTMW 임의 단위 자연 위치 (도메인 의미 부여 불가). 필드 보존 시 frontend / Phase 9 가 잘못된 신호로 오인 — 차라리 깨끗하게 제거.
- **3-way lockstep 동행**: TS interface (`app/src/types/analysis.ts`) + Python dataclass (`backend/shared/python/sunity_shared/analysis/force_signals.py`) + docs (`docs/contract.md §9`) 한 commit 내 atomic 변경.
- **Frontend null-guard**: `app/src/lib/userAnalyses.ts` normalize 가 null 처리 — 변경 후 회귀 0 보장.
- **Migration**: 기존 Firestore docs 의 distance 필드 = 무시 (read-side 가 안 읽음). 별도 backfill 불필요.

### Threshold Calibration — 정은지 5영상 + IPSF Tolerance 조합 (D-02 / D-03)

- **D-02**: Wave 1 진입 시 **정은지 5영상 (현재 보유분) tilt 분포 산출**:
  - `shoulder_tilt`, `hip_tilt` 각각 P25 / P50 / P75 / P90 산출 (5영상 × 5 phase = 25 data points)
  - 산출 산물: `backend/judging_data/tilt_thresholds.yaml` (또는 equivalent)
  - **medium cutoff** = max(정은지 P90, IPSF tolerance) 박제 — 정은지 baseline 이 5/5 영상에서 `low` 유지 보장
  - **high cutoff** = medium × 1.5 또는 IPSF major fault tolerance 박제 (research §3 정합)
- **D-03**: IPSF tolerance 매핑 — research §2 의 "기술 조건부 tolerance" (예: Iron X "body 90° to pole ±20°") 의 ±20° 같은 수치를 **default global tolerance** 로 활용. 동작 종류 무관하게 적용 (기술 조건부는 Phase 11 가 담당).
- **Future** (D-04): 정은지 추가 영상 확보 시 `tilt_thresholds.yaml` 의 수치만 재산출 (calibration script 재실행) — 코드 변경 0. belle 가 추가 영상 확보 시 "[정은지 추가 N개] 확보됐어" 신호 → Claude 가 calibration 재실행 + commit. **plan 변경 0, pipeline 영향 0**.

### Phase 9 Dependency — 평행 진입 + Raw Signal Only Guard (D-05, iteration 2 갱신 — Codex C-M4 정합)

- **D-05**: Phase 9 (ForceDirectionPattern) 는 Phase 8.1 종료 기다리지 않고 **평행 진입**. Phase 9 가 사용하는 신호 = **raw `shoulder_tilt` + `hip_tilt` + `confidence` + `warnings`** (rotation-only, origin-invariant). **`severity` 직접 trust 금지** — `axis_metric_transitional` 또는 `tilt_unavailable` 또는 `tilt_thresholds_fallback` warning 포함 시 severity 무시.
- **Why (Codex C-M4)**: Phase 8.1 calibration 은 정은지 5영상 기반 elite false-positive 차단 만 검증. 진짜 production validity 는 Phase 8.1 sensitivity evidence + Phase 9 실 영상 검증 후 확정. Phase 9 가 calibrated 'low' 를 line quality correctness 로 trust 시 Phase 8 fail pattern 재발 위험.
- **Phase 8.1 종료 시점**: Phase 9 가 tilt threshold 최종 박제만 import (calibration 결과). severity 사용은 Phase 8.1 의 SWEEP-EVIDENCE §11 sensitivity 통과 후만.
- **Phase 9 plan 작성 시 명시 guard**: acceptance 에서 `axisMetrics[*].severity` 직접 dependency reject. raw tilt feature engineering 만 허용.

### Plan 구조 — 중규모 3 plan (D-06)

- **D-06**: Wave 0/1/2 = 3 plan 구조 — Phase 8 의 4-plan 패턴과 일관 (scaled down).
  - **Wave 0** (schema migration): TS + Python + docs §9 distance 필드 삭제, frontend null-guard, lockstep 테스트
  - **Wave 1** (tilt metric + calibration): 정은지 5영상 P25/P75 산출 script, `tilt_thresholds.yaml` 박제, IPSF tolerance 매핑, compute_axis_deviation tilt-only 재작성, FPS-invariance 회귀
  - **Wave 2** (pipeline rewire + 검증 sweep): pipeline 호출 정합 + Pod 재배포 + 정은지 5영상 재sweep → 분포 evidence 박제 (목표: severity='low' 5/5)
- **Why**: 각 wave 가 위험 차원 다름 (정적 / 알고리즘 / production 통합) → atomic boundary 자연스러움. wave 단위 commit / 회귀 게이트 / rollback 단위.
