## Verdict

Iteration 2 is substantially better than the first 08.1 plan. The strategic changes are correct:

- Phase 8 distance metric is treated as a semantic failure, not as a threshold-tuning problem.
- The plan now explicitly chooses tilt-only.
- `P90` calibration is replaced in the patch document by `P100 + margin`.
- Wave 0 stub masking is recognized.
- Synthetic sensitivity evidence is added in principle.
- SMPL remains excluded.

But I would still not execute this as-is. The main issue is no longer the strategy. The main issue is plan consistency.

`CODEX-PATCHES.md` contains the right fixes, but the actual executable plan bodies still contain older instructions. An executor could reasonably follow `08.1-01-PLAN.md` or `08.1-02-PLAN.md` literally and reintroduce the same risks the patch document says it fixed.

Recommendation: do one cleanup pass before execution. Merge `CODEX-PATCHES.md` into the three plan files, or explicitly declare `CODEX-PATCHES.md` as the only override source and remove/mark conflicting old sections. After that cleanup, I would approve execution.

## Findings

### BLOCKER: Patch Document And Executable Plans Conflict

`CODEX-PATCHES.md` says the correct calibration is `version: "1.1"` with `p100`, `margin_deg`, and `medium_cutoff_deg = max(p100 + margin_deg, ipsf_tolerance_deg)`.

But `08.1-01-PLAN.md` still says:

- YAML `version: '1.0'`
- `schema_version: 1`
- fields only through `p90`
- `medium_cutoff_deg: max(p90, 20.0)`
- high cutoff = `medium * 1.5`
- drift tests assert `medium_cutoff >= max(P90, 20.0)`

Examples:

- `08.1-01-PLAN.md:34` still defines the old P90 YAML schema.
- `08.1-01-PLAN.md:37` still says `medium_cutoff = max(P90, 20.0)`.
- `08.1-01-PLAN.md:417-425` still defines drift tests around P90.
- `CODEX-PATCHES.md:73-118` says the opposite.

This is a hard execution risk. A plan runner could implement the old P90 path and still claim it followed the plan.

Required fix:

- Make `08.1-01-PLAN.md` internally reflect C-H2/C-H3.
- Remove the old P90 operational cutoff text.
- Update all tests, YAML schema, and script snippets to the same schema.
- Decide whether `schema_version` becomes `2`, or whether `schema_version: 1` remains and a separate `calibration_version: "1.1"` is introduced. Do not leave both meanings ambiguous.

### HIGH: Severity Boundary Still Conflicts With The New Calibration Rule

`CODEX-PATCHES.md` correctly says boundary values should remain low:

- `tilt > medium_cutoff_deg + 1e-9` triggers medium, or
- `tilt <= medium_cutoff_deg` remains low.

But `08.1-01-PLAN.md` still says `_severity_from_tilt()` uses:

- `>= thresholds[1] -> high`
- `>= thresholds[0] -> medium`
- else low

That old rule makes a value exactly equal to the calibrated elite maximum boundary become medium. This contradicts the point of `P100 + margin` and the requested `25/25 low` acceptance.

Required fix:

- Update `_severity_from_tilt()` spec everywhere to:
  - `None -> low` with warning context outside the helper.
  - `tilt > high_cutoff + eps -> high`
  - `tilt > medium_cutoff + eps -> medium`
  - otherwise `low`
- Add `test_severity_boundary_value_is_low`.
- Add a test for `medium_cutoff + 1` and `high_cutoff + 1`.

### HIGH: 08.1-02 Still Allows A Weak Pass

`08.1-02-PLAN.md` still says the binary pass is `25/25 severity == 'low'`.

That is not enough. A missing or fallback metric can still produce severity `low`.

The final sweep must require all of these:

- 25 axis metric instances exist.
- 25/25 have non-null `shoulderTilt`.
- 25/25 have non-null `hipTilt`.
- 25/25 have no `tilt_unavailable`.
- 25/25 have no `axis_metric_transitional`.
- 25/25 have no `tilt_thresholds_fallback`.
- 25/25 have `severity == 'low'`.
- Synthetic sensitivity cases pass.

`CODEX-PATCHES.md` moves in this direction, but `08.1-02-PLAN.md:265-281` still makes low severity the main pass gate. That is too weak.

Required fix:

- Replace the pass criteria block in `08.1-02-PLAN.md`.
- Add a `measured_low_count` separate from `severity_low_count`.
- Explicitly fail if any unavailable/fallback/transitional warning is present.

### HIGH: Calibration Fallback Path Can Become Circular Threshold Chasing

`08.1-01-PLAN.md` allows option B: Firestore unreachable, skip real YAML calibration, use fallback `(25.0, 37.5)`, and defer real calibration to Wave 2.

That fallback is useful for local imports and tests, but dangerous for production calibration. If Wave 2 runs with fallback thresholds and fails, the plan says to rerun calibration on the Wave 2 sweep itself. That can become circular: run with bad thresholds, observe failure, raise thresholds using the same output until the elite set passes.

The better rule is:

- Primary calibration source must be the inherited Phase 8 sweep docs that already contain real tilt values, before 08.1 changes.
- If Firestore is not reachable, extract those 25 real tilt values once into a repo artifact such as `08.1-CALIBRATION-SOURCE.json`.
- Do not calibrate operational thresholds from a failed Wave 2 sweep unless it is explicitly marked as a new calibration source and reviewed.

Required fix:

- Make Wave 1 real calibration a hard gate for production Wave 2, unless a checked-in calibration-source artifact exists.
- Allow fallback only for unit tests and local import safety.
- In `sweep_phase8_1.py`, fail if fallback thresholds are active unless `--allow-fallback` is set, as the patch already suggests.

### MEDIUM-HIGH: Raw Tilt Semantics Are Still Ambiguous

`08.1-01-PLAN.md` says shoulder/hip tilt values preserve signed degrees, and severity uses `abs()`.

But the current pole-aligned helpers return unsigned values:

- `_shoulder_tilt_pole_aligned()` uses `abs(dz) / norm`.
- `_hip_tilt_pole_aligned()` uses `abs(dz) / norm`.

So 3D raw tilt is already unsigned `[0, 90]`. The 2D helper currently returns signed angle difference, and the patch wants to normalize it to undirected `[0, 90]`. After C-M1, both 3D and 2D will be unsigned.

This is fine if the metric is an unsigned body-line inclination signal. It is not fine if Phase 9 expects directionality from shoulder/hip tilt.

Required fix:

- Change the plan language from "signed 보존" to "unsigned undirected tilt in degrees `[0, 90]`".
- If signed direction is needed later, create a separate field and a separate validation plan. Do not overload `shoulderTilt` / `hipTilt`.

### MEDIUM: YAML Versioning Needs One Clear Meaning

The patch uses `version: "1.1"` to indicate iteration-2 calibration. The old plan uses `schema_version: 1`. The sweep hygiene patch says fail if `version < 1.1`.

This is easy to implement incorrectly because `version` and `schema_version` are doing different jobs.

Recommended schema:

```yaml
schema_version: 2
calibration_method: "elite_p100_plus_margin"
calibration_version: "1.1"
```

Then:

- drift tests branch on `schema_version`.
- sweep script checks `calibration_method == "elite_p100_plus_margin"`.
- evidence reports `calibration_version`.

This avoids string-comparing arbitrary `version` fields.

### MEDIUM: Sweep Metadata Should Not Be Stuffed Into `sourceLabel`

C-M5 says to put commit hash and threshold checksum into `sourceLabel`. But the current Firestore read snippet extracts the display name with:

```python
d.get('sourceLabel', '').replace('sweep_phase8_1:', '')
```

If `sourceLabel` becomes a compound metadata string, this read path becomes brittle.

Recommended fix:

- Keep `sourceLabel: f"sweep_phase8_1:{name}"`.
- Add separate scalar fields:
  - `sweepCommitHash`
  - `thresholdChecksum`
  - `thresholdCalibrationMethod`
  - `thresholdCalibrationVersion`
  - `sweepCreatedAtMs`
- Add those fields to evidence extraction.

## If I Were Executing This

I would not add another conceptual redesign. The strategy is now right. I would do a cleanup pass that makes the plan executable:

1. Promote `CODEX-PATCHES.md` into the source plans.
   Merge C-B1/C-H1/C-MH1 into 08.1-00, C-H2/C-H3/C-M1 into 08.1-01, and C-M3/C-M5 into 08.1-02. Keep `CODEX-PATCHES.md` as history, not as an override document.

2. Make calibration a production gate.
   Wave 2 must not run with fallback thresholds unless the run is explicitly a fallback-mode test. Real production sweep should require a checked-in YAML generated from verified 25 non-null real tilt values.

3. Rename the threshold rule in YAML.
   Use `elite_p100_plus_margin`, not "P90", anywhere in operational cutoff logic. Keep P90 only as distribution visibility.

4. Treat final acceptance as two gates.
   Gate A: elite references are measured and low. Gate B: synthetic sensitivity catches medium/high. Both must pass.

5. Document tilt as unsigned orientation.
   This avoids Phase 9 using it as directional evidence.

6. Update Phase 9 guard now.
   Phase 9 should consume raw shoulder/hip tilt, confidence, and warnings. It should not trust severity when transitional, unavailable, or fallback warnings exist.
