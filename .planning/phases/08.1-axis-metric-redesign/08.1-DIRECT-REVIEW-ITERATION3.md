The new YAML schema nests thresholds under:

```yaml
  operational_cutoff:
    medium_cutoff_deg: ...
    high_cutoff_deg: ...
```

But the loader snippet in `08.1-01-PLAN.md` still reads:

```python

data['shoulder_tilt']['high_cutoff_deg']
```

Concrete reference:

- `08.1-01-PLAN.md:281-288`

If implemented literally, the loader will raise `KeyError`, fall back to `(25.0, 37.5)`, and Wave 2 will fail because `tilt_thresholds_fallback` appears.

```python
shoulder_node = data["shoulder_tilt"]["operational_cutoff"]

```

Also validate:

- `schema_version == 2`
- `calibration_method == "elite_p100_plus_margin"`
- `source.null_tilt_verified is True`

### HIGH: Sweep Script Swallows `_process` Failures

The Wave 2 sweep script catches `_process` exceptions, prints a failure, and continues. It still returns `0` at the end.

Concrete references:

- `08.1-02-PLAN.md:260-275`

This can make "sweep CLI exit 0" pass while one or more videos failed to process. Later Firestore checks may catch missing results, but the script acceptance itself is misleading.

Required fix:

- Track failed analysis IDs.
- Return non-zero if any `_process` failed.
- Include failure details in stdout and SWEEP-EVIDENCE if a partial run is being analyzed.

Recommended pattern:

```python
failures = []
...
except Exception as exc:
    failures.append((name, analysis_id, repr(exc)))
...
if failures:
    print(json.dumps({"failures": failures}, ensure_ascii=False, indent=2))
    return 1
```

## What Is Now Good Enough

I would keep these decisions:

- Distance field deletion, not recalibration.
- `AxisDeviationMetric` name retained for now with caveat, future `BodyLineTiltMetric` rename deferred.
- Unsigned tilt semantics `[0, 90]`.
- P100 + margin for elite false-positive prevention.
- Boundary-low severity rule.
- Non-null calibration preflight.
- `axis_metric_transitional` top-level warning.
- Phase 9 raw signal only guard.

- Sweep metadata as separate Firestore scalar fields instead of overloading `sourceLabel`.

These are the right technical direction.

## What I Would Do

I would stop adding patches and do a "canonicalization pass":

1. Delete stale implementation snippets.
   Any section that still says `schema_version=1`, `version: '1.0'`, `max(P90, 20.0)`, or old flat `medium_cutoff_deg` should be rewritten or removed.

2. Make `08.1-01` the source of truth for schema v2.
   The loader, calibration script, drift tests, verification, success criteria, artifacts, and output summary must all say the same schema:
   `schema_version=2`, `calibration_method=elite_p100_plus_margin`, `distribution.p100`, `operational_cutoff.*`.

3. Turn Firestore-unreachable into a real artifact path.
   If Firestore is unavailable, require `08.1-CALIBRATION-SOURCE.json`. Do not let production Wave 2 depend on fallback thresholds.

4. Make Wave 2 pass/fail strict.
   The final gate should be `measured_low_count == 25`, no transitional/unavailable/fallback warnings, synthetic sensitivity 5/5, and sweep script exit non-zero on any `_process` failure.

5. Reorder Wave 2 tasks.
   Run Task 2.5 before SWEEP-EVIDENCE generation. Evidence should consume sensitivity output, not reference a future task.

6. Keep Phase 9 conservative.
   Phase 9 should use raw tilt, confidence, and warnings. It should not treat axis severity as correctness until the 08.1 evidence file passes both elite-low and sensitivity gates.
