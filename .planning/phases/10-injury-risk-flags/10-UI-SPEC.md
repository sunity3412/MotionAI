# Phase 10 — UI Design Contract

> Visual and interaction contract for the injury-risk-flag warning layer on the analysis result screen. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Data structure, firing rules, and thresholds are owned by the data/algorithm plan; this doc owns how flags appear and read to the user.

## Typography

Use existing `typography` tokens (`theme/typography.ts`) only — no new sizes. Two weights in play (regular 400, bold 700), consistent with the project.

| Role | Token | Size / Weight | Line Height | Usage in this phase |
|------|-------|---------------|-------------|---------------------|
| Section heading | `typography.sectionTitle` | 20 / 700 | default | "부상 위험 신호" section title |
| Flag title | `typography.boxLabel` | 15 / 700 | default | Each flag's headline (compact, caution tone — deliberately not the louder 18/700 `listTitle`) |
| Body / "why" line | `typography.caption` | 12 / 400 | 18 | Per-flag explanation, disclaimer, "전문가 확인 권유" copy |

Rationale: flag titles use 15/700 (`boxLabel`) rather than 18/700 (`listTitle`) to keep the warning calm and avoid alarm (scope: "과잉 경고로 사용자 불안 유발 금지").

## Color

Light theme, white surface. **The injury-risk warning must NOT use brand red `#FF4B33`.** Brand red is reserved for positive emphasis, CTAs, and highlighted numbers; the project deliberately keeps red away from problem/error states (`colors.ts`: "오류는 의도적으로 틸 — 브랜드 레드와 혼동 방지"). The injury banner uses the established **amber caution semantic** (`warnAmber`), which reads as "주의 / 확인 필요" not "위험 확정" — aligning with the no-anxiety constraint.

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `colors.bg` | `#FFFFFF` | Screen + card background |
| Secondary (30%) | `colors.cardBg` / `colors.softBg` | `#FFFFFF` / `#F5F5F5` | Cards; neutral badge surfaces |
| Accent (10%) | `colors.brand` | `#FF4B33` | Reserved — NOT used by injury banner (see below) |
| Caution semantic | `colors.warnAmber` | `#E6A300` | Injury banner border, warning icon, flag title accent |
| Caution surface (NEW) | `colors.warnAmberBg` | `#FFF6E5` | Injury banner background tint (light amber) — see token addition |
| Body text | `colors.textPrimary` / `colors.textSecondary` | `#0C0C0C` / `#ACACAC` | Flag explanation / disclaimer |

**Accent (`brand` #FF4B33) reserved for:** primary CTA buttons, highlighted numeric values (`highlightNumbers`), positive/progress emphasis, Mode-1 reference framing. **Never** for injury/error states.

**New token to add** (planner/executor — `theme/colors.ts`, additive only, brand hex unchanged):
- `warnAmberBg: '#FFF6E5'` — light amber tint for the injury banner surface, giving clear visual distinction (Success Criterion 4: "시각적으로 구분되고") from white cards AND from the neutral-gray `AccuracyLimitBadge` (`softBg`). If a zero-new-token path is required, fall back to `colors.softBg` (`#F5F5F5`) + `warnAmber` border like `AccuracyLimitBadge` — but the amber tint is the recommended, more distinct treatment.

No second destructive/error color is introduced — there are no destructive actions in this phase.

## Placement & Interaction Contract

**Location:** dedicated section on `app/src/app/analysis/result.tsx`, rendered **immediately after the score gauge card** (the `OctagonScore` card block) and **before the "동작 비교" section**. This gives the safety signal early salience without an alarming modal/interstitial.

**Section structure (top → bottom):**
1. Section title: `부상 위험 신호` (`typography.sectionTitle`).
2. Disclaimer header (one line, `typography.caption`, `textSecondary`): frames the whole section as possibility-only + expert referral (see Copywriting).
3. One `InjuryRiskFlagCard` per active flag (amber banner surface), in severity order (highest first).

**Per-flag card layout:**
- Row 1: `Ionicons name="warning"` (size 16, `warnAmber`) + flag title (`boxLabel`, color `warnAmber`).
- Row 2: "why" line (`caption`, `textPrimary`, lineHeight 18) = posture condition + control-loss signal in plain Korean (D-02 combination), phrased as 가능성.
- Row 3 (shared, once per card OR once per section): "전문가 확인 권유" line (`caption`, `textSecondary`).

**Conditional rendering / states:**
- **No active flags → entire section is OMITTED.** Do NOT render a "안전합니다 / 부상 위험 없음" reassurance — that is a false safety claim and is forbidden (matches the project's graceful-omit pattern, e.g. `bodyProfileSummary`, `openQuestionsForCoach`). Absence of warning ≠ safety guarantee.
- **Mode 1 vs Mode 3:** asymmetry-vs-reference (D-03), trunk/joint hyperextension (D-04/D-05), and control-loss are valid in both modes; "레벨 대비 무리" (D-06) is **Mode 1 only** — its card simply does not appear in Mode 3. No mode toggle UI; visibility is driven by which flags the backend emitted.
- **Severity visual tiers:** keep within the amber semantic — do not escalate to red. Visual differentiation between a lower and higher severity flag may use icon fill / title weight only (both already 700), not a new alarming color. **Do not surface a raw numeric risk score as a headline** — the project value is "수치는 보조, 원인이 핵심"; lead with the cause (body region + why), not a number. Any number, if shown, is inline via `highlightNumbers` and secondary.

**No destructive actions, no CTAs, no modals** are introduced by this phase (the flag cards are read-only informational; optional `자세히 ›` deep-detail is out of scope for v1).

## Copywriting Contract

All Korean. **Forbidden word: "부상" as a confirmed claim** — never "부상입니다 / 부상 위험 있음(단정)". Always frame as **"위험 가능성 / ~할 수 있어요 / 부담 가능성"** + expert referral. No emojis.

| Element | Copy |
|---------|------|
| Section title | `부상 위험 신호` |
| Section disclaimer (header line) | `부상을 확정하는 신호가 아니라, 측정값에서 보이는 위험 가능성이에요. 전문가 확인을 권해드려요.` |
| Flag — 좌우 비대칭 (D-03) | Title: `좌우 비대칭 신호` · Why: `기준보다 좌우 움직임 차이가 크고, 동작이 흔들리는 구간이 있어요. 한쪽에 무리가 갈 가능성이 있어요.` |
| Flag — 요추 과신전 (D-04) | Title: `허리 부담 가능성` · Why: `허리를 깊게 젖히면서 자세가 불안정한 구간이 보여요. 허리에 부담이 갈 수 있어요. (몸통을 한 덩어리로 추정한 값이라 정확하지 않을 수 있어요.)` |
| Flag — 관절 과신전 (D-05) | Title: `무릎·팔꿈치 과신전 가능성` · Why: `무릎 또는 팔꿈치가 반대로 젖혀지는(역꺾임) 자세가 통제가 흔들리는 구간에서 보여요. 관절에 무리가 갈 수 있어요.` |
| Flag — 레벨 대비 무리 (D-06, Mode 1 only) | Title: `레벨 대비 무리한 동작 가능성` · Why: `입력하신 경력 대비 난이도가 높은 동작이고, 반동·흔들림이 함께 보여요. 단계를 낮춰 연습하는 게 안전할 수 있어요.` |
| Expert-referral line (per card or section footer) | `정확한 판단은 강사 또는 전문가와 함께 확인해 주세요.` |
| Empty state (no flags) | (none — section is not rendered; NO reassurance text) |
| Error state | (none — this is a derived deterministic layer; if `SafetyFlag` data is absent/malformed, omit the section silently, matching `result.tsx` graceful-degrade convention) |
| Destructive confirmation | none (no destructive actions in this phase) |

Copy guidance for the executor: keep each "why" to ~1–2 sentences, lead with the body region, state the control-loss observation, end with "~가능성/~수 있어요". The D-04 trunk-rigid-body limitation MUST be acknowledged inline (parenthetical above) per CONTEXT D-04. Numbers, if any, render via `highlightNumbers()` (brand-colored), but avoid leading with a risk-score figure.
