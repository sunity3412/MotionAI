## Plan 12.5-01 Review

### 1. Summary

Plan 12.5-01 is substantially improved and mostly aligned with the phase goal: it fixes the earlier false weighting assumption, adds backend-owned explanation data, keeps frontend backward compatible, and separates mode3 progress from similarity. The remaining risk is not architecture but semantic correctness: the UI copy must not claim more IPSF precision than the current scoring engine actually provides, and the new explanation helpers must use exactly the same inputs/windowing as the score functions.

### 2. Strengths

- Backend-owned `dimensionExplanation` is the right direction. It avoids hardcoding scoring semantics in `result.tsx`.
- Weight handling is corrected from the incorrect `40/30/30` assumption to available-dimension averaging.
- The plan explicitly handles 3/2/1 dimension cases, including mode3 first with line omitted.
- Good contract discipline: TS, Python, docs, exact-key tests, fixtures, and old Firestore docs are all considered.
- Mode3 progress is correctly separated from deficit copy and avoids "% similarity" framing.
- Mock E2E with no network is appropriate for this phase.

### 3. Concerns

- **HIGH - Baseline copy may overclaim IPSF precision.** Current code's `line_score` and `stability_score` are generic heuristics, not full per-motion IPSF criteria yet. Copy like `"정은지 측정값 + IPSF 기준"` risks implying Phase 16-level judging is already integrated. Safer copy would be closer to `"정은지 측정값 + IPSF 실행 기준 참고"`.

- **HIGH - Explanation source can drift from score source unless call-site inputs are pinned.** `line_score()` uses `profile.hold_window` when present, while `extension_deviation()` currently falls back to auto `hold_window()` and ignores `profile.hold_window` in `backend/shared/python/sunity_shared/analysis/dimensions.py`. The new line helper must not reuse that path unless fixed.

- **MEDIUM - `grep balance = 0` is too broad.** `rg balance docs backend app/src` also catches legitimate `balanced` references and historical/research text. Make the cleanup target contract drift only, not every string occurrence.

- **MEDIUM - `34/33/33` can look like real unequal weighting.** Since actual scoring is equal mean, the UI should label these as rounded display percentages or say `"동등 비중"` to avoid false precision.

- **MEDIUM - Release gate is mixed into implementation acceptance.** TestFlight ship and belle real-video validation are valid phase close-out gates, but they depend on external state. Keep them separate from code-complete acceptance.

- **LOW - UI verification is light.** Typecheck will not catch RN text wrapping, card height, or visual crowding after adding baseline/deficit/progress rows.

- **LOW - Helper edge cases need explicit tests.** Include NaN frames, single-frame stability, empty/invalid hold windows, and no EXTEND joints.

### 4. Suggestions

- Add an acceptance criterion: `dimensionExplanation.keys()` must exactly match `dimensionScores.keys()`, and weights must sum to 100 over only those keys.
- Create shared window helper logic so `line_score`, `line_deficits_by_joint`, `stability_score`, and `stability_wobble_by_joint` clamp and slice frames identically.
- Make the pipeline call explicit: pass the same `angles` and `profile` used to compute `absolute_dimension_scores()` into `build_result()` at `backend/functions/pipeline/app.py`.
- Replace broad cleanup with targeted checks, e.g. contract/test drift for dimension key `balance`, while allowing unrelated `balanced`.
- Add frontend fixture assertions or a simulator screenshot check for: with explanation, without explanation, mode3 first, and mode3 second+ delta row.
- Keep `dimensionExplanation` optional in TS for old docs, but always emit the key from new backend results, even if `{}`.

### 5. Risk Assessment

**Overall risk: MEDIUM.**

The plan is technically feasible and covers the main contract/UI/backend surfaces. Risk remains medium because this phase is about trust and transparency: if explanation copy overstates IPSF authority or deficit summaries are computed from a subtly different window than the score, the feature can make the product feel less trustworthy rather than more. Addressing the source-alignment and copy-precision issues should reduce the plan to low risk.
