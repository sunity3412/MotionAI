## 1. System Classification

**System Type:** Hybrid (Structured Extraction 주 + Content Generation 부)

**Description:**
폴스포츠 (Pole Sports) 수강생이 본인 연습 영상을 업로드하면 Gemini Vision 이 4 영역 (A. 정은지 reference 영상 → IPSF 명칭 + clipRange + checkpoint 관절 자동 산출, B. RTMW 키포인트 + 영상 → 한국어 코칭 멘트, C. 영상 → 그립/백벤드/occlusion/카메라 angle flag, D. RTMW 저신뢰 frame → keypoint 좌표 보강) 을 single-shot multimodal 호출로 처리한다. 사용자 = 폴스포츠 학원 수강생/강사/운영자. "Good" = 정은지 (세계챔피언) 영상이 고득점으로 평가되고, 코칭 멘트가 "고관절 외회전 부족 → 내전근 활성화" 처럼 강사 철학과 IPSF Code of Points 에 정합하며, 그립 종류·백벤드·측면 occlusion 같은 RTMW 가 놓치는 시각 단서를 Gemini 가 보강해서 채점이 의미있게 작동한다.

**Critical Failure Modes:**
<!-- The 3-5 behaviors that absolutely cannot go wrong in this system -->
1. **객관성 위반 — 좌표/점수/사람 판단 출력.** Gemini 가 "이 자세는 8.5점" / "정은지는 잘했다" 같은 주관 점수 라벨링을 출력하면 메모리 [[analysis-objectivity-no-human-scores]] 원칙 위반 + IPSF 객관 임계값 채점 체계 붕괴. 영역 A/B/C 모두 hard fail. 영역 D 만 좌표 출력 허용 (RTMW 보강 목적, 객관성 가드 OFF).
2. **고수 위양성 — 정은지 영상에서 채점/인식이 무너지는 케이스.** 영역 A 가 정은지 폭스탑/백벤드를 IPSF 등재 동작으로 매핑 못 하거나, 영역 C 가 정은지 영상에서 occlusion_severe=True 로 잘못 flag 해서 점수가 부풀려진 fallback 경로로 빠지면 학원 운영자/강사 신뢰 즉시 파괴. 박제: PROJECT.md "고수가 낮게 나오는 위양성 (정은지 영상 41점 같은) 없이 점수가 실제 자세 품질을 반영해야".
3. **강사 대체 톤 — "AI 가 강사 역할 대체" 인상.** 영역 B 코칭 멘트가 "이 동작은 잘못됐습니다" 처럼 단정/지시형으로 작성되면 강사/운영자 (도입 결정권자) 의 1순위 거부 우려 직격. 메모리 [[field-research-stakeholders]] + PROJECT.md Active "강사 보조 도구 포지셔닝". 멘트는 항상 "원인 → 해결 순서 + 강사와 영상 확인 권고" 마무리.
4. **IPSF Code of Points 명칭/Criteria 환각.** 영역 A 가 존재하지 않는 IPSF 코드 (예: "F999 Imaginary Move") 를 fabricate 하거나, checkpointJoints 의 EXTEND/BENT_OK 판정이 IPSF Compulsory Criteria 와 어긋나면 (a) Compulsory 트랙 채점이 전체 무너짐. 메모리 [[ipsf-5-track-scoring]] + [[judging-baseline-ipsf-code-of-points]].
5. **학원 용어 ↔ IPSF 명칭 매핑 실패.** 영역 A 가 "폭스탑" (IPSF 비등재 한국 학원 통용명) 같은 분기 2 entry 를 분기 1 IPSF 등재 동작으로 잘못 강제 매핑하거나, 반대로 분기 1 명백한 AKA 매핑 (나비/Butterfly, 큐피드/Cupid 등) 13개+ 를 분기 3 미등재로 떨어뜨리면 학원 사용자 1차 진입 UX 가 깨짐. 메모리 [[studio-term-3branch-system]].

## 1b. Domain Context

> Researched by `gsd-domain-researcher`. Grounds the evaluation strategy in domain expert knowledge.

**Industry Vertical:** Sports tech / 폴스포츠 (Pole Sports) — IPSF (International Pole Sports Federation) 공식 종목 + 한국 폴스포츠 학원 시장 (KPSA 도 IPSF 따름).

**User Population:**
- **수강생 (직접 사용자)** — 폴스포츠 학원 등록 학생. 비전문가, 본인 영상 업로드 후 분석 결과 + 코칭 멘트 소비. 일반 답변만 받으면 즉시 이탈.
- **강사/선수 (도입 결정권자 + 가장 큰 저항)** — 폴 동작 도메인 전문가. "각도가 중요한 게 아니라 힘·유연성 한계 인식이 핵심" 철학. AI 가 자기 자리를 대체한다고 느끼면 학원 도입 차단.
- **학원 운영자 (도입 결정권자)** — 학원 사업주. 신뢰 게이트 = "스피닝 폴에서도 인체 추적/분석 정확", 분석 자료 무분별 배포 방지, 부상 유발 우려.
- **belle (창업자, 폴스포츠 경력자 + 강사)** — 도메인 + 제품 의사결정.
- **정은지 선수 (세계챔피언, reference 인물)** — 영역 A 의 reference 영상 제공자. 본인 통용 호칭 (예: 폭스탑 → "버터플라이 콤보") 이 학원/IPSF 명칭과 다를 수 있어 분기 2 의 `championPersonalAlias` 박제.

**Stakes Level:** High
- **부상 리스크** = 직접 안전 (Critical 후보) 단 코칭 멘트 차원으로 영역 B 의 `injury_risk` 필드만 박제. 실제 운동 지시 X.
- **학원 도입 신뢰** = 사업적 Critical — 강사/운영자 1회 신뢰 깨지면 파일럿 자체 차단.
- **개인정보/신체 노출** = High — 영상은 신체 노출 콘텐츠. 영역 A/C/D 영상 입력은 Files API 48h 자동 만료 + 분석 자료 공유 제한이 v2 박제.

**Output Consequence:**
- **영역 A** 출력은 reference DB 에 영구 박제 → mode1 의 비교 baseline. 잘못된 IPSF 명칭/clipRange/checkpointJoints 가 들어가면 그 reference 로 비교되는 모든 수강생 분석이 오염.
- **영역 B** 출력은 결과 화면 카드 본문 + detail2 (causes/injuryRisk/coachNote). 수강생이 그대로 읽고 다음 연습에 반영 → 잘못된 코칭 = 잘못된 자세 학습 + 부상 가능.
- **영역 C** 출력은 후속 분석 path 게이팅 (occlusion_severe → D skip, camera_angle_problematic → 점수 신뢰도 표시, backbend_present → IPSF Backbend Criteria 활성). flag 오인식 → 채점 path 자체가 잘못 분기.
- **영역 D (v1, 2차 R-B2 정합)** 출력은 user-visible `KeypointReport.data` (2D normalized 좌표) + `KeypointReport.confidence` 보강 + 좌우 mirror hint audit 까지. **RTMW 3D pole-aligned scoring 행렬 (`coco_array`) 은 mutate 0** — DTW / 8 관절각 차원 점수 / KISMAM 은 RTMW 원본으로 계산. 좌표 환각 시 영향 = user 가 보는 KeypointOverlay 시각화만, 점수는 불변. **D-v2 deferred**: 좌표계 계약 (RTMW 3D ↔ Gemini normalized 2D) + 2D→3D lifter 박은 후 후속 plan 에서 scoring 행렬 주입 재진입.

### Known Failure Modes in This Domain

1. **Self-occlusion in inverted/folded poses.** 폴스포츠는 인버트 (거꾸로 매달리기), 스콜피오 (몸이 폴 주위로 둥글게), 백벤드 (등 뒤로 젖히기), 폭스탑 (다리/팔이 폴+몸을 교차) 자세가 핵심. 관절이 신체에 의해 가려지고 좌우 구분이 불가능해진다. POCO/PoseExaminer 연구가 명시: "yoga, gymnastics, acrobatic poses where limbs fold across the body" 가 단일 stage 추정기의 typical failure mode. 영역 C 의 occlusion_severe flag + 영역 D 의 keypoint 보강이 직격 대응.

2. **Spinning pole tracking degradation.** 학원 운영자 명시한 신뢰 게이트 = "스피닝 폴에서 인체 추적 정확". 폴이 회전하면 사용자 신체도 같이 돈다 → 카메라 angle 이 1초마다 바뀜 + motion blur. RTMW confidence 가 frame 단위로 진동 → 채점 jitter. 영역 C 의 camera_angle_problematic + 영역 D 의 보강이 대응 경로.

3. **좌우 좌표 swap (mirror error).** 측면/완전 뒤집힘 자세에서 RTMW 가 left/right 키포인트를 swap 함 — Phase 13 의 좌/우 mirror 별도 plan 으로 박제. 영역 D 의 보강이 Gemini Vision 으로 좌우 disambiguation 가능 (영상의 의상/머리 방향 단서 활용) 단 영역 D scope 박제 필요.

4. **IPSF 비등재 동작의 채점 공백.** 한국 학원 통용 "폭스탑" 같은 동작은 IPSF Code of Points 에 등재 안 됨. 대부분 AI 시스템은 "unknown move → 채점 불가" 로 빠지지만 IPSF Page 9 "all components" 절대 공통 트랙 (메모리 [[ipsf-5-track-scoring]]) 으로 자세 품질만 채점 가능. 영역 A 가 분기 3 라우팅을 잘못하면 이 path 가 막힘.

5. **코칭 멘트의 일반화 (generic answer) 이탈.** 폴 댄스 AI 코칭 앱 (Moveally / MotionMentor) 의 외부 리뷰: "AI as digital replacement for pole coaching was not impressive. Issues include uneven feedback quality, home learners receiving no real-time corrective feedback." → 일반 답변 = 즉시 이탈. 영역 B 가 "허리를 펴세요" 같은 generic 멘트로 빠지지 않고 부위별 (고관절/코어/내전근) 구체 언어 유지해야 함.

### Regulatory / Compliance Context

- **공식 표준화 baseline = IPSF Code of Points 2025-2027** (Pole Sports + Aerial Pole). KPSA 한국폴스포츠협회도 IPSF 따름 → 단일 baseline. 메모리 [[judging-baseline-ipsf-code-of-points]] 박제 — "미국/유럽/일본 등 다른 폴스포츠 단체의 채점 기준 참고 X. IPSF 단일."
- **개인정보** = 신체 노출 영상. Files API 48h 자동 만료 활용 + 분석 자료 무분별 배포 방지 (학원 운영자 명시 우려, v2 박제). GDPR/PIPA 등 일반 개인정보보호법 적용 가능하나 파일럿 (TestFlight 게스트 모드, 영상은 Firestore + S3 본인 격리 박제) scope 에서 추가 compliance 작업 미수반.
- **부상 책임** = 의료 advice 아님. 영역 B 의 `injury_risk` 필드는 "강사와 영상 확인 권고" 마무리 강제 + "AI = 강사 보조 도구" 포지셔닝 유지로 의료/물리치료 advice 영역 진입 회피.
- **공식 인증/regulation** = 없음. 스포츠 코칭 AI 는 의료기기/금융/법률 같은 regulated industry 아님.

## 2. Framework Decision

**Selected Framework:** `google-genai` (Python SDK, direct usage — no orchestration wrapper)

**Version:** `>=1.0,<2.0` (이미 `backend/runpod_inference/requirements.txt` 박혀있음. Phase 5 `gemini_moment_extractor.py` 패턴 재사용)

**Rationale:**
Phase 17 의 4 영역 (A reference 자동 등록 / B 코칭 멘트 / C finding 장면 인식 / D keypoint 보강) 은 전부 **영상 + prompt → 구조화 JSON** single-shot multimodal call 패턴. agent loop / tool use / multi-step planning 불필요. Pydantic `response_schema` 로 4 영역 출력 강제 가능. LangChain/CrewAI 같은 추상화는 abstraction overhead + 디버깅 비용만 추가 (ai-frameworks.md anti-pattern #1, #5 직격).

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| Google ADK (Agent Development Kit) | Multi-agent orchestration 용. 4 영역은 병렬 독립 호출, agent loop 아님. 4 영역이 서로 데이터 주고받는 workflow 로 진화 시 재평가. |
| LangChain | Abstraction overhead, p99 latency 저하. 단순 multimodal call 에 불필요. |
| LlamaIndex | RAG 우선. 영상 분석 영역 아님. |
| CrewAI | Multi-agent role-based 용. 4 영역 간 협업 아님. |
| Cerebras (현 LLM) | Vision 없음. 영역 B 의 Vision 보강은 가능 X. 단 B 의 텍스트-only path 는 그대로 유지 가능 (A/B test 후 결정). |

**Vendor Lock-In Accepted:** Partial — Gemini lock-in 박힘 박힘 (belle 2026-06-12 결정 + `GEMINI_API_KEY` Lambda env 이미 박혀있음). google-genai SDK 박혀있는 한 다른 Google AI 모델로 swap 가능. 단 영상 multimodal = Gemini 의 강점.

### Entry Point Pattern

**Hybrid (Structured Extraction 주 + Content Generation 부) 단일 영상 multimodal call.**
4 영역 모두 이 동일 패턴: 영상 업로드 → ACTIVE 대기 → Pydantic schema 강제 호출 → `response.parsed` 사용.

```python
# 4 영역 공통 베이스 (Pydantic schema 만 영역별로 교체).
# A=Reference 등록 / B=코칭 멘트 / C=Finding 인식 / D=관절 보강 — 모두 동일 호출 구조.

import logging
import time
from pathlib import Path

from google import genai
from google.genai import errors as genai_errors
from google.genai import types
from pydantic import BaseModel, Field

log = logging.getLogger(__name__)

# 영역 C 예시 (Finding 장면 인식) — 가장 단순한 flag 추출.
class FindingFlags(BaseModel):
    grip_visible: bool = Field(description="손이 폴 잡은 게 영상에 보이는지")
    backbend_present: bool = Field(description="등 뒤로 젖히기 자세가 포함되는지")
    occlusion_severe: bool = Field(description="신체 50% 이상 가림이 1초 이상 지속되는지")
    camera_angle_problematic: bool = Field(
        description="측면/뒤집힘 등 RTMW 가 키포인트 추정 어려운 각도인지"
    )
    notes_ko: str = Field(description="짧은 한국어 근거 1~2 문장. 좌표/점수 금지.")


def analyze_video_finding(video_path: str, api_key: str) -> FindingFlags:
    """단일 영상 → Pydantic 검증된 FindingFlags 반환.

    영역 A/B/D 도 동일 구조 — schema 클래스만 교체.
    """
    client = genai.Client(api_key=api_key)

    # 1. 영상 업로드 (Files API). 로컬 path 필수 — HTTP URL 직접 입력 불가.
    #    S3 presigned URL 은 boto3 로 먼저 /tmp 에 다운로드 후 path 전달.
    uploaded = client.files.upload(
        file=video_path,
        config=types.UploadFileConfig(mime_type="video/mp4"),
    )

    # 2. PROCESSING → ACTIVE 대기 (Files API 비동기). ACTIVE 안 되면 FAILED_PRECONDITION.
    #    5~60s 영상 = 통상 5~20초. timeout 120s 박제 (gemini_moment_extractor 패턴 정합).
    start = time.monotonic()
    while getattr(uploaded.state, "name", str(uploaded.state)) == "PROCESSING":
        if time.monotonic() - start > 120.0:
            raise RuntimeError(f"Gemini Files API timeout — {uploaded.name}")
        time.sleep(2.0)
        uploaded = client.files.get(name=uploaded.name)
    if getattr(uploaded.state, "name", str(uploaded.state)) == "FAILED":
        raise RuntimeError(f"Gemini Files API processing failed — {uploaded.name}")

    # 3. generate_content + response_schema=Pydantic → 자동 JSON 검증.
    try:
        response = client.models.generate_content(
            model="gemini-3.5-flash",  # 영역 C 는 Flash 충분. A/D 는 Pro 권장 (§4).
            contents=[
                uploaded,
                "이 영상의 4개 flag 를 추출해주세요. JSON 만 응답.",
            ],
            config=types.GenerateContentConfig(
                response_mime_type="application/json",
                response_schema=FindingFlags,
                temperature=0.0,           # 분류 = deterministic
                max_output_tokens=512,     # flag 4개 + notes — 항상 명시 (§4b.3)
                http_options=types.HttpOptions(timeout=60_000),  # ms 단위
            ),
        )
    except genai_errors.APIError as e:
        log.error("Gemini API error code=%s message=%s", e.code, e.message)
        raise

    # 4. response.parsed = Pydantic 인스턴스 (검증 통과 시). None 이면 raw text fallback.
    parsed = response.parsed
    if parsed is None:
        # SDK 버전/모델 조합으로 parsed 가 None 인 케이스 (Plan 5 spike 박제).
        import json
        return FindingFlags.model_validate(json.loads(response.text))
    return parsed
```

### Key Abstractions

| Concept | What It Is | When You Use It |
|---------|-----------|-----------------|
| `genai.Client(api_key=...)` | 신 SDK 진입점. Vertex AI / AI Studio 양쪽 지원. `aio` attribute = async client. | 모든 호출의 시작. 호출당 1회 init (Pod = 모듈 캐시). |
| `client.files.upload(file=path)` | 영상/오디오/PDF 등 멀티모달 자산 업로드. `mime_type` 명시 권장. PROCESSING→ACTIVE 상태 머신. | 영상 입력 — 4 영역 모두 필수. HTTP URL 직접 입력 불가 (로컬 path 만). |
| `types.GenerateContentConfig` | `response_mime_type`, `response_schema`, `temperature`, `max_output_tokens`, `thinking_config`, `http_options` 등 호출 옵션 컨테이너. | 구조화 출력 + 토큰 제한 + 타임아웃. 4 영역 모두 사용. |
| `response_schema=PydanticModel` | Pydantic `BaseModel` 클래스를 직접 schema 로 전달. SDK 가 model_json_schema 변환 + propertyOrdering 보존. `response.parsed` 로 검증된 인스턴스 추출. | 4 영역 출력 강제의 핵심. dict-schema 보다 항상 Pydantic 우선. |
| `client.aio.models.generate_content` | async 버전. `await` 로 호출, 4 영역 병렬 실행 시 `asyncio.gather` 로 묶기. | 영역 A+C, B+D 같은 독립 영역 병렬 호출 시 latency 절감. |
| `types.ThinkingConfig(thinking_budget=0)` | Gemini 2.5 의 thinking 비활성. 0 = OFF (latency 절감), -1 = AUTO, 양수 = 명시 budget. | 영역 C (flag 추출) = 0. 영역 A/B (motion 추론 + 코칭) = AUTO 또는 4k~10k. |

### Common Pitfalls

1. **`uploaded.state` 가 PROCESSING 인데 즉시 `generate_content` 호출** — Gemini 가 `FAILED_PRECONDITION` 반환. 영상 입력 시 반드시 `client.files.get(name=...)` 폴링 → `ACTIVE` 확인. 5~60s 영상 = 통상 5~20초. timeout 120s 박제 (gemini_moment_extractor.py L353~363 검증된 패턴).

2. **S3 presigned URL 을 `client.files.upload(file=url)` 에 직접 넘김** — Files API 는 **로컬 path 또는 IOBase 만** 지원. presigned URL 은 boto3 로 먼저 `/tmp/{analysis_id}.mp4` 다운로드 후 path 전달. gemini_moment_extractor.py L341~347 의 `RuntimeError` 가드 그대로 재사용.

3. **`response.parsed` 가 None 인데 무조건 사용** — SDK 1.x 에서 model/schema 조합에 따라 `parsed` 가 None 이고 `text` (JSON string) 만 채워지는 케이스 있음 (spike_gemini_motion_classify.py L257~265 박제). `parsed is None` 분기 + `PydanticModel.model_validate(json.loads(response.text))` 폴백 필수.

4. **`response_schema` 에 dict 넘기면서 `type` 을 lowercase 로 작성** — Gemini schema 는 `'STRING' / 'INTEGER' / 'OBJECT' / 'ARRAY' / 'BOOLEAN'` (대문자) 사용. JSON Schema 의 `'string'` 과 다름. **Pydantic 모델 직접 전달이 가장 안전** — SDK 가 자동 변환 + propertyOrdering 보존.

5. **legacy `google-generativeai` (0.8.x) 와 `google-genai` (>=1.0) 혼재 import** — 두 패키지가 같은 `google.*` 네임스페이스를 점유. 한 venv 에 둘 다 깔리면 import 우선순위 충돌. `pip uninstall google-generativeai` 박제 + 신 SDK 만. 새 AI Studio `AQ.` 키 (2025-말 갱신) 는 legacy 가 인식 못 함 (gemini_moment_extractor.py L321~324 박제).

6. **`max_output_tokens` 미지정** — Gemini 2.5 thinking 모델은 unbounded 시 thinking budget 까지 다 소모하고 빈 응답 반환 가능. 4 영역 모두 명시 (§4 모델 설정 표 참조). 영역 C = 512, 영역 A/D = 2048, 영역 B = 2500 (coach_writer.py 정합).

7. **동기 client 를 async event loop 안에서 호출** — Lambda async handler 또는 FastAPI route 에서 `client.models.generate_content()` 를 `await` 없이 직접 호출하면 event loop 블로킹. **반드시 `client.aio.models.generate_content(...)` + `await`** 사용 (§4b.2).

### Core Pattern

```python
# 4 영역 공통 베이스 클래스 — schema + model + 영역별 prompt 만 교체.
# gemini_common.py 신설 박제. coach_writer.CerebrasCoachWriter 인터페이스 정합 (graceful no-op).

from __future__ import annotations

import json
import logging
import time
from dataclasses import dataclass
from pathlib import Path
from typing import Any, Generic, TypeVar

from google import genai
from google.genai import errors as genai_errors
from google.genai import types
from pydantic import BaseModel, ValidationError

log = logging.getLogger(__name__)

T = TypeVar("T", bound=BaseModel)


@dataclass
class GeminiVisionCall(Generic[T]):
    """4 영역 공통 호출 베이스.

    설계 원칙:
      · graceful — API 키 없거나 호출 실패 시 None 반환 (예외 X, 분석 흐름 차단 X).
        coach_writer.CerebrasCoachWriter (L107~143) 의 graceful 정신 그대로.
      · response_schema=Pydantic 강제 → 검증 통과만 반환. ValidationError = retry 1회.
      · _enforce_no_reject_patterns 2차 가드 (좌표/점수/판단 reject). 영역 D 만 좌표 허용.
    """

    schema: type[T]
    model: str
    prompt: str
    temperature: float = 0.1
    max_output_tokens: int = 2048
    thinking_budget: int | None = None
    enforce_object_guard: bool = True   # 영역 D = False (좌표 출력 허용)
    api_key_loader: Any = None          # _load_api_key 주입 (gemini_moment_extractor 정합)

    def call(self, video_path: str | Path) -> T | None:
        # graceful — 키 없으면 None (caller 가 fallback path 사용).
        try:
            api_key = (self.api_key_loader or _load_api_key)()
        except RuntimeError as exc:
            log.warning("Gemini API key 미설정 — graceful skip: %s", exc)
            return None

        client = genai.Client(api_key=api_key)

        # 1. Files API upload + ACTIVE 대기.
        uploaded = client.files.upload(
            file=str(video_path),
            config=types.UploadFileConfig(mime_type="video/mp4"),
        )
        start = time.monotonic()
        while getattr(uploaded.state, "name", str(uploaded.state)) == "PROCESSING":
            if time.monotonic() - start > 120.0:
                log.warning("Files API timeout — graceful skip")
                return None
            time.sleep(2.0)
            uploaded = client.files.get(name=uploaded.name)
        if getattr(uploaded.state, "name", str(uploaded.state)) == "FAILED":
            log.warning("Files API state=FAILED — graceful skip")
            return None

        # 2. response_schema=Pydantic + max_output_tokens 명시 + thinking config.
        cfg_kwargs: dict[str, Any] = dict(
            response_mime_type="application/json",
            response_schema=self.schema,
            temperature=self.temperature,
            max_output_tokens=self.max_output_tokens,
            http_options=types.HttpOptions(timeout=60_000),  # ms
        )
        if self.thinking_budget is not None:
            cfg_kwargs["thinking_config"] = types.ThinkingConfig(
                thinking_budget=self.thinking_budget
            )

        # 3. 호출 + 1회 retry (ValidationError 또는 5xx 만).
        for attempt in (1, 2):
            try:
                response = client.models.generate_content(
                    model=self.model,
                    contents=[uploaded, self.prompt],
                    config=types.GenerateContentConfig(**cfg_kwargs),
                )
                raw_text = getattr(response, "text", "") or ""

                # 좌표/점수/판단 2차 가드 ([[analysis-objectivity-no-human-scores]]).
                if self.enforce_object_guard:
                    _enforce_no_reject_patterns(raw_text, context=self.model)

                # response.parsed = 검증 통과 인스턴스, None 이면 raw text 폴백.
                parsed = getattr(response, "parsed", None)
                if parsed is not None:
                    return parsed  # type: ignore[return-value]
                return self.schema.model_validate(json.loads(raw_text))

            except (ValidationError, json.JSONDecodeError) as exc:
                log.warning("Schema 검증 실패 attempt=%d: %s", attempt, exc)
                if attempt == 2:
                    return None  # graceful — caller 가 fallback path 사용
            except genai_errors.APIError as exc:
                # 4xx (auth/quota) = 즉시 graceful skip. 5xx = retry 1회.
                if exc.code and 500 <= exc.code < 600 and attempt == 1:
                    log.warning("Gemini 5xx — retry: code=%s", exc.code)
                    time.sleep(1.0)
                    continue
                log.warning("Gemini API error code=%s msg=%s", exc.code, exc.message)
                return None
        return None
```

### Tool Use

Gemini 의 native tool/function calling 은 **사용하지 않음**. 4 영역 모두 single-shot generate_content. 이유:
- 영역 A/C/D = 단일 영상 입력 → 단일 JSON 출력. tool loop 불필요.
- 영역 B = 코칭 텍스트 생성. 외부 데이터 조회 없음 (RTMW 수치는 prompt 에 직접 포함).
- agent loop 도입 시 LangChain/Google ADK 가 더 적합 — Phase 17 scope 외 (§2 Alternatives 박제).

**대신 사용:** Pydantic `response_schema` (출력 강제) + Files API (영상 입력) + 좌표/점수/판단 reject regex (객관성 가드, gemini_moment_extractor.py L61~87 재사용).

### State Management

- **호출 단위 stateless** — 4 영역 모두 single-shot. 대화 히스토리/multi-turn 없음.
- **캐시 경계 1: in-memory** — `(video_uri, region, model)` 키로 dict 캐시 (gemini_moment_extractor.py L274~276 패턴). Pod/Lambda 모듈 캐시 = 호출당 1회 init.
- **캐시 경계 2: Firestore TechniqueCache** — Phase 5 의 `technique_cache.compute_video_hash` 재사용. 영역 A 결과 (reference 등록) 와 영역 C 결과 (finding flag) 는 cross-analysis 재사용 가능 → Firestore `analyses/{id}/gemini/{region}` subcollection 박제. 영역 B/D 는 분석별 1회성 → 캐시 X.
- **Files API auto-expire 48h** — Google 측 영상 보존 48시간. 그 이후 재호출 시 자동 재업로드. 우리 코드는 매 호출 업로드 (멱등성 + 단순성 우선).

### Context Window Strategy

- **Gemini 2.5 Pro context = 2M tokens / Flash = 1M tokens** — 5~60s 영상 = ~258 tokens/sec × 60 = 최대 ~15.5k tokens. 한참 여유.
- **`thinking_budget` 가 실질 cap** — Pro 의 default thinking 이 prompt 길이 × 5~10배 까지 확장 가능. 영역 A/B 만 thinking ON (-1 / 4k), 영역 C/D 는 OFF (0).
- **영상 길이 60s 초과 시** — `clipRange` 사전 분할 (영역 A 의 핵심 출력) 후 30s 단위 호출. 단 파일럿 (정은지 영상 5~30s) scope 에서는 미발생.
- **Lambda 256MB / 15s default timeout** — pipeline Lambda 는 900s/1024MB 박제 정합. 영역 A/B/C 는 Lambda OK. 영역 D = Pod (RTMW 와 동거).

### Structured Outputs with Pydantic

**핵심:** 4 영역 모두 Pydantic `BaseModel` 을 `response_schema` 로 직접 전달 → SDK 가 model_json_schema 자동 변환 + propertyOrdering 보존 + Gemini schema 형식 (대문자 `STRING`/`INTEGER`) 변환. `response.parsed` 로 검증 통과 인스턴스 추출. dict-schema 보다 항상 Pydantic 우선 (§3 Pitfall #4).

```python
# 4 영역 Pydantic schema 박제 박제.

from pydantic import BaseModel, Field
from typing import Literal


# ── 영역 A: Reference 자동 등록 ──────────────────────────────────
class CheckpointJoint(BaseModel):
    joint_key: Literal[
        "leftElbow", "rightElbow", "leftShoulder", "rightShoulder",
        "leftHip", "rightHip", "leftKnee", "rightKnee",
    ]
    expectation: Literal["EXTEND", "BENT_OK", "CONTACT"] = Field(
        description="EXTEND=180도 신전 필수, BENT_OK=부분 굽힘 의도, CONTACT=폴 접촉"
    )


class ReferenceRegistration(BaseModel):
    """영역 A 출력 — IPSF 명칭 + clipRange + checkpointJoints."""
    motion_name_ipsf: str = Field(description="IPSF Code of Points 공식 영문 명칭")
    motion_name_ko: str = Field(description="학원 한국어 통용명")
    clip_start_seconds: float = Field(ge=0, description="동작 진입 시점")
    clip_end_seconds: float = Field(ge=0, description="동작 종료 시점")
    checkpoint_joints: list[CheckpointJoint] = Field(
        min_length=1, max_length=8, description="채점 대상 관절 + 기대 자세"
    )
    confidence: float = Field(ge=0.0, le=1.0)


# ── 영역 B: 코칭 멘트 (coach_writer.py detail/detail2 정합) ─────
class CoachCause(BaseModel):
    title: str
    explanation: str
    fix: str


class CoachDetail2(BaseModel):
    causes: list[CoachCause] = Field(min_length=3, max_length=5)
    injury_risk: str | None = None
    coach_note: str = Field(description="강사와 함께 영상 확인 권고 마무리")


class JointCoaching(BaseModel):
    joint_key: str
    detail: str = Field(description="카드 본문 한 줄 (실행 지시)")
    detail2: CoachDetail2


class CoachPayload(BaseModel):
    """영역 B 출력 — coach_writer.write() 반환 형식 정합."""
    joints: list[JointCoaching] = Field(min_length=1, max_length=8)


# ── 영역 C: Finding 장면 인식 ──────────────────────────────────
class FindingFlags(BaseModel):
    """영역 C 출력 — boolean flag 4종 + 짧은 근거."""
    grip_visible: bool
    backbend_present: bool
    occlusion_severe: bool
    camera_angle_problematic: bool
    notes_ko: str = Field(max_length=200, description="짧은 한국어 근거. 좌표/점수 금지.")


# ── 영역 D: 관절 보강 (Pod-only) ───────────────────────────────
class RefinedKeypoint(BaseModel):
    frame_index: int = Field(ge=0)
    joint_key: str
    x_normalized: float = Field(ge=0.0, le=1.0, description="frame width 정규화")
    y_normalized: float = Field(ge=0.0, le=1.0, description="frame height 정규화")
    confidence: float = Field(ge=0.0, le=1.0)


class KeypointRefinement(BaseModel):
    """영역 D 출력 — RTMW 저신뢰 frame 만 보강."""
    refined: list[RefinedKeypoint] = Field(max_length=200)
```

**Framework 통합:**
- 4 영역 모두 `client.models.generate_content(config=types.GenerateContentConfig(response_mime_type='application/json', response_schema=ReferenceRegistration))` 패턴.
- SDK 가 Pydantic v2 `model_json_schema()` 자동 호출 → Gemini schema 변환 → `response.parsed` 가 검증된 인스턴스. `response.text` 는 raw JSON 보존 (감사용).

**Retry 정책 (1회 retry 박제):**
1. `pydantic.ValidationError` 또는 `json.JSONDecodeError` → 1회 retry, 같은 prompt 재호출 (temperature=0 영역은 deterministic 이지만 thinking variance 존재). 박제 attempt 카운터 로그.
2. `genai_errors.APIError` 5xx → 1회 retry + 1초 backoff. 4xx (quota/auth) = 즉시 graceful return None.
3. 2회 모두 실패 → `return None` (graceful). caller (영역 A=등록 큐, B=Cerebras 폴백, C=빈 flag, D=RTMW 원본 keypoint 유지) 가 fallback path 박제.
4. 좌표/점수/판단 reject regex (영역 A/B/C, gemini_moment_extractor.py L143~177 재사용) 매치 → `ValueError` raise (graceful X — 객관성 가드는 hard fail. memory [[analysis-objectivity-no-human-scores]]).

### Async-First Design

**Gemini SDK 의 async 패턴:**
- 동기: `client.models.generate_content(...)` — Lambda sync handler / CLI / 단위 테스트.
- 비동기: `await client.aio.models.generate_content(...)` — FastAPI route / Lambda async handler / 영역 병렬 호출.
- 비동기 client 는 `async with Client().aio as aclient:` 또는 `await aclient.aclose()` 로 명시 해제 (리소스 누수 방지).

**4 영역 병렬 패턴 (단일 분석에서 A+C 동시 + B+D 후속):**

```python
import asyncio
from google import genai

async def analyze_all_regions(video_path: str, api_key: str) -> dict:
    """A+C 병렬 → 결과로 B+D prompt 박제 → B+D 병렬."""
    async with genai.Client(api_key=api_key).aio as aclient:
        # Wave 1: A (Reference 후보) + C (Finding flag) — 서로 독립.
        a_task = call_region_a(aclient, video_path)
        c_task = call_region_c(aclient, video_path)
        a_result, c_result = await asyncio.gather(a_task, c_task, return_exceptions=True)

        # Wave 2: B (코칭) + D (keypoint 보강) — A/C 결과 prompt 박제.
        # 단 occlusion_severe=True 이면 D skip (의미 없음).
        b_task = call_region_b(aclient, video_path, rtmw_metrics=...)
        if isinstance(c_result, FindingFlags) and not c_result.occlusion_severe:
            d_task = call_region_d(aclient, video_path)
            b_result, d_result = await asyncio.gather(b_task, d_task)
        else:
            b_result = await b_task
            d_result = None
    return {"a": a_result, "b": b_result, "c": c_result, "d": d_result}
```

**The one common mistake (박제):** Lambda async handler 또는 RunPod FastAPI route (`backend/runpod_inference/server.py`) 안에서 **동기** `client.models.generate_content(...)` 을 그대로 호출 → event loop 블로킹 (다른 요청 전체 정지). **반드시 `client.aio.models.generate_content(...)` + `await`** 사용. server.py L59 의 module-load lock 패턴과 동거 박제.

**Stream vs. await:**
- **`await` (non-stream)** — 4 영역 모두 기본. Pydantic schema 검증 = 전체 응답 필요. streaming 으로 받으면 schema 검증 불가.
- **stream (`generate_content_stream`)** — 영역 B 의 코칭 멘트만 향후 검토. UX 상 "코칭이 한 글자씩 나타나는" 효과가 분석 정확도와 무관하므로 우선순위 낮음. 영역 A/C/D 는 streaming 적합 X (구조화 검증 필수).

### Prompt Engineering Discipline

**System vs. user prompt 분리:**
- google-genai 는 `types.GenerateContentConfig(system_instruction=...)` 로 system prompt 명시. user content 는 `contents=[uploaded_file, "<user prompt>"]`. coach_writer.py L18~30 의 `_SYSTEM` 텍스트 박제 패턴 그대로 영역 B 에 재사용.
- 4 영역 모두 system 에 **객관성 헌장** (좌표/점수/판단 금지, gemini_moment_extractor.py L227~255 정신) + 영역별 역할 정의. user 는 영상 + "이 영상의 X 를 JSON 으로 추출하세요" 한 줄.

**Few-shot:**
- **인라인 우선** — 영역 A/C 의 schema 자체가 Pydantic Field description 으로 표현되어 별도 few-shot 불필요.
- **동적 retrieval 불필요** — RAG 영역 아님 (§2 LlamaIndex ruled out).
- 영역 B 만 향후 검토 — coach_writer.py 의 detail2 causes 패턴이 정착되면 정은지 영상 3건 reference 코칭 사례를 system instruction 에 inline 박제.

**Token budget:**
- `max_output_tokens` **반드시 명시** (§3 Pitfall #6). 4 영역 박제값: C=512, A/D=2048, B=2500.
- `thinking_config.thinking_budget` 명시: C/D=0 (OFF), B=4096, A=-1 (AUTO).
- prompt 길이는 영상 token (~15.5k for 60s) 이 지배적 — system+user 텍스트는 < 500 tokens 박제.

### Context Window Management

**Hybrid (Extraction + Generation) 특화 전략:**

- **단일 영상 < 60s = no 압축 필요** — Pro 2M / Flash 1M context window. 영상 ~15.5k tokens + prompt ~500 tokens = 충분.
- **영상 > 60s = sub-clip 분할 (영역 A 책임)** — 영역 A 의 `clipRange` 출력이 후속 영역 (B/C/D) 의 입력 영상을 30s 단위로 분할. Phase 17 파일럿 scope (정은지 영상 5~30s) 에서는 미발생, 향후 학원 수강생 영상 (최대 60s 제한) 박제.
- **영역 B 의 RTMW 수치 prompt 포함** — 8 관절 × deviation_deg = ~30 tokens. coach_writer.py L69~74 와 동일 포맷. 영상 tokens 대비 무시 가능.
- **agent compaction 비대상** — single-shot, multi-turn 없음, autonomous loop 없음. context 폭발 위험 0.
- **Files API 48h 자동 만료** — 명시적 정리 불필요. 같은 영상 재분석 = 자동 재업로드 (멱등).

- **영역 A/D** — Pro 고정. A=IPSF 명칭 정확도 우선, D=좌표 deterministic 보강 정확도 우선. Flash 전환 금지 (정확도 critical).

**Latency 예산:**
- Files API upload + ACTIVE 대기 = **5~20초** (10초 영상). 4 영역 호출당 1회씩 = 병렬 X 시 누적 80초.
- `client.aio` + `asyncio.gather` 로 A+C 병렬 / B+D 병렬 = **30~40초** 박제. Lambda pipeline 900s timeout 정합.
- 영역 C (Flash, thinking OFF) = **2~5초** 응답. 영역 A/D (Pro, AUTO/OFF) = **5~15초**. 영역 B (Pro, thinking 4k) = **10~25초**.

## 5. Evaluation Strategy

> 도메인 rubric ingredients (§1b "What Domain Experts Evaluate Against" 5개) 를 측정 가능 차원으로 변환. 메모리 [[analysis-objectivity-no-human-scores]] = 사람 점수 라벨링 영구 금지. **임계값 수치 라벨링과 binary pass/fail 라벨링만 허용.**

### Eval Tooling

**Primary Tool:** **Arize Phoenix** (self-hosted, open-source) — 기존 tracing 도구 detection 결과 = 없음 (`.codex/agents/*.toml` 만 매치, 이건 agent 설정 파일). Phoenix 가 default 적용 근거:
- belle 메모리 [[runpod-gpu-env]] + Lambda 박제 환경 = self-host path 적합 (Pod 또는 별도 EC2 micro-instance 에 docker 1줄 띄움).
- OpenTelemetry 표준 → `google-genai` SDK + Pydantic 코드 변경 0 (auto-instrument).
- belle "비용 신경 X but 효율 잡기" 박제 + 분석 정확도 우선 → eval signal 가시화가 가치 핵심.
- LangChain/LangGraph 미사용 → LangSmith 비대상.

**보조 도구:**
- **Promptfoo** — **local prompt regression eval** (2차 R-W1 정합). 4 영역 reference dataset 을 Promptfoo YAML 로 박제 → belle/Claude 가 PR 작성 전 수동 로컬 실행. **자동 CI/CD 게이트 (.github/workflows 또는 merge block) 는 Phase 17 scope 밖** — 별도 후속 plan 으로 분리.

## 6. Guardrails

**박제 — G1 = hard fail, G2/G6 = graceful:** [[analysis-objectivity-no-human-scores]] 헌장 위반은 fallback 으로 우회하면 안 된다 (객관성 가드 실패 = 시스템 의미 자체 붕괴). 반대로 schema 검증 / API quota 는 graceful skip 박제 — 분석 흐름 끊기지 않음.

## 7. Production Monitoring

**Tracing Tool:** **Arize Phoenix (self-hosted on RunPod Pod + EC2 micro fallback)**.

- **Phoenix collector** = RunPod Pod 별도 컨테이너 (port 6006, 영구 volume) 또는 EC2 micro (t4g.small). belle 메모리 [[next-pod-use-network-storage]] = 영구 volume 박제 정합.

- **RunPod Pod** (영역 D) → in-process collector 또는 동일 Phoenix endpoint 로 export.

| **M5** | LLM judge calibration drift (E4 영역 B 톤) | F1 flywheel 산출 | belle binary 라벨 vs judge score correlation ≥ 0.7 / week |

**Smart Sampling Strategy (사람 검수 박제):**

ai-evals.md "smart sampling — weight toward interactions with concerning signals" 정합. 100% 검수 불가 → 신호 기반 가중치 박제:

| Signal | Sampling Weight | 검수자 |
|--------|----------------|--------|
| `isReference=True` 인 정은지/강사 영상 분석 | **100%** — 자동 belle 알림 + 익일 검수 | belle |
| Online guardrail (G1~G6) trigger 발생 | **100%** — Phoenix trace + Firestore 자동 archive | Claude/엔지니어 |
| `analysis.score.overall < 30` 또는 `> 95` (양극단) | **20%** sampling | belle |
| 영역 B `causes` 가 정확히 3개 (Pydantic 최소값) — generic 의심 | **30%** sampling | belle (월 1회 묶음) |
| 영역 C `occlusion_severe=True` 또는 `camera_angle_problematic=True` | **15%** sampling | 운영자 + belle (학원 파일럿 진입 후) |
| 영역 A 분기 3 라우팅 (미등재 자동 수집) | **100%** — F7 누적 검토 | belle (월 1회 분기 2 승격 검토) |
| 그 외 일반 분석 | **2% baseline** sampling — quality 기준선 유지 | Claude/엔지니어 자동 보고 |

**박제 — Signal-Metric Divergence:**
- M1~M5 가 정상인데 belle/강사가 "결과가 이상하다" 신호를 보내면 → ai-evals.md "signal-metric divergence" = early warning. 정량 통과/정성 불통 케이스 = eval gap → reference dataset 보강 (해당 영상 sample 을 60건 production dataset 에 추가).
