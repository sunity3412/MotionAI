<objective>
Build the pure, numpy-only transparent deduction-tally engine that REPLACES the severity→fixed-ceiling band. The engine consumes the MEASURED GEOMETRY LAYER (the dimension/kismam deviations that today produce `score_result["overallScore"]` via `assemble.py:736` / `kismam.overall_score`) PLUS the Phase 23 quantification substrate (angle deltas + body-relative notches) and an IPSF criterion-grouping table. It emits a `DeductionBreakdown` OBJECT (`{baseline, records, final, coverageGaps, fallback}`): `final = max(0, round(100 + Σ(record.points)))` where each `record.points` is SIGNED NEGATIVE, with a full per-criterion record list (measured value, numeric baselineValue, deviation, applied rule id, signed-negative points, IPSF anchor citation). The Gemini supported_difference / fault label (body_part/fault_state) is used ONLY to LOCATE which criterion is implicated and to ADD vision-only faults — it never gates whether a measured deviation deducts. severity is NOT a scoring/selection input (criteria_for_fault never reads it); it is ONLY the coachRootCauseEligible aux signal (MEDIUM-1). This plan delivers the engine, its grouping/weight table + the `criteria_for_fault` fault-context router (scoped to what the substrate can actually measure, with deferred gaps TRACKED not hidden), the 3-way contract for persistence, and the unit gates — all pure (no Pod, no Gemini, no AWS). The pipeline seam wiring (Plan 02) and eval gates (Plan 03) build on this.

Purpose: belle rejected severity→fixed band as human judgment injected per-video (ND-01, [[scoring-must-be-transparent-deduction-tally]]). The point is a tally whose every −point is traceable to a named measured deviation + a named rule, identical rule across all videos (no curve-fit). Per ND-03 the tolerance/penalty must expand to ALL dimensions feeding the tally — so the measured geometry layer (not a 100-minus-Gemini-only recompute) is the substrate, preserving Phase 20's false-positive purpose: a fault video must NOT score 100 just because Gemini stayed silent or the reference pair was missing.

Criterion-activation has TWO unioned sources (HIGH-1): a MEASURED-DEVIATION SEED (`criteria_from_measured_deviations`) that activates the measurable criteria whenever their measured substrate is finite AND beyond tolerance (the Gemini-silent defense — measured geometry deducts on its own, so `supported_differences=[]` never yields `records=()`/`final=100` when geometry deviates), UNIONed with the Gemini fault-context router. The line/leg no-double-count exclusion is applied AFTER the union. A single `keypoint_set`→criterion map cannot express the leg sub-faults — `split`/`straddle` normalize to `keypoint_set="leg"` (vision_veto.py:238-239), as do a bent-knee leg_extension fault and a knee-reach shortfall. So the PUBLIC router is `criteria_for_fault(fault_key, supported_difference, measured_deviations)`, which routes on the fault's `body_part`/`fault_state` (read off the supported_difference dict) + the available measured substrate. The old `criterion_for_fault_key(keypoint_set)` is demoted to an internal total-coverage helper, not the selection API. NOTE (live-source trap): `_keypoint_set_for` (vision_veto.py:241) normalizes BOTH "torso/몸통" AND "line/라인/정렬" to `keypoint_set="line"`, so the gap/route decision MUST read raw `body_part`/`fault_state` from the supported_difference — never the normalized `keypoint_set` — or a torso fault mis-routes into the `line` criterion instead of its coverage gap.

Substrate-honesty scope (ND-06): the `line`/extension criteria (`line`, `leg_extension`) derive their deviation from `dimensions.line_score` / `extension_deviation`, which gate on `profile.expects_extension(joint)`. For a move whose technique profile has an EMPTY `joint_expectations` ({} — unregistered/미상/low-confidence moves), `expects_extension` returns False for every joint, so `line_score` returns None and that criterion contributes 0 deviation (and 0 deduction). This is CORRECT and HONEST — a true 0, NOT a silent band and NOT a false penalty. The unregistered/unknown-fault case is defended by the measured `dimension_overall` fallback + the Gemini-located criteria, NOT by a `line` deduction the substrate cannot produce. The plan does not over-claim `line` coverage for unregistered moves; it claims the 0-contribution is honest.

Cross-criterion non-double-count (HIGH-5): `line` is a COLLECTIVE 180°-extension-deficit over ALL EXTEND joints; `leg_extension`/`arm_extension` are per-limb extension criteria over the SAME joints. To avoid deducting a single bent knee twice (once in leg_extension, once in line's collective deficit), `line` activates ONLY for `keypoint_set=="line"` or a line-dominant fault, and EXCLUDES the joint substrate already claimed by an activated explicit leg/arm extension criterion. This aligns with pairs.yaml `dominant_dimension: line` (line-dominant) vs `dominant_dimension: angle` (per-limb) labels.

Baseline-as-scoring-substrate (ND-05, HIGH-4): the per-move `baseline_kind` (floor/pole_vertical/hip_line) is a GENUINE scoring substrate, not an audit label — the `body_relative_reach` criterion (the one `reference_relative` criterion) consumes `bodyRelativeNotches.delta_notches`, which `vision_veto.body_relative_notches` computes baseline-relative (`delta_notches = student_notches − reference_notches`). INSUFFICIENT-reach (the fault) is `delta_notches < 0`, so reach is scored as `shortfall = max(0, reference_notches − student_notches − tolerance)` (HIGH-2 — NOT `max(0, delta_notches − tol)` which misses it, NOT `abs()` which wrongly punishes over-reach). Different baseline_kind → different notch reach → different measured deviation → different score. This criterion activates ONLY for hand/knee reach faults (the measurable `_NOTCH_REACH_KEYPOINTS`); grip/head/torso stay coverage gaps (not force-mapped).

Output: `deduction_engine.py` + `ipsf_criteria.py` (pure core), `DEDUCTION_*_KEYS` in `models.py` + `DeductionBreakdown` in `analysis.ts` + `docs/contract.md §10` (3-way lockstep, with `baselineValue`/`baselineKind` per HIGH-3), and `test_deduction_engine.py` (Wave 0 unit gates SCORE-10..16 partial).
