## Spacing Scale

계약 단위는 **토큰명 우선**, 토큰이 없는 화면-로컬 간격은 4의 배수만 허용 (기존 화면 실측 패턴 준거). **Figma 프레임이 있는 요소는 Figma 추출 간격이 우선한다.**

| Token / 값 | 값(참고) | Usage |
|-------|-------|-------|
| `spacing.screenX` | 20 | 화면 좌우 패딩 (전 화면 공통) |
| `spacing.cardPadding` | 16 | 카드 내부 패딩 |
| 4 | 4 | 카드 타이틀-부제 간격 (`analyze.tsx` cardSub marginTop 준거) |
| 8 | 8 | heading-sub 간격, 체크박스-라벨 간격, 다이얼로그 버튼 2개 가로 gap |
| 12 | 12 | 카드 리스트 gap, 링크 marginTop, **F4 공지 배너와 인접 요소 최소 간격** |
| 16 | 16 | 안내 캡션 marginTop (`analyze.tsx` guidance 준거) |
| 20 | 20 | 오류 텍스트 marginTop, 리스트 상단 |
| 24 | 24 | 모달 내부 패딩, 하단 여백 |
| 28 | 28 | 헤딩 아래 첫 카드 그룹 marginTop |

**Exceptions (스펙 고정값 — 4의 배수 아님, 신규 도입 금지·기존 토큰만):**
- `layout.ctaHeight` 54 / `layout.inputHeight` 54 (design.md §5-3)
- `radius.button` 13 / `radius.card` 15 / `radius.listItem` 8.58 / `radius.modal` 20
- `layout.cardBorderWidth` 0.858 (§5-4)
- Figma 다이얼로그의 큰 radius — Figma 추출값 우선 (`radius.modal` 초과 값이면 토큰 신설 검토)
- 아이콘 전용 터치 타깃 최소 40×40 + `hitSlop` (기존 backBtn 패턴). 체크박스 터치 영역은 행 전체(라벨 포함)로 44pt 이상 확보.

## Typography

이 phase 가 사용하는 역할 4종 / 굵기 2종. 반드시 `typography` 토큰 spread (`...typography.x`) 로 적용. **Figma 프레임이 있는 요소는 Figma 추출 타이포가 우선한다** (추출 후 가장 가까운 토큰에 매핑).

| Role | Token | Size(참고) | Weight | Line Height |
|------|-------|-----------|--------|-------------|
| Display (화면 헤딩) | `typography.heading` | 30 | 700 | 기본 (RN auto) |
| Heading (섹션/다이얼로그 타이틀, CTA) | `typography.sectionTitle` / `typography.button` | 20 | 700 | 기본 |
| Label (카드·FAQ 항목 타이틀) | `typography.listTitle` | 18 | 700 | 기본 |
| Body (본문·안내·경고 본문) | `typography.caption` | 12 | 400 | **lineHeight 18~19 명시** (기존 guidance 패턴 — caption 다줄 본문은 반드시 lineHeight 지정) |

- 굵기는 400(Regular)/700(Bold) 2종만. 예외: 기존 `badgeText` 의 fontWeight '600' 패턴(samples.tsx) 재사용 시 1곳 허용 — 신규 600 도입 금지.
- `typography.buttonSecondary`(17/400)는 보조 버튼 라벨에만.

## Color

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `colors.bg` (흰색) | 전 신규 화면 배경. 서브 화면 = 흰 배경 (design.md §5-1) |
| Secondary (30%) | `colors.cardBg` + `colors.divider` 테두리, 텍스트 `colors.textPrimary`/`textSecondary`/`textMid` | 카드, FAQ 리스트, 고지 영역 |
| Accent (10%) | `colors.brand` | **아래 "reserved for" 목록만** |
| 인라인 폼 오류 | `colors.inputError` (틸 #54B8CD) | **입력 필드 테두리·인라인 오류 텍스트 전용** (design.md §5-3-1, 기존 analyze.tsx error 패턴 유지) |
| 다이얼로그 오류·경고 시각 언어 | Figma 패턴 (§Figma Dialog Pattern) | **빨간 원형 느낌표 아이콘 + 브랜드색 주액션 CTA** — 인라인 폼 오류색과 별개의 시각 언어 |
| Advisory (측정 주의) | `colors.warnAmber` / `colors.warnAmberBg` | 기존 advisory tier 의미론 — 이 phase 신규 사용처 없음 (참조만) |

> **오류색 이원 계약 (belle Figma 실물 확인 2026-07-07):** 인라인 폼 오류(입력 테두리·필드 아래 오류 문구)는 기존 틸(`colors.inputError`) 유지. 반면 **오류·경고 다이얼로그**는 Figma 실물 패턴대로 빨간 원형 느낌표 아이콘 + `colors.brand` filled 주액션을 쓴다 — "빨간 오류색 금지"는 인라인 폼 스코프에만 적용되며 다이얼로그에는 적용하지 않는다.

**Accent (`colors.brand`) reserved for:**
- 다이얼로그/화면의 주 CTA 버튼 배경 (Figma 패턴 우측 주액션, "시작하기" 등)
- 오류·경고 다이얼로그의 빨간 원형 느낌표 아이콘 (Figma 추출 hex 를 토큰 매핑 — `colors.brand` 계열 우선, 상이하면 토큰 신설)
- 카드 좌측 아이콘 (SourceCard 패턴)
- 학습활용 opt-in 체크박스의 **checked 상태** (unchecked = `colors.inputBorder` 테두리)
- 텍스트 링크 (underline + `colors.brand`)
- 튜토리얼 dot 인디케이터 활성 dot
- FAQ 배지/pill 배경은 `colors.brandTint` + 텍스트 `colors.brand` (samples.tsx badge 패턴)

**금지:** 인라인 hex 사용. Figma 추출값 매핑에 기존 토큰(`brandTint`/`brandSoft`/`brandBg` 등)이 부족하면 `colors.ts` 에 토큰 신설 후 사용. 다크 배경 금지 (예외 없음 — not_pole 실패 화면(loading.tsx)의 기존 네이비는 기존 예외 화면 유지).

## Figma Dialog Pattern (경고·오류 다이얼로그 공통 계약)

**belle 확인 Figma 실물 패턴** (예: "용량이 너무 커요" / "지원할 수 없는 파일이에요" 프레임). 이번 phase 의 모든 경고·안내 다이얼로그는 이 패턴을 따른다.

구조 계약:

| 요소 | 계약 |
|------|------|
| 카드 | 연한 브랜드 틴트(연분홍) 배경 + 큰 radius 라운드 카드 — Figma 추출값을 `colors.brandTint`/`brandSoft`/`brandBg` 계열 토큰에 매핑 (불일치 시 토큰 신설) |
| 아이콘 | 중앙 상단 **빨간 원형 느낌표(!)** — Figma 추출 hex 토큰 매핑 |
| 타이틀 | 굵은 검정 텍스트 (`colors.textPrimary`, Bold — Figma 추출 크기를 토큰 매핑) |
| 본문 | 회색 1~2줄 설명 (`colors.textMid`/`textSecondary` 매핑) |
| 버튼 | **2개 가로 배치** — 좌: 닫기/보조 (흰 배경 `colors.cardBg` + 연한 보더 `colors.inputBorder` 또는 `divider` + 회색 텍스트 `colors.textSecondary`) / 우: 주액션 (`colors.brand` filled + 흰 굵은 텍스트 `typography.button` + `colors.textWhite`) |

**실행자 지침 (필수 순서):**
1. Figma 에서 해당/유사 다이얼로그 프레임을 **먼저 탐색**한다 (Figma MCP).
2. 있으면 **그대로 구현** (추출값 → 토큰 매핑).
3. 없으면 위 패턴을 확장해 신규 다이얼로그를 만든다 (design.md §0 자율 설계는 그 다음).
4. **기존 저화질 경고 모달(analyze.tsx lqCard)** 이 이 Figma 패턴과 다르면 이번 기회에 Figma 패턴으로 정렬을 검토한다 — 단 **D-07 연동 로직(승인 플래그 → not_pole 화질 우선 분기)은 불변.**

## Screen / Component Contracts

### S1. 첫 실행 튜토리얼 (SCENARIO 0, D-03/D-04)

- **비주얼 = Figma 프레임 추출이 계약** (§Figma Contract — Tutorial). 자체 디자인 금지.
- 구조 계약(design.md §5-8과 정합): 전체 화면 가로 스와이프 슬라이드 + 하단 dot 인디케이터 + 우상단 `건너뛰기` + 마지막 슬라이드 `시작하기` CTA (`layout.ctaHeight`, `radius.button`, `colors.brand` 또는 `gradients.brandButton`) — 단 Figma 프레임과 다르면 Figma 우선.
- 노출 규칙: **첫 실행 1회 + 스킵 가능** (로컬 플래그 — AsyncStorage 등 저장 방식 재량). 이후 FAQ 화면에서 재진입 가능해야 함.
- 내용 = 기대설정 중심 ("무엇을 측정하고 무엇은 못 하는지").

### S2. 이용방법/FAQ 화면 (SCENARIO 0, F2 — `analysis/samples.tsx` 교체)

- **Figma 에 이용방법/FAQ 류 프레임이 있으면 그것이 계약** — 실행자는 먼저 탐색.
- 없으면: 기존 samples.tsx 레이아웃 골격 재사용 — `colors.bg` 배경, backBtn(40×40, hitSlop 10), `typography.heading` 헤딩, `typography.caption` 부제, ScrollView 리스트. FAQ 항목 = 카드 (`colors.cardBg`, `layout.cardBorderWidth` + `colors.divider`, `radius.card`, `spacing.cardPadding`) 또는 아코디언 — 형태 재량, 토큰 준수.
