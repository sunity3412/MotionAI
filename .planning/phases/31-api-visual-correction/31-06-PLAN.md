<objective>
리뷰 H-03 의 결정론 백스톱을 구현한다: 생성된 교정 이미지의 목표 관절각을 실제 pose 추정으로 재측정해 허용오차와 대조하는 게이트. 허용오차 값 자체는 호출측(31-09)이 31-13 calibration 채택값을 env 로 주입한다 — 이 플랜은 tolerance 를 인자로 받는 측정기만 구현 (3차 리뷰 H3-02 원칙과 정합). 추정은 Pod 의 기존 estimator 를 얇은 엔드포인트로 재사용 (Lambda 에 GPU/onnx 반입 금지). Pod 미가용 시 fail-closed: typed 'pose_gate_unavailable' → 이미지 미노출 (D-08).

3차 리뷰 H3-04 해소: 3차 개정은 워커가 20MB 이미지를 허용하는데 /pose-image 는 8MB 상한이었고, 그 상한이 decoded 인지 base64 문자열인지도 모호했다. 이번 계약:
- **/pose-image 상한 (전부 명시): decoded image bytes <= 8MB, pixel count <= 16M (예: 4096×3904), 최대 변 <= 4096px, format allowlist = PNG/JPEG.** Pydantic 레벨에서 base64 문자열 12MB 상한(전송 방어) + decode 후 3중 검증. PIL `Image.MAX_IMAGE_PIXELS` 설정으로 decompression bomb 시 decode 자체가 거부.
- **측정측 정규화: measure_generated_pose 가 전송 전 deterministic resize(최대 변 1024px LANCZOS)/re-encode(PNG) 를 수행하고 encode 결과가 decoded/문자열 상한 이하임을 assert** — 워커가 어떤 크기(<=20MB)의 생성 이미지를 받아도 endpoint 는 항상 상한 내 요청만 받는다.

ARROW_JOINT_MAP 과 `joint_inner_angle_deg` 는 31-03(fault_zoom.py) 단일 출처를 import 재사용 — target 각도와 재측정 각도가 같은 함수로 계산 (B2-01 provenance 일관).

Purpose: "그럴듯하지만 기하가 틀린" 생성 이미지의 사용자 노출·학습 적재를 결정론적으로 차단 — payload 경계까지 계약으로.
Output: Pod /pose-image 엔드포인트 + pose_gate.py + 테스트.
