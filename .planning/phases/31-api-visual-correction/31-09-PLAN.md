<objective>
3차 리뷰 §7 Step 2 를 구현한다: worker/dispatcher 분리. 2차 개정의 "CAS → send, 실패는 예외 전파" 는 CAS commit 직후 crash 시 재전달된 과거 action 이 새 state 에서 no-op 하고 다음 action 은 영영 발행되지 않는 창 4개를 남겼다 (B3-01) — 폐기.

새 구조:
- **worker (VisualWorkerFunction):** 메시지 {jobId, action, generation} 수신 → 자기 외부 side-effect 1개 수행 → `transition_visual_job` 이 다음 state + nextAction + dispatchState='pending' 을 **한 transaction** 에 기록 → best-effort `sqs.send_message({jobId, action: nextAction, generation})` + `mark_visual_job_dispatched` CAS. **send 실패는 삼키고 log 만 남긴다 (예외 전파 아님)** — durable outbox 가 이미 남아 있어 dispatcher 가 복구한다.
- **dispatcher (VisualDispatchFunction — H3-09):** 별도 소형 Lambda (reserved concurrency 1, EventBridge rate(1 minute)). `list_dispatch_pending` 으로 dispatchState='pending' 인 **모든 nonterminal state** 를 조회해 정확한 nextAction 을 발행 + dispatched CAS + pending age metric 방출. worker 와 concurrency 를 공유하지 않는다.
- **종결:** 전부 `finalize_visual_job` (B3-02 — job+analysis 원자). canonical S3 put/copy 는 finalize 호출 전 immutable key 로.
- **URL 비저장 (H3-01):** poll succeeded 시 outputUrl 을 기록하지 않는다 — polling→fetching 전이는 상태만. fetch invocation 이 taskId 를 재-poll 해 fresh URL 을 얻고 같은 invocation 에서 즉시 streaming download 한다.
- **moderation retry (B3-01):** polling 에서 blocked + retryCount < MODERATION_RETRY_MAX 면 transaction 으로 polling→retry_ready + retryCount+1 + nextAction='create' 기록. create action 은 'reserved'|'retry_ready' 를 처리한다.

judge 입력은 31-05 `prepare_judge_payload` 로 정규화 + 16MB 내부 상한 (H3-03), pose 게이트 입력은 pose 전용 resize/re-encode 로 /pose-image 상한 준수 (H3-04). display/training 임계값은 31-13 CALIBRATION.json 채택값을 env 로 소비.

Purpose: 유료 잡이 고아도 중복 과금도 영구 불일치도 될 수 없는 비동기 실행기 — 3차 리뷰 §8-3 gate 1·2·3·4·11 의 실행 지점.
Output: visual-worker Lambda + visual-dispatch Lambda + 운영자 스크립트(reconciler 포함) + crash-injection 테스트.
