| **학습 페어 적재** (D-01) | `after`(생성물) 의존 → 교정 이미지 OFF 시 **자동으로 함께 정지**. phase 22 는 별도 경로(S3 `fixtures/phase22` 112영상)로 수집 중이라 학습 트랙은 안 멈춤 |

**★ 회전 영상의 위험은 교정 이미지와 성격이 다르다.** 교정 이미지는 실패하면 안 보여주면 그만이지만, 회전 영상은 **사용자가 그것을 자기 자세로 착각한다.** sliding-spin 에서 사용자는 "내가 봉에서 떨어져 있네" 라고 판단하는데 실제로는 봉을 잡고 있었다 — **없는 결함을 만들어내는 시각물**이다.

**코드는 지우지 않는다.** `VisualGenEngine` 추상화가 있어 자체 모델([[phase22-vlm-notebook-2026-guide]]) 준비 시 **엔진만 교체**하면 워커·디스패처·게이트·삭제 로직을 그대로 재사용한다.

## 4. 배포 범위 — 생성 Lambda 3종 제외

**이렇게 하면 막혀 있던 배포가 성립한다.**

지금 배포가 실패하는 이유는 SAM 템플릿의 임계값 파라미터(`DisplayPoseTolDeg`·`TrainingPoseTolDeg`)에 **Default 가 없기** 때문이다. 이는 31-10 의 의도된 설계로, 미측정 임계값이 조용히 프로덕션에 들어가는 것을 막는다. 임의값을 넣는 것은 **측정이 아니라 창작**이므로 금지.

**해법: 생성 기능을 아예 배포하지 않는다.**

- 제외: `visual-worker` / `visual-dispatch` / `visual-request` (Lambda 3종) + 관련 SQS/알람
- 그러면 임계값 파라미터 자체가 불필요 → 배포 성립
- 부수 효과: **미검증 코드가 프로덕션에 아예 올라가지 않는다**

**주의:** `pipeline/app.py` 의 producer 훅은 `VisualJobsEnabled=false` 일 때 조용히 폴백하도록 31-10 이 만들었다. 훅 자체는 배포돼도 무해하나, **enqueue 대상 큐가 없으면 예외가 나지 않는지** 확인할 것.

## 6. 실행 순서 (belle 개입 지점 표시)

1. **로컬 게이트** — 백엔드 전체 테스트(baseline **57 failed / 3366 passed / 수집오류 2** 초과 금지), phase31 스위트, `npm run typecheck`. *위험 0*
2. **SAM 템플릿 축소** — 생성 Lambda 3종 + 관련 리소스를 배포 대상에서 제외. 임계값 파라미터 제거 또는 조건부화
3. **`sam validate --lint` + 배포 dry-run**
4. 🔷 **belle 승인 → SAM 배포** *(라이브 변경)*
5. **배포 후 분석 E2E 1건** — 기존 분석이 안 깨졌는지 즉시 확인. 깨지면 롤백
6. **시뮬레이터에서 앱 확인** — 참고코너·2D 뷰어·화살표가 실제로 렌더되는지. *[[verify-ui-on-simulator-before-ota]]*
7. 🔷 **belle 승인 → OTA 발행** *(사용자 노출)*. 발행 후 belle 앱 **완전 종료 2회**(expo-updates 는 2회차에 적용)
8. **HUMAN-UAT 적립** — 즉시 belle 에게 넘기지 말고 [[batch-uat-after-phase-31]] 대로 배치 검토

**Pod 불필요** (회전은 Pod 무관 HTTP, 교정 이미지는 OFF). **추가 지출 0.**
