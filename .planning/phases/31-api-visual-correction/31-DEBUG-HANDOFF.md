## 1. 미해결 — 2D 비교 뷰어가 가로 막대로 뭉개짐 ★최우선

**증상:** 참고하세요 > 자세 비교 카드가 뜨지만 스켈레톤이 아니라 **가로 일직선**으로 그려짐 (belle 스크린샷 확인).

**원인 확정 (실측):**

`app/src/components/PoseCompareViewer.tsx`
```
const AXIS_H = 0;   // 화면 가로 = x
const AXIS_V = 2;   // 화면 세로 = z  ← 문제
```
주석 근거: *"joints3d(pole_aligned) 는 수직 분산이 Z 축에 있다 (z spread ~235, x ~95, y≈0)"*

**그런데 실제 데이터는 정반대다.** belle 분석 `2f68dcb38c7c4479b64ec6a61690c64a` 프레임 34 / 기준 `ref-power-spin` 프레임 90 실측:

| 축 | 사용자 spread | 기준 spread |
|---|---|---|
| axis0 (x) | 66.03 | 99.13 |
| axis1 (y) | 79.01 | 175.85 |
| **axis2 (z)** | **0.00** | **0.00** |

**z 가 전 관절 0** → 세로 좌표가 상수 → 한 줄로 깔림. 주석이 경고한 바로 그 현상인데 축을 반대로 골랐다.

**추정 수정:** `AXIS_V = 1` (y). RTMW 가 2D 백본이라 joints3d 가 `(x, y, 0)` 로 저장되는 것으로 보인다.

**착수 전 확인할 것:**
1. z=0 이 **모든 분석에서** 그런지, 이 건만 그런지 (다른 analysis 몇 개 표본)
2. `space: 'pole_aligned'` 의 축 정의가 문서화돼 있는지 (`pipeline/app.py:2070` 부근 주석이 좌표계 근거)
3. 주석의 "z spread ~235" 는 **구 R3F 뷰어(NLF 3D 시절)** 근거일 가능성 — NLF→RTMW 전환([[rtmw-free-stack-pivot]])으로 무효가 됐는데 주석만 남았을 수 있다
4. 세로 방향 부호 — 31-08 이 "어깨 중점이 고관절 중점보다 화면 위" 로 런타임 결정하게 해뒀으므로 축만 바꾸면 부호는 자동 처리될 것

`ARROW_JOINT_MAP` 이 요구하는 3점과 실제 측정 8관절이 어긋난다:

| 대상 | 필요 3점 | 가능? |
|---|---|---|
| 무릎 | 엉덩이-무릎-**발목** | ❌ |
| 팔꿈치 | 어깨-**팔꿈치**-**손목** | ❌ |

## 4. 이 3건의 공통 패턴 ★조사 가치 높음

**전부 "코드가 쓰는 데이터를 우리가 실제로 그렇게 보유/측정하는가" 를 아무도 대조하지 않아 생겼다.**

| 버그 | 코드의 가정 | 실제 |
|---|---|---|
| 뷰어 축 | z 에 수직 분산 | z 전부 0 |
| 뷰어 프레임 | 두 문서가 같은 프레임 공간 | 사용자 83 / 기준 159 |
| 화살표 | 발목·팔꿈치·손목 측정됨 | 8관절만 측정 |

**단위 테스트는 셋 다 통과했다.** 각 함수는 주어진 입력에 대해 옳게 동작하지만, **그 입력이 실환경에서 오는 형태와 다르다.** 12라운드 외부 리뷰도 못 걸렀다.

→ **같은 계열이 더 있는지 찾는 것이 이번 디버그의 본체.** 후보: `result.tsx` 의 다른 파생 로직, `visualCards.ts` 상태 파생, keypointReport ↔ joints3d ↔ angles 세 좌표/프레임 공간을 오가는 모든 지점.
