## 1. 제품 정의 (belle 2026-07-20 — 이 phase 의 헌법)

> 사실 기술은 보완일 뿐, 사용자가 이 분석을 보고 **① '해석을 쉽게'** 하고 **② '이렇게 하면 되겠다'는 방법을 알게** 해야하고, **③ '방법'을 몰랐을 땐 코치를 찾아야 함을 인지시키는 것**이 우리의 역할.
>
> 분석의 목표는 결국 사용자의 폴스포츠를 **더 잘하게, 부상 위험이 없도록, 연습을 혼자서도 충분히 가능하도록, 강사에게 무엇을 물어봐야 할지 알 수 있도록** 하기 위한 방법일 뿐.

**따름정리:** [[feedback-analysis-first]] 의 "분석 정확도 최우선" 은 유효하되, **정확도는 ①②③의 수단**이다. 정확한 수치를 냈는데 못 읽으면 실패다.

**belle 의 핵심 의심 (이 phase 의 출발점):**
> *"영상에서 이렇게 집는 걸 사용자가 '이해'할까? **각도 191도 어쩌고가 무슨 말인지는 알까?**"*

실제로 191° 는 180° 를 넘은 **과신전**이라 사용자는 "180이 최대 아닌가?" 로 혼란한다. **번역 없이는 이해가 구조적으로 불가능한 출력**을 내고 있다.

## 2. 연구 근거 (2026-07-20 deep-research: 104 에이전트 / 22 소스 / 주장 108개 추출 → 25개 검증 → 8 confirmed)

검증 방식 = 주장별 3표 적대적 검증(2/3 반박 시 기각). **confidence 와 vote 를 그대로 표기한다 — 확신 정도를 지우지 말 것.**

### 2-1. 우리 출력 형식이 실패 모드로 명명되어 있다 — **high / 3-0**
OPTIMAL 이론 (Wulf & Lewthwaite 2016, *Psychon Bull Rev*). 원문:
> 지도자가 *"동작이 어떻게 수행되어야 하는지 **설명**하고, **교정 피드백**을 주고, **신체 부위의 협응**을 언급하는"* → *"학습자 자기효능감 저하, 자기집중 증가... 결국 **악순환**과 최적 이하의 학습"*

우리 출력이 정확히 그 셋이다 (각도 수치 / 교정 지시 / 관절 이름).

**논문이 처방하는 대안 4가지 — 그대로 제품 패턴이 된다:**
1. **pull 방식** — 학습자가 요청할 때 피드백 (전부 펼치지 않음)
2. **선택권** — 무엇을 개선할지 학습자가 고름
3. **잘한 점 강조, 실수는 대체로 무시** — top-1 만
4. **신체 부위 언급 회피 → 주의를 과제 목표로 외부화**

*한계:* 대안은 논문에서 수사적 예시("imagine a scenario")로 제시됐고, 후속 반복연구(McKay 등)가 expectancy/autonomy 성분의 학습 이득을 문제 제기했다. **"현 형식이 문제"는 강한 근거, "이 대안이 증명됨"은 약한 근거.**

### 2-2. 검증된 대안 프레이밍 = 우선순위 + 트리아지 — **high / 3-0·2-1**
Kaia Motion Coach (JMIR 논문 PMC8317029 로 교차검증). 핵심은 "오디오"가 아니라:
- **부상 위험 순으로 우선순위**를 매겨 **한 번에 하나만** 노출 (전수 나열 아님)
- 동작 **중** 전달 (우리는 사후 분석이라 이 축은 불가)
- JMIR: 앱의 교정 제안이 **대면 물리치료사 피드백과 일치**

→ **우리가 가져올 수 있는 것 = 트리아지.** `safetyFlags` 가 이미 재료.

### 2-3. "적을수록 좋다" 로 단순화하면 안 된다 — **medium / 2-1·3-0**
- 24 RCT / 895명 체계적 문헌고찰: 피드백은 **대체로 학습을 돕는다**
- 유명한 guidance hypothesis(피드백 빈도 낮추기)는 메타분석에서 **"현존 연구가 지지하지 않는다"**
- 같은 리뷰: 최적 빈도·타이밍·지속은 *"불분명하게 남아 있다"*

→ **수치를 삭제하지 말고 계층화(접기)한다.** 삭제의 근거가 없다.

### 2-4. 유일하게 방어 가능한 규칙 = 상황 의존 — **high / 3-0**
> *"피드백 개입 시 **학습자의 숙련도와 기술의 복잡도를 평가**해 적절한 modality·frequency·timing 을 제공하는 것이 중요하다. 다만 이 변수들이 어떻게 상호작용하는지에 대한 이해는 제한적이다."*

→ "초보에겐 숫자 적게" 같은 구체 규칙은 **연구 근거가 아니라 우리가 실측해야 할 제품 가설**이다. 계측 없이 확정 금지.

### 2-5. 교정 이미지 — 상용 사례 0건, 그리고 그게 우연이 아닐 수 있다 — **low / 1-2**
- 생성으로 "교정된 자세 사진"을 출시한 제품이 **검증 결과 하나도 없음**
- 리서치 열린 질문: *"기술적 공백인가 의도적 교육학적 선택인가? **증거는 후자를 가리킨다** — 학습자에게 자기 몸의 교정된 이상적 이미지를 주는 것은 강력한 internal-focus 개입이며, 그것이 아무도 출시하지 않는 이유일 수 있다."*

→ **belle 결정: 매달리지 않는다.**

### 2-6. (보관용) 필요해질 때의 기술 해법 — **high / 3-0**
BrushNet(ECCV 2024)이 우리가 겪은 전신 재생성 문제를 명명하고 해법을 준다: **latent 공간 블렌딩이 아니라 픽셀 공간 합성** — 마스크를 흐린 뒤 copy-and-paste. 마스크 밖은 **비트 단위 원본 보존** → 전신 재생성이 *구조적으로 불가능*.
→ 지금은 안 쓴다. 나중에 교정 이미지를 되살릴 때의 해법으로만 보관.

### 2-7. 커버리지 한계 (정직하게)
- 체조 앱(CheckForm) 관련 주장은 **전부 기각**(0-3 / 1-2) — 가장 가까운 유사 도메인인데 살아남은 게 없다
- "원인 진단 → 드릴 처방" 패턴은 **검증 실패** — 제품 사례로 입증되지 않았다
- Wulf 의 external-focus 개별 실험들(골프 어깨-골반 각, best-trials 피드백, 관대한 성공 기준)은 **소스 접근 실패(403/PDF 추출 실패)로 0-3 기각** — *반증된 게 아니라 미확인*. 재검증하면 "수치 나열이 해롭다" 논거가 크게 강해진다. **재검증 가치 높음.**

## 4. 이 phase 가 만들 것 — 4 기둥

### ① 번역 레이어 — 숫자를 사람 말로
- `191°` → "무릎이 오히려 **뒤로 젖혀졌어요**" + 왜 위험한지 (과신전은 부상 축)
- `−20점` → "가장 큰 감점 요인이에요"
- **관절 이름 대신 외부 큐**: "왼쪽 무릎 19도 부족" → "**발끝으로 천장을 밀어내듯**" (근거 2-1 ④)
- **수치는 삭제하지 않고 접는다** (근거 2-3). 펼치면 기존 투명 감점 내역 그대로 — [[scoring-must-be-transparent-deduction-tally]] 불변

### ② 우선순위 — 한 번에 하나
- **top-1 결함만 전면**, 나머지는 탭하면 열림 (pull, 근거 2-1 ①③)
- **잘한 것 먼저** (근거 2-1 ③)
- **부상 위험 순 정렬** (근거 2-2). `safetyFlags` 활용
- 과금 모델 정합: belle — *"B도 과금 형태의 모델인 우리한테도 좋을 것 같다"*

### ③ 코치로 가는 출구 — 이미 있는 섹션 강화
- AI 가 **명시적으로 손을 든다**: "여기서부터는 강사와 함께 확인하세요"
- 강사 = 도입 결정권자 ([[field-research-stakeholders]]) — 강사가 자기 자리를 인정받는 구조
- belle: *"D는 당연히 다양성을 난 추구하고"*

### ④ 재생 중 큐 — 보고서를 "코칭받는 재생"으로 ★신규 아이디어
- 정적 목록 대신 **영상 재생 시 결함 순간에 큐 노출**
- **새 기술 0** — 결함 프레임 인덱스·DTW 정렬이 이미 있다
- Kaia 의 "동작 중 전달"을 사후 분석에서 흉내내는 가장 가까운 형태
- 오디오/자막 중 무엇으로 할지는 열린 질문

## 7. 열린 질문 [열린 질문] — belle 결정 필요

각 항목은 **선택지 + 트레이드오프 + 판단이 갈리는 지점**을 함께 둔다. 진행자는 추천을 갖되 belle 이 뒤집을 수 있게 근거를 노출할 것.

### Q1. ④ 재생 중 큐를 무엇으로 전달하는가
- **A. 자막/오버레이** — 학원은 시끄럽고 옆에 사람이 있다. 이어폰 없이도 됨. 화면을 봐야 함
- **B. 오디오** — Kaia 가 검증한 형태. 다만 그건 *동작 중*이고 우리는 *재생 중*이라 근거가 그대로 옮겨오지 않음
- **C. 둘 다 + 사용자 설정**
- *갈리는 지점:* 사용자가 이 화면을 **어디서 보는가**. 학원 현장인지 집인지에 따라 답이 다름. belle 이 현장을 안다.

### Q2. 외부 큐 문구를 누가 만드는가
- **A. 동작별 고정 문구집** — 품질 통제 가능, 강사 감수 가능, 비용 0. 6동작 × 관절 조합만큼 belle·강사가 써야 함
- **B. LLM 생성** — 확장성 있음. 다만 [[vision-score-must-analyze-not-stamp]] 교훈대로 **일반적 조언으로 흐를 위험**. 현장 리서치: 수강생은 일반적 답변에 이탈
- **C. 하이브리드** — 고정 골격 + LLM 이 상황 수치만 채움
- *갈리는 지점:* 문구 품질이 이 phase 의 성패다. LLM 이 "무릎을 더 펴세요" 수준을 뱉으면 **지금과 똑같아진다.**

### Q3. 수치를 어디까지 접는가
- **A. 기본 접기** — OPTIMAL 정합. 다만 [[scoring-must-be-transparent-deduction-tally]] 의 "내역 노출" 과 충돌하는지 판단 필요 (접기 ≠ 삭제이므로 충돌 아님이 내 해석)
- **B. 기본 펼치기** — 현행 유지, 번역만 위에 얹음
- **C. 사용자 설정** — [[coaching-tone-customization]] 선례 존재
- *주의:* "적을수록 좋다"는 **연구가 지지하지 않는다**(§2-3). 접는 근거는 OPTIMAL 의 pull 방식이지 정보량 축소가 아니다.

### Q4. 강사용 뷰를 따로 두는가
- **A. 분리** — 상세 수치는 강사, 수강생은 외부 큐만. 강사=도입 결정권자와 정합. 화면 1개 추가
- **B. 통합 + 접기** — Q3-A 와 같은 해법으로 양쪽 커버
- *갈리는 지점:* 강사가 앱을 **직접 보는가**, 아니면 수강생 화면을 **함께 보는가**. 후자면 분리가 무의미.

### Q5. Wulf external-focus 논거를 재검증할 것인가
- 소스 접근 실패로 0-3 기각됐으나 **반증이 아니라 미확인**(§2-7). 재검증하면 ① 설계 근거가 크게 강해짐
- **A. 이 phase 에서 재검증** (반나절) / **B. 근거 없이 진행** / **C. 안 함**
- *갈리는 지점:* 골프 실험(외부 큐가 어깨-골반 각을 실제로 바꿨는가)은 **우리 ①의 핵심 가정**이다. 틀리면 번역 레이어의 전제가 흔들린다.

### Q6. Phase 31 을 어떻게 마감하는가 (선행 조건)
- **A. 교정 이미지 flag OFF 로 31-12 마감** 후 32 착수 (권장)
- **B. 31 을 보류로 두고 32 먼저**
- *주의:* 31 산출물이 32 의 재료다. 열어둔 채 쌓으면 **무엇이 배포됐고 무엇이 아닌지 엉킨다.**
