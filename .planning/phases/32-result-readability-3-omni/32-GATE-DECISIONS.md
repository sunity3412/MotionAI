# Phase 32 게이트 확정 기록 (32-GATE-DECISIONS)

4대 미결 게이트 중 **실물 게이트(D-17)** 확정 + **D-23 스윕 매핑** 확인 기록. 후속 플랜(32-08/32-10/32-11/32-13)의 입력 문서.

- **일자:** 2026-07-21 저녁 (belle 실기기 리뷰 — OTA `2cf7b6af` 적용 확인 후)
- **선행 상태:** wave-1 수리 3건 반영 실물 (32-01/32-02 + 32-03 배포·스윕·OTA). 슬라이더 실기기 작동 확인으로 OTA 적용 검증됨 (belle 원문: "작동도 잘 되는데").

## 실물 게이트 (D-17) — 3건 확정

### 1. 동작 비교 형태 = 기본 양옆 동시 재생 + 탭하면 한쪽 확대 + 가로 유지 (제안안 채택)

- belle 원문 요지: "기본 양옆 동시 재생이 양 옆에 두고 가로확대(현재처럼)인거지? 그럼 1" (이해 확인 후 1안 확정).
- 소비처: 32-11 (비교 형태 구현).

### 2. 자세 비교 카드 = **존치 + 이번 phase 내 완성** (폐지·보류 없음)

- belle이 확대비교 드릴다운 시트 스크린샷(다리 신전 결함 — 내 프레임 + 정은지 프레임 쌍)을 가리키며 확정. 원문 요지: "이거라면 제대로 잡고 가야 된다", "이정돈 해야지".
- **실체 = 결함 순간 기준 프레임 쌍 비교** (방향 매칭 프로토 포함 방향).
- 품질 담보 경로: **32-10** 시트 3단 문구 재구성 + **32-13** 문장-영상 일치 스팟체크.
- 짝 실패(방향 매칭 실패) 시 해당 카드 숨김은 **최후 폴백으로만** 유지.
- 구분 명시: phase 31의 시간대응 실프레임 나열 카드는 **폐지 유지** (belle 제품가치 부정 이력) — 본 결정과 별개.
- 소비처: 32-10/32-11/32-13.

### 3. 재생 중 큐 밀도 = **결함 구간당 1개**

- 소비처: 32-08 (재생 중 큐 구현).

## D-23 스윕 매핑 — belle 확인 결과

- **확정:** 백엔드가 파이프라인에 배포되는 웨이브(32-09 / 32-12 B안 / 32-13 / 32-14 / 32-15)마다 **6 fixture 전수 재분석 스윕**, 백엔드 무배포 UI-only 웨이브는 재분석 대신 **기존 6 doc 전수 렌더 검증**. belle의 "한번에 몰아서, 결정만 실시간" 원칙과 합치 확인됨.
- 첫 실행 실적: 32-03 (기준선/배포후 각 13멤버 SERIAL, 점수 diff 0 — `32-03-SWEEP.md`).
- **커버리지 갭 (belle "왜 6개" 질의에 대한 답, 명시 기록):** 점수 기준선을 보유한 **학생 fixture가 6동작뿐**이라 6개다. 등록 기준 모션 10개 중 나머지 4개는 학생 영상 부재로 **스윕 미커버 갭** — 해소하려면 fixture 촬영·적재 별도 작업 필요 (현재 백로그, phase 32 범위 밖).

## 폰트 피드백 (32-07/32-10 입력)

- 로딩 화면(분석 중 진행률 화면)의 최소 폰트들 "정말 너무 작음" — 전역 타이포 하한 상향 시 기준 (**32-07** D-05).
