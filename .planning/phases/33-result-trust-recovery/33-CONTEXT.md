## Implementation Decisions

### 운영 규칙 (phase 내내 적용)
- **D-01** belle 에게 묻는 것은 딱 2회다 — ① 목업 확인 1회(확대비교+영상 표시 한 번에) ② 실기기 UAT 1회(구현 완료 후). 그 외 모든 결정은 Claude 가 정하고 근거를 문서에 남긴다. 판단이 갈리는 지점을 belle 에게 되던지지 않는다. belle 이 이미 결정한 것(일러스트 2안 확정 등)을 승인 게이트로 다시 묻지 않는다.
- **D-02** 예시 동작 매몰 금지 — belle 이 든 예시(파워스핀·킵업)는 증상을 목격한 창구일 뿐 범위가 아니다. 실제 범위는 전역이다(phrasebook 13 entry 전부 `__common__`, crop 로직 동작무관 공통, 오버레이 배선 공통). 어떤 수정도 특정 동작에 맞춰 만들지 않는다.

### 척추 · 분석 정확성 게이트
- **D-03** 표현 작업으로 분석 오류를 덮는 해법은 전부 기각. "다리 스플릿" 항목에 어깨 크롭이 붙은 것이 그 사례 — 표현만 고치면 정합성 ②("짚은 곳이 진짜 그곳")가 구조적으로 성립하지 못한다.
- **D-04** A-0 게이트를 웨이브 A 최선두에 신설. 6동작 fixture 에서 "현재 짚고 있는 부위(활성 criterion·크롭 관절)" vs "실제 결함 부위(기준·학생 영상 대조 실측)"를 전수 대조. 보유 데이터로 수행(신규 분석 불요). 판정: 어긋남 큼 → C+M3 를 phase 33 안으로 끌어와 뿌리부터 수정 후 표현 계층 / 어긋남 작음 → 표현 계층만 수정. 이 분기는 Claude 가 실측으로 판정(belle 질문 아님), 근거와 선택 분기를 문서에 남긴다.

### 심플 우선 (설명 추가는 최후 수단)
- **D-05** 해법 순서 = ① 없앤다(그 표시가 꼭 필요한가) → ② 자명하게(같은 크기·같은 순간·같은 표시로 맞추면 '다르다'가 저절로 보인다) → ③ 최후에 한 줄(①②로 안 되는 것만). 한 화면에 새로 추가되는 문장은 최대 1줄. 새 라벨·배지·범례를 추가하는 태스크는 계획에 넣지 않는다. 글자를 늘리는 방향의 해법은 기본 기각.
- **D-06** "근거 동봉"은 사용자 화면이 아니라 내부 검수용이다 — 크롭의 관절·프레임 근거는 우리가 오연결을 잡기 위한 검증 산출물(로그·검수 리포트)이며 사용자 화면에 라벨로 내보내지 않는다.

### 판정 기준 (목업·구현 합격선 — 조사 전 고정, 이후 불변)
- **D-07** 판정 기준 6개: ① 3초 안에 어디가 문제인지 짚기 ② 두 사진에서 무엇이 다른지 가리키기(글자 없이 형태만으로면 최상) ③ 그래서 뭘 하라는지 전달(단 D-05 순서를 지킨 결과여야 함) ④ 최악 데이터에서도 안 무너짐 ⑤ 틀렸을 때 틀린 줄 알 수 있음(표시는 자기 근거를 밝힘 — 무슨 관절·어느 순간) ⑥ 화면이 전보다 단순해짐(요소·문장 수가 늘었으면 실패). ⑥은 ①~⑤와 동급.
- **D-08** 최악 데이터 목록 고정: 가림(다른 신체·폴에 관절 가려짐) / 거꾸로(인버전) / 회전 중 모션블러 / 프레임 밖 잘림 / 좌표 결측 구간. 목업은 좋은 케이스 1개 + 위 최악 케이스로 함께 그린다. 좋은 영상만으로 만든 목업은 무효.

### 도메인 근거 조사 (무제한 조사 금지)
- **D-09** IPSF 전체를 읽지 않는다. 등재 동작별로 질의 4개만 고정: (1) 완성 기준=무엇이 되면 잘한 것 → 코칭 문구·크롭 대상 선정 (2) 흔한 실패 → 코칭 문구·일러스트 소재 (3) 강사가 교정 시 쓰는 말 → 코칭 문구 어휘 (4) 강사가 어디를 보라 하는가(부위·순간) → 확대비교가 무엇을 자르나. 출처 = NotebookLM 폴스포츠 노트북(IPSF Code of Points) + 현장 리서치. 대상 = fixture 6동작 우선 → 등재 11동작. 산출 = 동작×4질의 표 1장(코칭·크롭·일러스트 공통 재료). 앱이 새 표기법을 발명하지 않는다 — 학원에서 이미 통하는 방식을 옮긴다.
