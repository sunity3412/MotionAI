## 0.1. ★★ 척추 — 모든 것은 정확한 분석에서 나온다 (belle 확정)

> belle 원문: "이 모든것이 되는 핵심은 **정확한 분석**, 정확한 분석을 통한 **동작비교에서의 틀린 점
> 제시**, 정확한 분석을 통해 나온 **정확한 화면확대와 부위**, 정확한 분석을 통해 나온 개선점을
> 나타낸 **직관적이면서도 멋진 일러스트 화면과 음성, 자막**"

```
정확한 분석  ← 뿌리
   ├→ 동작비교에서 틀린 점 제시
   ├→ 정확한 화면 확대 + 부위
   └→ 개선점을 보여주는 일러스트 · 음성 · 자막
```

**표현 계층은 전부 뿌리의 열매다.** 뿌리가 틀리면 화면을 아무리 잘 만들어도 *틀린 것을 예쁘게
보여주는 것*이 된다. "다리 스플릿" 항목에 어깨 크롭이 붙은 것이 정확히 그 사례다.
**표현 작업으로 분석 오류를 덮는 해법은 전부 기각.**

### 귀결 — 웨이브 A 앞에 "분석이 맞는가" 게이트를 둔다 (A-0)

이 척추를 받아들이면, 기준모션 기질 정합(C+M3)을 phase 33 범위 밖으로 둔 결정이 위태롭다.
**"어느 관절이 문제인가"라는 분석 출력 자체가 기질 비대칭으로 오염돼 있을 수 있고**
(특히 인버전 동작 6종), 그 상태에서 화면만 고치면 §0.5 의 정합성 ②("짚은 곳이 진짜 그곳")가
구조적으로 성립하지 못한다.

그래서 **A-0 을 웨이브 A 최선두에 신설한다.** 이미 보유한 데이터로 수행 — 신규 분석 불요.

```
A-0. 분석 출력 정확성 확인
  6동작 fixture 에서 "현재 짚고 있는 부위(활성 criterion·크롭 관절)"
   vs "실제 결함 부위(기준 영상·학생 영상 대조 실측)" 를 전수 대조

  판정:
    어긋남 큼  → 기준모션 기질(C+M3)을 phase 33 안으로 끌어와 뿌리부터 수정 후 표현 계층
    어긋남 작음 → 표현 계층만 수정, 기질은 예정대로 별도 트랙 유지
```

**A-0 결과에 따라 phase 범위가 바뀐다.** 이 분기는 Claude 가 실측으로 판정한다(belle 질문 아님).
판정 근거와 선택한 분기는 문서에 남긴다.

## 0.5. ★ 심플이 먼저 — 설명을 붙이는 건 최후 수단 (belle 지적 반영)

> belle: "심플하면서도 **분석 잘되는구나를 사용자가 알 수 있게**" /
> "(문서가) 영상에다가 다시 뭘 적어놓을 것 같은 느낌"

**belle 감이 맞다.** 이 문서의 "표시마다 뭘 하라는지 붙어 있나 / 크롭마다 근거 동봉" 을 그대로
실행하면 **화면에 글자만 늘어난다.** 지금 병은 설명 부족이 아니라 **표시가 서로 안 맞는 것**이다.
설명을 얹어 덮으면 더 복잡해지고 신뢰는 안 돌아온다.

**해법 순서 (위에서부터 시도, 아래로는 못 풀 때만 내려간다):**

```
① 없앤다      — 그 표시가 꼭 필요한가? 아니면 지운다
② 자명하게    — 같은 크기·같은 순간·같은 표시로 맞추면 '다르다'가 저절로 보인다
③ 최후에 한 줄 — ①②로 안 되는 것만, 짧게
```

확대비교가 안 읽히는 진짜 이유는 캡션이 없어서가 아니라 **두 사진이 안 맞아서**다.
②만 제대로 하면 글자 없이도 읽힌다. **글자를 늘리는 방향의 해법은 기본 기각.**

**판정 기준에 상한을 둔다:** 한 화면에 새로 추가되는 문장은 **최대 1줄**. 그 이상 필요하다는 것은
①②를 덜 한 것이다. 새 라벨·배지·범례를 추가하는 태스크는 계획에 넣지 않는다.

**"근거 동봉"은 화면이 아니라 내부 검수용이다.** (§6.5 표의 표현이 모호했음 — 여기서 확정)
크롭의 관절·프레임 근거는 **우리가 오연결을 잡기 위한 검증 산출물**(로그·검수 리포트)이며
**사용자 화면에 라벨로 내보내지 않는다.**

### 사용자가 "분석 잘 되는구나" 를 느끼는 지점

설명량이 아니라 **정합성**에서 온다. 아래 4개가 신뢰의 실체다:

```
① 두 사진이 딱 맞물린다      — 같은 크기·같은 순간이라 겹쳐 보인다
② 짚은 곳이 진짜 그곳이다     — 어깨라 해놓고 다리를 짚지 않는다
③ 말이 그 동작에 맞다        — 옆으로 뻗는 동작에 "천장으로" 라고 하지 않는다
④ 군더더기가 없다            — 필요한 것만 있고 빨리 뜬다
```

이 4개가 되면 belle 이 말한 "심플한데 분석 잘 되네" 가 성립한다.
반대로 이 4개가 안 되는 상태에서 설명을 늘리면 **"궁금만 하는 앱"이 "복잡하고 궁금한 앱"이 될 뿐이다.**

## 1. 결정 — 도메인 근거를 어디서 얼마나 (Claude 결정)

**결정: 무제한 조사 금지. 질의를 미리 고정하고 표로 받는다.**

IPSF 전체를 읽는 방식은 시간만 쓰고 화면 설계에 안 붙는다. 대신 **등재 동작별로 아래 4개만** 묻는다.

| 질의 | 어디에 쓰이나 |
|---|---|
| 이 동작의 **완성 기준**은 무엇인가 (무엇이 되면 잘한 것인가) | 코칭 문구 · 크롭 대상 선정 |
| **흔한 실패**는 무엇인가 | 코칭 문구 · 일러스트 소재 |
| 강사는 이걸 교정할 때 **어떤 말로 지시**하는가 | 코칭 문구 어휘 |
| 강사는 **어디를 보라고** 하는가 (몸의 어느 부위·어느 순간) | 확대비교가 무엇을 잘라야 하는가 |

**출처:** NotebookLM 폴스포츠 노트북([[notebook-lm-pole-sports]], IPSF Code of Points) + 현장 리서치
기록([[field-research-stakeholders]]). **대상:** fixture 보유 6동작 우선, 등재 11동작까지 확장.
**산출:** 동작 × 4질의 표 1장. 이 표가 코칭 문구·크롭 대상·일러스트의 **공통 재료**가 된다.

**앱이 새 표기법을 발명하지 않는다** — 학원에서 이미 통하는 방식을 옮긴다. 그래야 수강생이
화면 보는 법을 따로 배우지 않는다.

## 2. 결정 — 판정 기준 (Claude 결정: 4개 → 5개로 보강)

목업·구현이 통과해야 할 합격선. **조사 시작 전에 고정하고, 이후 바꾸지 않는다.**

```
① 3초 안에 "어디가 문제인지" 짚을 수 있나
② 두 사진에서 "무엇이 다른지" 가리킬 수 있나  ← 글자 없이 형태만으로 되면 최상
③ "그래서 뭘 하라는지"가 전달되나 — 단, §0.5 순서(없앤다→자명하게→최후 한 줄)를 지킨 결과여야 함
④ 최악 데이터에서도 무너지지 않나
⑤ ★ 틀렸을 때 틀린 줄 알 수 있나
⑥ ★ 화면이 전보다 단순해졌나 — 요소·문장 수가 늘었으면 실패
```

**⑥이 ①~⑤와 동급이다.** 다 만족해도 화면이 복잡해졌으면 통과가 아니다.
설명을 얹어 ①~③을 달성하는 것은 우회로이지 해법이 아니다.

**⑤를 새로 넣는 이유:** 현 확대비교의 최악은 "틀렸는데 그럴듯해 보인 것"이다.
"다리 스플릿" 항목에 어깨 크롭이 붙어도 화면만 봐서는 알 수 없었다. 그래서 **표시는 자기 근거를
밝혀야 한다** — 무슨 관절인지, 어느 순간인지. 근거를 못 밝히는 표시는 노출하지 않는다.

**④의 최악 데이터 목록도 미리 고정한다** (나중에 고르면 유리한 것만 고르게 된다):

```
가림(다른 신체·폴에 관절이 가려짐) / 거꾸로(인버전) / 회전 중 모션블러
/ 프레임 밖 잘림 / 좌표 결측 구간
```

목업은 **좋은 케이스 1개 + 위 최악 케이스**로 함께 그린다. 좋은 영상만으로 만든 목업은 무효.

## 4. 결정 — 웨이브 A 내부 순서 (Claude 결정)

**결정: 병렬 아님. 아래 순서에 실제 의존이 있다.**

```
1) 동작별 기준 자세 확정 (§1 표)      ← 모든 것의 공통 재료
        ↓
2) 코칭 문구                          ← 코드 변경 0, 데이터 작업. 재료를 가장 먼저 소비
        ↓
3) 확대비교 (조사 → 목업 → 구현)      ← "이 동작에서 어디를 보나"가 크롭 대상 근거
        ↓
4) 영상 위 표시                       ← 확대비교와 목업 동시 확인(belle 확인 1회 원칙)
        ↓
5) 일러스트                           ← 문구가 확정돼야 무엇을 그릴지 정해짐
```

**왜 코칭 문구가 먼저인가:** 코드 수정이 없어 독립적이고, §1 조사 재료를 가장 먼저 소비해
나머지 작업의 근거를 확정해준다. 또 belle 이 "왜 천장으로 뻗으라 하나"로 지적한 신뢰 파손이
가장 값싸게 복구된다.

**목업(3·4)은 하나로 묶어 belle 확인 1회**로 처리한다.

## 6. 계획에 반드시 박아야 할 제약

- **검증은 6동작 fixture 전수 동일 빈도.** 한 동작만 좋아지면 미완료 판정.
  fixture 없는 등재 동작은 대체 검증 수단을 계획에 명시.
- **표시 추가 금지.** 화면 요소는 줄이거나 답을 붙이거나 둘 중 하나.
- **조사 없이 바로 구현하는 태스크 금지.** (현 확대비교가 그렇게 만들어져 망가진 것으로 판단)
- **채점 산식·임계값 무접촉.** 이 phase 는 표현·문구 계층.
- **코칭 문구는 코드 변경 불요** — `phrasebook.py:145` 가 이미 `{motion_key}.{criterion}` 우선 조회
  지원. `backend/data/phrasebook.json` 데이터 작업. **모순 시 출력 차단이 하드 게이트**

## 6.5. 오류 0 설계 (belle 지시: "최고의 결과물, 오류 0")

지금까지 오류가 새어나온 경로는 하나다 — **틀렸는데 그럴듯해 보여서 아무도 못 잡음.**
("다리 스플릿"에 어깨 크롭 / 파워스핀에 "천장으로 뻗어라" / 정은지 쪽 표시 누락)
그래서 계획은 **산출물마다 "틀리면 걸리는 장치"를 한 쌍으로** 편성한다. 장치 없는 태스크는 계획에 넣지 않는다.

| 산출물 | 틀리면 걸리는 장치 |
|---|---|
| 코칭 문구 | 기준 영상 프레임과 **방향 전수 대조**. 모순 → 그 문구 출력 차단(fail-closed) |
| 확대비교 크롭 | 크롭마다 **근거 기록**(무슨 관절·어느 프레임) — **내부 검수용, 화면 미노출**(§0.5). 전 항목 육안 대조 후 항목↔관절 불일치 시 그 카드 미노출 |
| 영상 위 표시 | 표시 ↔ 지적 항목 **양방향 일치 검사**. 짝이 없는 표시는 렌더 금지 |
| 일러스트 | 해부학 **전수 검수**(사지 개수·관절 방향). 1장이라도 실패 시 그 세트 미배선 |
| 앱 코드 | **시뮬레이터 실렌더** 확인 후 OTA. typecheck 통과를 근거로 삼지 않음 |
| 백엔드 | **6동작 fixture 전수** 재분석. 한 동작만 좋아지면 미완료 |

**통과 판정 규칙**

- "괜찮아 보인다"로 통과시키지 않는다. **수치·관측·전수 목록** 중 하나로 증명한다.
- 조용한 실패 금지. 못 하는 것은 **비워서 티 나게** 둔다(잘못된 값으로 채우지 않는다).
- 표본 검사 금지. 전수가 원칙이고, 전수가 불가하면 **무엇을 못 봤는지 계획에 명시**한다.
- **belle 확인 2회 앞에 Claude 자체 게이트를 둔다.** belle 에게 불량이 도달하면 그건 게이트 실패다.
  목업도 판정 기준 5개로 먼저 떨어뜨린 뒤 살아남은 것만 올린다.
- 각 계획의 완료 조건에 **"이 산출물이 틀렸다면 어떻게 알았을까"** 를 적는다. 답이 없으면 미완료.
