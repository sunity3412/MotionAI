## ★ 불변식 0 — 예시 동작에 매몰 금지 (belle 반복 지적)

> belle: "파워스핀으로 진행했다고 **파워스핀에만 매몰되지 말고**… 저번엔 킵업을 예시로 들었더니

belle 이 든 예시는 **증상을 목격한 창구일 뿐 문제의 범위가 아니다.** 실제 범위는 전부 전역이다:

| 발견 | belle 이 본 창구 | **실제 범위** |
|---|---|---|
| 코칭 문구가 동작을 모름 | 파워스핀 "천장으로 뻗어라" | phrasebook entry **13개 전부 `__common__`** → **전 동작 전 항목**이 같은 병 |
| 확대비교 결함 8종 | 파워스핀 분석 1건 | crop 생성·연결 로직이 동작 무관 공통 경로 → **전 동작** |
| 영상 위 표시 무설명 | 파워스핀 결과 화면 | 오버레이·마커·음성 배선 공통 → **전 동작** |

**작업·검증 규칙:** 어떤 수정도 특정 동작에 맞춰 만들지 않는다. 검증은 **6동작 fixture 전수 동일 빈도**
([[verify-all-fixtures-not-kipup-only]]). 한 동작에서만 좋아지고 다른 동작이 그대로면 **미완료로 판정**한다.
등재 동작 11종 중 fixture 없는 것은 대체 검증 수단을 명시한다.

## 이 phase 의 불변식 (모든 작업의 합격선)

> **화면에 표시되는 모든 것은 "이게 뭐고, 그래서 뭘 하라는 건지"를 그 자리에서 답한다.**
> 답하지 못하는 표시는 **노출하지 않는다.**

지금은 표시(점·원·선·바 마커·음성·각도)가 많고 답이 없다. 표시를 늘리는 작업은 이 phase 에서 금지.
표시를 **줄이거나, 답을 붙이거나** 둘 중 하나만 한다.

## ★ 표기 설계 조사 방법 (belle 지적: "계획의 방법을 안써놨네")

구현 전에 **조사가 선행**한다. 조사 없이 바로 구현하는 경로는 만들지 않는다
(현 확대비교가 그렇게 만들어져 망가진 것으로 판단).

**단계 1 — 판정 기준을 먼저 확정** (안 정하고 조사하면 취향 싸움이 됨)

```
① 3초 안에 "어디가 문제인지" 짚을 수 있나
② 두 사진에서 "무엇이 다른지" 가리킬 수 있나
③ 표시마다 "그래서 뭘 하라는지"가 그 자리에 붙어 있나
④ 최악 데이터(가림·회전·거꾸로)에서도 무너지지 않나
```

**단계 2 — 근거 3갈래**

- **(a) 도메인 우선** — 폴스포츠 강사가 실제로 자세를 지적하는 방식(거울·손으로 짚기·나란히 보기·
  시범)을 화면 은유로 그대로 옮긴다. 출처 = NotebookLM 폴스포츠 자료([[notebook-lm-pole-sports]]) +
  현장 리서치([[field-research-stakeholders]]). **앱이 새 표기법을 발명하지 않는다** — 학원에서
  이미 통하는 방식이어야 수강생이 따로 배울 게 없다.
- **(b) 선행 사례** — 자세 비교 관용구 조사(나란히 / 반투명 겹침 / 슬라이더 문지르기 / 유령 실루엣 /
  각도호 / 궤적선). 각각 **무엇을 보여주는 데 강하고 무엇을 못 보여주는지**로 정리.
- **(c) 데이터 한계** — 백엔드가 실제로 줄 수 있는 것(좌표 정확도·결측·crop 범위·시간 정렬 정밀도)을
  먼저 확정. **못 주는 것을 그린 목업은 무효.**

**단계 3 — 안 2~3개로 좁힘.** 같은 실데이터·같은 최악 케이스로 각각 그린다.
갈리는 지점: 확대비교 = 나란히 vs 겹침 / 크기 기준(몸·관절·폴) / 차이 표시(원·화살표·각도호·유령).
영상 표시 = 키포인트 12점 유지 vs 숨김 / 음성 중 화면 거동.

**단계 4 — 자체 검열.** 단계 1 기준으로 Claude 가 먼저 떨어뜨린다. belle 에게는 **살아남은 안만**.
전부 늘어놓고 고르라는 것은 belle 에게 일을 떠넘기는 것이라 금지.

**단계 5 — belle 확인 1회.** 실데이터 목업으로 한 번에.

**코칭 문구는 방법이 다르다 (취향 아닌 사실 확인):**

```
1. 동작별 기준 자세를 사실로 확정 — IPSF 자료 + 기준 영상 프레임 실측
2. 그 사실 위에서 문구 작성 (전 동작 대상 — 불변식 0)
3. 전수 대조 검수 — 문구가 가리키는 방향 vs 기준 영상의 실제 방향
4. 어긋나고 못 고치면 그 문구는 출력하지 않는다
```

**틀린 조언보다 조언 없는 게 낫다** — 현재는 틀린 것을 자신 있게 말해 신뢰가 깨진 상태.

## W1. 확대비교가 스스로 말하게 (belle 최우선)

> belle: "이게 제일 중요해.. 솔직히 이것만 되도 안 읽혀도 볼만할거다"
> belle 의문: "확대사진이 달라도 **이게뭐지?**"

**실측된 결함 8종** (32-UAT-FINDINGS §A):

1. **정은지 쪽에 표시가 없음** — 내 영상만 선/원. 비교 대상이 안 그려짐
2. **배율 불일치** — 내 쪽 확대·인물 잘림 vs 정은지 전신 → 나란히 놔도 비교 불가
3. **3장이 같은 순간** (user 34 / ref 90 고정, 관절만 상이) → belle "중복 느낌"의 정체
4. **자세 국면 어긋나 보임** — 내 쪽 다리 벌림 vs 정은지 접힘
5. **항목↔크롭 오연결** — "다리 스플릿"에 `left_shoulder` 크롭(55°)
6. **각도 배지가 PNG 에 구워짐** → 앱에서 못 끄고 못 옮김
7. 크롭이 인물 밖으로 잘림
8. `advisory` 항목이 데이터엔 있으나 시트 미노출

**해결 원칙:** 두 사진은 **같은 순간·같은 배율·같은 표시**여야 하고, 캡션이 **무엇을 견주는 중인지**
한 문장으로 말해야 한다. 그게 안 되면 그 카드는 내보내지 않는다(불변식).

**손볼 곳:** 백엔드 crop 생성(`analysis/fault_zoom*`) + 앱 연결
(`app/src/app/analysis/result.tsx:1215 selectedZoom` — region 첫 매치 반환이라 관절 정확도 없음).

**게이트:** 목업 선행 ([[ux-propose-user-centric-screens-first]]). belle 실제 영상 프레임으로
수정안을 먼저 보이고 확인받은 뒤 구현. **Task 1 = 목업.**

## W3. 코칭 문구가 동작을 알게 — **분석 오류 (신뢰 직결)**

> belle 의문: "정은지 선수도 다리를 양 옆으로 뻗는데 **왜 천장으로 뻗으라 하는거지?** (파워스핀 기준)"

**원인 규명 완료 (코드 실측):**

- `backend/data/phrasebook.json` 의 entry 키가 **13개 전부 `__common__.{criterion}`**
  (`__common__.leg_extension` 등). **동작별 문구가 0건.**
- `analysis/phrasebook.py:145` 조회 순서는 이미
  **`{motion_key}.{criterion}` (동작 전용) → `__common__.{criterion}` → fail-closed**.
- 즉 **기계는 동작별 문구를 지원하는데 데이터가 비어 있어** 전부 공통으로 떨어진다.
  파워스핀(다리를 옆으로 뻗는 동작)에도 `leg_extension` 공통 큐
  "발끝으로 **천장**을 길게 밀어낸다는 느낌으로" 가 출력된다.

**해결:** 코드 변경 없이 **동작별 문구 데이터 작성**. 등재 동작 × 실제 방출 criterion 조합에 대해
그 동작의 실제 기준 자세에 맞는 statusLine/whyLine/cueLine/coachQuestion 을 채운다.

**하드 게이트:** 문구가 **기준 모션의 실제 자세와 모순되면 안 된다.**
작성 후 각 동작의 기준 영상 프레임과 대조 검수(정은지가 실제로 하는 방향과 큐 방향 일치 확인).
모순 검출 시 fail-closed(일반론 조언 차단)가 공통 큐 오출력보다 낫다.
