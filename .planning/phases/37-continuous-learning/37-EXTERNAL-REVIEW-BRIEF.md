# 외부 AI 리뷰 요청 — "시간이 갈수록 똑똑해지는 분석 모델" 설계안

작성 2026-09-22 · 요청자: Sunity (폴스포츠 AI 코치)

## 0. 리뷰어에게 — 이 문서를 받은 당신이 할 일

우리는 **아직 안 만든 학습 구조**를 설계하는 중이고, 한 가지 방향을 골랐다.
**그 선택이 틀렸다면 틀렸다고 말해달라.** 동의만 하는 리뷰는 우리에게 쓸모가 없다.

구체적으로 답을 받고 싶은 질문은 **§9** 에 모아 뒀다. 그전에 §1~§8 을 읽어야
우리가 어떤 제약 안에 있는지 안다. 특히 **§8(우리가 가장 불확실한 것)** 은
우리 스스로 약하다고 보는 지점이라, 거기부터 공격해도 좋다.

리뷰가 우리에게 유용하려면 이런 형태였으면 한다:
- "그 선택은 맞다/틀렸다" + **왜** + 우리가 안 본 근거
- 우리가 제약이라고 믿는 것 중 **사실은 제약이 아닌 것**이 있으면 지적
- 우리 규모(아래 숫자)에서 **더 나은 대안**이 있으면 그것
- "이건 애초에 학습으로 풀 문제가 아니다" 도 유효한 답이다

## 1. 서비스가 무엇인가

폴스포츠(pole sports) 수강생이 연습 영상을 올리면, **세계챔피언(정은지 선수)의 같은
동작과 비교해 자세를 교정해주는 모바일 앱.** 현재 파일럿 MVP 단계, 실증은 2026년 10월 중순.

사용 모드 2가지:
- **Mode 1** — 내 영상 vs 정은지 기준 모션 (전문가 기준 점수)
- **Mode 3** — 내 영상 2개 비교 (성장 확인)

**핵심 가치는 "분석 정확도"다.** 점수가 믿을 만해야 하고, 출력이 단순 수치가 아니라
*"왜 안 되는지 + 무엇이 필요한지"* 여야 한다. 현장 조사 결론: AI가 일반적 답변만 하면
수강생은 이탈하고, 각도 수치만 보여주면 강사 철학과 충돌한다.

## 3. 채점이 어떻게 되나 — 그리고 왜 이건 모델이면 안 되는가

점수 = `100 − Σ(감점)`, 실행 감점 상한 40.

감점은 3가지 출처에서만 나온다:
- `ipsf_absolute` — 동작별 criteria 파일. **IPSF(국제폴스포츠연맹) Code of Points 인용**이
  근거다. 예: 파워스핀 무릎 `angle_target=180, tolerance=20, source_ref="IPSF CoP Glossary
  'Fully extended leg' p.130-131"`
- `reference_relative` — 정은지의 같은 순간 각도를 기준으로 삼는 축 (사람이 각도를 안 정함)
- `dimension_overall`

관절별 허용오차 **20도 dead-zone**, 초과 1도당 **1.2점** 감점.

감점마다 한국어 코칭 문장이 같이 나온다. 실제 출력 예:
> −20.0 "위로 뻗는 다리는 폴을 따라 수직으로, 반대 다리는 아래로 길게 눌러 한 줄로 뻗어보세요"
> −14.3 "어깨가 귀 쪽으로 으쓱 올라가지 않게 견갑을 눌러 잡고, 팔과 몸통 사이 각을 기준 자세에 겹쳐 맞춰보세요"

**★이 계층을 학습 모델로 바꾸지 않기로 이미 결정돼 있다.** 이유:
- 점수가 블랙박스가 되면 "왜 깎였는지"를 못 보여준다 = 제품 핵심 가치 상실
- 규정집 인용이 근거인데 데이터로 재보정하면 출처가 사라진다
- **사람 점수 라벨링은 영구 금지**다(오너 결정). 사람이 매긴 점수에 맞추는 순간
  AI 객관성이 깨지고, 그건 우리가 팔려는 것 자체를 훼손한다

리뷰어가 "채점도 학습시켜라"라고 제안한다면, **위 세 제약을 어떻게 지키면서 그게 가능한지**
까지 같이 말해달라.

## 4. 2026-09-22 실측 — 되는 것과 안 되는 것

정은지 선수의 **정타(잘한 것) / 실수(일부러 틀린 것)** 영상 쌍으로 Mode 1 을 돌렸다.
(GPU 서버 실행, 앱과 동일 경로)

| 동작 | 정타 | 실수 | 분리 |
|---|---|---|---|
| power-spin | 100 | **66** | 34 |
| peter-pan | 100 | **85** | 15 |
| pdshape | 100 | **87** | 13 |
| climb | 100 | **89** | 11 |
| kip-up | 100 | **100** | **0** |

**재현성**: 같은 영상을 3번 돌렸다 — GPU를 바꾸고(L4→4090), Gemini 캐시를 지워
새로 호출시켰는데 **차원 점수까지 완전히 동일**(100 / angle 100 · line 91 · stability 84).
"실행마다 점수가 다르다"는 현행 판에서 재현되지 않는다.

**kip-up 만 실패.** 일부러 틀린 영상에 앱이 내보내는 것:
```
100점
"이번 영상에서는 측정된 감점 항목이 없었어요 — 지금 자세를 유지해보세요"
"정은지 선수와 거의 동일한 자세입니다 · 관절각 일치도 99점"
보완운동 0건
```
**틀린 자세를 유지하라고 단언한다.**

★그런데 원인 분석에서 중요한 게 나왔다. 저장된 관절 각도를 직접 비교하니:
```
관절              정타중앙  실수중앙    차이
left_shoulder      27.8     59.6    +31.8      ← 크게 갈린다
left_knee         175.1    175.9     +0.8      ← 안 갈린다
```
그리고 서버 로그상 시스템은 **왼어깨를 찾아내서 확대 카드 앵커까지 걸었다.**
붙일 criteria 가 없어서 감점이 0이 됐을 뿐이다.

**즉 이 실패는 학습 부족이 아니라 사람이 쓴 설정(criteria 부재 + 허용오차 20도)에서 왔다.**
학습으로 바뀌는 값이 하나도 없다. → 리뷰어가 주목할 만한 지점이다(§8-5 참조).

또 하나: 서비스 오너가 두 영상 정지컷을 육안으로 보고 이렇게 판독했다 —
*"다리가 뜬 높이가 잘된 영상이 훨씬 높다. 왼팔이 잘된 건 잘 굽어 있고 잘못된 건 좀 펴져서
힘을 덜 받는다. 이 둘이 서로 영향을 미치는 것 같다."*
- 왼팔 관측은 데이터와 방향이 일치했다(팔꿈치 최소각 29.5° vs 40.6°)
- **"다리 높이"는 우리 표현에 아예 없다** — 특징이 관절 굽힘각 8개(팔꿈치·어깨·엉덩이·무릎
  좌우)뿐이라 절대 위치·높이를 표현할 수단이 없다
- Gemini 는 같은 영상에 "자세 차이가 거의 없어요"를 냈다
- 2026-06-27에 사람이 적어둔 라벨("공중에서 양 무릎 굽음")은 **실측과 반대**였다
  (무릎 최소각: 정타 149.8° / 실수 160.6° — 정타가 더 굽는다)

## 6. 우리가 내린 결정 — A 가 아니라 B

서비스 오너의 요구는 이것이다:
> *"1년이든 몇 년이든 계속 똑똑해지는 모델을 만들고 싶다. 폴스포츠에 많이 쓰겠지만
> 다른 종목(예: 발레)에서도 쓸 수 있게, 사람 동작에 대해 학습해야 하지 않나."*

두 방식을 놓고 **B** 를 골랐다.

```
A. 가중치 누적형
   지난 사이클의 학습된 모델 위에 새 데이터를 더 학습시킨다.
   "이어지는 것"은 모델 가중치.

B. 데이터 누적형  ← 우리 선택
   데이터셋만 누적하고, 매 사이클 베이스 모델에서 처음부터 다시 학습한다.
   "이어지는 것"은 데이터셋.
```

**B 를 고른 이유 4가지:**

1. **망각 회피** — 새 데이터만 추가 학습하면 이전 능력이 덮인다(catastrophic forgetting).
   특히 우리 데이터가 소량이라 최근 배치로 쏠릴 위험이 크다.
2. **되돌릴 수 있음** — 한 사이클이 모델을 망쳐도 그냥 버리면 된다. A 는 그 손상이
   다음 사이클에 계속 쌓인다.
3. **재현 가능** — 모델이 (베이스 + 데이터 스냅샷 + 하이퍼파라미터) 셋으로 재현된다.
   A 는 과거 모든 실행 순서에 의존해서 어디서 나빠졌는지 못 짚는다.
4. **★베이스 교체 내성** — 몇 년 단위로 보면 오픈 베이스 모델이 크게 좋아진다.
   A 는 2026년 베이스에 묶여 그 발전을 못 받는다(갈아타려면 어차피 처음부터 = B).
   B 는 베이스만 바꿔 같은 데이터셋을 다시 학습시키면 된다.

**즉 우리 입장은 "복리로 쌓이는 자산은 가중치가 아니라 데이터셋이고, 그 데이터셋은
미래의 어떤 베이스 모델이든 다시 읽을 수 있다"이다.**

받아들이는 대가: 데이터가 커질수록 매 사이클 학습 비용이 증가한다.

(※ 현재 코드의 `resume_from_checkpoint` 는 A 가 아니다 — 중단된 학습을 같은 데이터로
재개하는 크래시 복구다.)

## 7. B 위에 세운 설계 — 층을 넷으로 분리

오너 요구 중 "다른 종목에서도 쓸 수 있게"를 만족시키려면 한 덩이 모델로는 안 된다고 봤다.
한 모델에 몸 지식과 폴 지식이 섞이면 폴만 떼어낼 수 없기 때문이다.

```
1층. 몸 (종목 무관)    관절 표현 · 결함 문법("견갑이 솟는다", "관절이 무너진다")
                        가장 오래 가고 다음 종목으로 그대로 이전         ← 현재 없음. 설계 본체
2층. 종목 (폴)         어느 동작의 어느 국면을 보는가                   ← 현재 Gemini 가 임시 담당
3층. 채점              ★모델 아님. 투명한 감점 합산 (§3)               ← 현재 있음, 유지
4층. 말                감점 → 한국어 코칭 문장. 교체 가능한 소모품      ← 현재 Cerebras/Gemini
```

**1층과 2층을 가르는 것이 종목 이전의 전부**라고 본다.

근거로 삼은 관찰: 현재 출력되는 코칭 문장이 이미 몸 언어다 —
*"어깨가 귀 쪽으로 으쓱", "왼쪽 팔과 몸통 사이 각", "견갑을 눌러"*. 폴 용어가 하나도 없다.
견갑 하강 실패는 클라이밍·체조·역도에서도 같은 결함이다. 반면 "파워스핀 hold 국면"은
폴에서만 의미가 있다.

**증류 천장 문제**: 현재 정답을 Gemini 가 만들므로 학생 모델의 상한이 Gemini 다.
이걸 넘는 유일한 재료는 **강사(사람)의 판정**이라고 보고, 데이터 수집 우선순위를 그렇게 잡았다:
```
1순위  같은 동작을 여러 방식으로 틀린 영상 (지금 동작당 1편뿐 → 과적합)
2순위  강사 판정 — 부위·시점만 (점수 금지)
3순위  같은 동작을 다른 사람(강사 2~3명)이 수행 (지금 기준이 정은지 1명뿐)
4순위  학생 영상
보류   다른 종목 영상 — 1·2층이 갈리기 전에 넣으면 섞인다
```
**병목은 양이 아니라 짝(pair)과 사람 라벨**이라고 판단했다.

## 8. ★우리가 가장 불확실한 것 — 여기부터 공격해달라

솔직하게, 우리가 약하다고 보는 지점들이다.

**8-1. "증류는 선생을 못 넘는다"는 주장이 너무 강한 것 아닌가**
우리는 이걸 거의 공리처럼 썼다. 하지만 학생이 교사를 능가하는 사례(더 나은 데이터 선별,
self-consistency, RL, 앙상블 교사 등)가 있는 것으로 안다. **우리 조건(라벨 244개, 단일 교사,
도메인 협소)에서 그게 현실적인지** 판단해달라. 만약 가능하다면 강사 판정 수집의 우선순위가
내려갈 수도 있다.

**8-2. "1층(몸)"이 구체적으로 무엇인지 우리도 모른다**
"관절 표현 + 결함 문법"이라고 썼지만 입력·출력·학습 방법이 백지다. 소량 데이터로 범용적인
인체 동작 표현을 학습한다는 게 현실적인가? 아니면 그 층은 **애초에 학습하는 게 아니라
기존 파운데이션 모델(포즈 추정 + VLM)에 맡기고, 우리는 그 위 얇은 층만 가져야 하나?**
후자라면 우리 "층 분리" 구상은 다시 짜야 한다.

**8-3. 우리 규모에서 파인튜닝이 맞는 도구인가**
학습 데이터 244행, 수집 548편, 짝 6쌍, 사람 라벨 0건. 사이클 5회 전부 실패.
이 규모에서 8B VLM 파인튜닝이 합리적인가, 아니면
**프롬프트 엔지니어링 + 검색(RAG) + 규칙 개선**이 더 빠른 길인가?
"지금은 파인튜닝할 때가 아니다"도 우리가 받아들일 수 있는 답이다.

**8-4. B의 "베이스 교체 내성" 논거가 과장 아닌가**
A 방식도 주기적으로 베이스를 바꿔 처음부터 다시 학습하면 되지 않나? 그러면 A와 B의 차이가
우리가 주장한 만큼 크지 않을 수도 있다. 또 B의 비용 증가가 언제쯤 실질적 문제가 되는지
우리는 추정치가 없다.

**8-5. ★그리고 가장 근본적인 의문 — 우리 병목이 정말 모델인가**
오늘 실패한 kip-up의 원인은 학습된 무엇이 아니라 **사람이 쓴 설정**이었다
(criteria 파일이 비어 있음 + 허용오차 20도 상수 + 축 미발화).
오늘 파워스핀 점수를 80점에서 100점으로 되돌린 것도 **학습이 아니라 코드 수리**였다.
그렇다면 "계속 똑똑해지는 모델"보다 **채점 규칙과 특징 표현을 개선하는 것**이
실제 분석 정확도에 더 크게 기여하는 것 아닌가?
(오너의 요구는 장기 비전이고 타당하지만, 우선순위 판단이 필요하다)

**8-6. 특징 표현의 구멍**
오너가 육안으로 **가장 먼저** 짚은 차이("다리가 뜬 높이")를 우리 특징이 표현하지 못한다.
관절 굽힘각 8개가 전부다. 이건 데이터를 더 모아서 해결되는 문제가 아니라 표현 설계 문제다.
**인체 동작 분석에서 어떤 특징 집합이 표준인지**, 우리가 무엇을 빠뜨렸는지 지적해달라.

1. **A vs B 선택이 우리 조건에서 맞는가?** 틀렸다면 무엇을 잘못 봤나.

3. **§8-3 — 이 데이터 규모에서 파인튜닝이 적절한가?** 아니라면 대안은.
4. **§8-1 — 증류 천장은 실제로 우리를 막는가?** 강사 판정 수집이 정말 1순위인가.
5. **§8-2 — "몸 층 / 종목 층" 분리가 실현 가능한 구상인가?** 종목 이전을 달성하는
   더 나은 아키텍처가 있나.
6. **§8-6 — 인체 동작 분석 특징 표현에서 우리가 빠뜨린 것은?**
7. **§3 제약(투명 채점 · 사람 점수 라벨 금지 · 규정집 출처)** 중 우리가 과하게
   해석한 것이 있나. 있다면 어디까지 완화 가능한가.
8. 우리가 **아예 묻지 않은 것 중 물어야 했던 것**이 있다면.
