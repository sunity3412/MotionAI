<objective>
Add two pod-free purity gates to the Phase 24 eval suite that close the two holes the
current `check_generalization` gate leaves open:

1. **Clean-residual gate** — the existing generalization gate only proves `fault shortfall
   > success shortfall` (relative). A contaminated 정타(correct) member can still carry a
   reference-relative angle residual above tolerance and pass relatively. This gate asserts
   the absolute property: every measured-angle record in a `correct` member must reconstruct
   to a raw deviation ≤ that criterion's IPSF tolerance.

2. **Sensitivity (above-cutoff) gate** — elite-low (clean stays clean) alone does not prove
   metric validity. This gate feeds a clearly-above-tolerance synthetic deviation (the kip-up
   18° knee class, scaled to tolerance+margin) directly into `deduction_engine.tally` and
   asserts it produces a non-trivial penalty (`final < 100`), while a within-deadzone input
   produces none.

Purpose: harden the analysis-accuracy P1 verification floor. The clean-residual gate is
EXPECTED to FAIL once the post-24-07 granular reference-relative pod artifact lands with
contaminated 정타 residuals — that red is the signal P1 objective-IPSF scoring must turn
green. The sensitivity gate is synthetic and always runs.

Output: two new gate functions in assert_gates.py (registered in main()) + unit tests.
</objective>

- `ipsf_criteria.CRITERION_GROUPS` is a tuple of dicts, each with `id`, `tolerance`, `slope`,
  `ipsf_cap`, `deviation_source`, `direction`. Angle criteria tolerance = `_ANGLE_TOLERANCE_DEG`
  (20.0, [CITED]); reach `body_relative_reach` tolerance = `_NOTCH_TOLERANCE` (0.5). slope =
  `kismam._PENALTY_PER_DEG`, `_ANGLE_CAP` = 90.0. THRESHOLDS MUST be read from this structure —
  no magic numbers in either gate.
- `check_generalization` already builds `tol_by_crit = {c["id"]: c["tolerance"] for c in
  ipsf_criteria.CRITERION_GROUPS}` — reuse the exact same idiom.
- `deduction_engine.tally(...)` returns a `DeductionBreakdown` object with `.records` (tuple of
  `DeductionRecord` objects, each `.points` signed-negative, `.criterion`, `.measured_value`,
  `.baseline_value`, `.deviation`, `.deviation_source`) and `.final` (int = `max(0, round(100 +
  Σpoints))`). `.to_dict()` flattens to camelCase (`measuredValue`, `baselineValue`, `deviation`,
  `deviationSource`, `points`, `final`, `records`).
- ENGINE INVARIANT: a record is emitted ONLY when `over = max(0, raw_deviation - tolerance) > 0`
  (see `if over <= 0.0: continue`). So any measured-angle record present in a `correct` member
  already implies raw deviation > tolerance.
- RAW-DEVIATION RECONSTRUCTION (uniform across deviation_source): `raw = abs(baselineValue -
  measuredValue)`. For ipsf_absolute baselineValue=180 and measured_value = 180 - d → raw = d.
  For reference_relative over_target baselineValue=0.0 and measured_value = d → raw = d. For reach
  baselineValue = reference notches, measuredValue = student notches → raw = ref - stu shortfall.
  This is the tolerance-anchored quantity to compare, robust to the over-vs-raw field convention.
- The `dimension_overall_fallback` criterion is NOT in CRITERION_GROUPS (no `tolerance`), so it is
  naturally skipped by `tol_by_crit.get(crit) is None` — correct: the honest-0 fallback score is
  not a measured-angle residual and is out of this gate's scope.
- Artifact path constant already exists: `_BREAKDOWN_ARTIFACT`. Artifact member shape: `{motion:
  {fault: {records:[...], final, ...}, correct: {records:[...], final, ...}}}`; members may be
  `null` (climb) or have empty `records` (clean). Reuse the existing `_records_of(member)` helper
  to extract records (it handles object/records-list/null shapes).
- Tests load gates via the file-path loader `_load_gates()` already present; the suite imports
  `deduction_engine, ipsf_criteria, vision_veto` and reuses `_ctx`, `_diff`, `_tally`. Run with:
  `cd backend && python -m pytest tests/test_phase24_gates.py` (conftest.py injects shared/python).
