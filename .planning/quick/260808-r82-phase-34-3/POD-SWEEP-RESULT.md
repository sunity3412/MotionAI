## 3. 운영 경로 결함 발견·수리 — 리그 H4 전건 FAIL (커밋 a994455)

첫 신선 재분석에서 리그 H4(음성 진품 조인)가 **r00~r04 5건 전건 FAIL**
("이 분석의 coachAudio 에 없는 rid — 외부 mp3 의심").

- **원인 (재봤다)**: `_run_deferred_coach_audio` 는 Firestore `result.coachAudio`
  단일 field-path 만 부분 갱신하고 **in-memory result 에는 싣지 않는다**. 스테이지가
  `doc_like = {"result": {**result, ...}}` 로 조립하면 coachAudio 가 없어 H4 가
  조인할 대상이 0 → 전건 FAIL. **즉 실제 업로드 경로에서는 합성 영상이 원리적으로
  부착 불가능한 상태였다.**
- **왜 어제 안 드러났나**: 08-08 --write 성공은 `rerun_compare_stage.py` 진단
  드라이버 경로 — Firestore doc 을 읽어 넘기므로 coachAudio 가 있었다.
  [[feedback-approval-attaches-to-production-path]] ("승인은 산출물이 아니라 생산
  경로에")의 정확한 실사례.
- **수리**: 스테이지가 이미 받는 `coach_audio_items`(그 분석이 방금 합성한 목록 —
  Firestore 재조회보다 강한 동일성)로 doc_like 의 coachAudio 를 채운다.
- **회귀 게이트 2건 + 뮤테이션 검증**: 수정을 되돌리면 새 테스트가 **정확히 FAIL**

## 5. 남은 결함 — E 저더(ref 패널 재개 직후) : **표집 운으로 통과, 실재함**

리그는 PASS 를 냈지만 **같은 입력·같은 코드의 두 렌더가 임계를 사이에 두고 갈렸다**:

| 렌더 | ref 이벤트 시각(초) | 최악 2s창 | 리그 |
|---|---|---|---|
| run1 | 69.73 · 70.53 · 70.77 · 70.87 · 71.50 (+87.87) | **5** | FAIL |
| run2 (부착본) | 69.57 · 70.37 · 71.00 (+87.70) | **3** | PASS (임계 4 바로 아래) |

- 두 렌더 모두 **같은 구간(69.5~71.5s = 마지막 정지 해제 직후)**에서 ref 패널이
  가다-서다. 갈린 이유는 RTMW 재추출 비결정성(파리티 실행에서 align curve 불일치
  실측) — 즉 **PASS 는 판정기의 승인이 아니라 표집 운**이다. 08-08 E v2 를 만들 때
  잡았던 함정("픽스처 PASS 는 창 착지 운")과 같은 계열이므로 통과로 종결하지 않는다.
- **원인 확정 (재봤다)**: 그 구간 DTW 곡선 slope 가 0.714 → 0.429 → **0.000**
  (user 16.67 → 17.17 → 17.67s). ref 시간이 멈춘다 = ref 패널 정지. user 영상이
  ref 보다 길어 끝에서 정렬이 눌러붙는 것 — **어제 반려의 뿌리와 동일 구조**를
  채점(수술 ②)·freeze 짝(G 핀)에선 막았고 **재생 트랙에만 남아 있다.**
- **다음 라운드 방향 (실현 가능성 확인됨)**: 재생 트랙에서도 ref-눌러붙음 꼬리를
  제외. 승인 5편 slope~0 run 실측 = elbow 0 · kipup 0 · peterpan 0 ·
  powerspin (7.73s, 6프레임) · pdshapefault (0.33s 4프레임, 17.40s 10프레임).
  **승인본 3편은 무영향**, powerspin·pdshapefault 는 꼬리 근방이라 byte 변화 가능 →
  "종점 마진 절단"은 승인 렌더를 바꾼다(pdshapefault 종점 여유 0.07s). 따라서 후보는
  **꼬리의 slope~0 구간만 제외**(중간 run 무접촉)이며, 승인 5편 재렌더 diff 를 게이트로.
