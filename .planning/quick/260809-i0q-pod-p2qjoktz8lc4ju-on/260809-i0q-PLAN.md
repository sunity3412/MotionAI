# Pod p2qjoktz8lc4ju 기동 + 실업로드 경로 결정론 ON

## 배경

08-08 마감의 운영 이전 잔여 1건: **서버 경유 실업로드 경로는 결정론 OFF**.
채점 엔진(`rtmw_engine`)과 렌더 정렬(`compare_align.build_model`)이 둘 다
`RTMW_DETERMINISTIC=1` env 게이트에 걸려 있는데, Pod 서버 기동 스크립트에 그 env 가
없어 belle 이 앱에서 업로드하면 결정론 없이 돌아간다. 같은 영상이 매번 다른 정렬을
만들면 리그 판정이 운에 걸린다([[render-determinism-context-must-wrap-all-rtmw-paths]]).

## 착수 시 발견 (계획 수정 근거)

메모리 노트는 대상 파일을 `start_p15_server.sh` 로 적고 있었으나 **두 스크립트를 직접
열어 보니 그 파일이 함정 쪽이었다**:

| 파일 | 크기/날짜 | PR_INVERSION_ENABLED | 코치/프리페치/모델 로테이션 |
|---|---|---|---|
| `start_server.sh` | 3118B / 07-22 | **있음 (=1)** | 전부 있음 |
| `start_p15_server.sh` | 1033B / 06-21 | **없음 (OFF 함정)** | 없음 |

`current-pod-pqe6uaw7mf8bh9` 메모리가 이미 "서버 시작 정본 = start_server.sh
(p15 판 = 인버전 OFF 함정 금지)" 로 경고해둔 바로 그 상황. 따라서 **정본은
start_server.sh** 이고, 결정론 env 는 여기에 넣는다.

## 작업

### T1. 정본 start_server.sh 에 결정론 env 박제 (Pod)
- 파일: `/workspace/start_server.sh` (Pod, Network Volume)
- 조치: `export RTMW_DETERMINISTIC=1` 추가 (근거 주석 동반, 멱등 삽입)
- 검증: 재기동 후 `/health` → `envFlags.RTMW_DETERMINISTIC == true`

### T2. p15 함정 스크립트 무장해제 (Pod)
- 파일: `/workspace/start_p15_server.sh`
- 조치: 정본으로 위임(delegate) — 어느 쪽을 실행해도 인버전·결정론이 켜지도록
- 근거: 메모리 노트가 이 파일을 가리키고 있었음 = 다음 세션도 같은 함정을 밟는다

### T3. 서버 기동 + 기계 검증
- 부트스트랩(`bootstrap_full.sh`) → `start_server.sh`
- 검증: `/health` 4항목 — `commitSha == main HEAD`,
  `envFlags.RTMW_DETERMINISTIC == true`, `envFlags.PR_INVERSION_ENABLED == true`,
  `modelInitCanary.modelLoaded == true`

### T4. SSM / Lambda 동기화
- SSM `/sunity/motion/runpod-analyze-url` → 새 proxy URL
- Lambda `sunity-motion-pilot-pipeline` env `RUNPOD_ANALYZE_URL` → 동일 (나머지 키 보존)
- 검증: Lambda get-function-configuration 로 값 재조회

### T5. 정본 기동 스크립트 리포 버전화
- 파일(신규): `backend/runpod_inference/start_server.sh`
- 근거: 이 스크립트가 git 밖이라 인버전(32-15)·결정론(08-08) env 누락이 **반복**됐다.
  리포에 두면 diff 로 보이고 리뷰된다. Pod 볼륨 사본이 실행 정본인 것은 유지하되,
  리포본이 내용 정본.
