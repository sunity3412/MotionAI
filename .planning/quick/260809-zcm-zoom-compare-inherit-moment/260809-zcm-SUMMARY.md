# 260809-zcm 요약

## 왜 손댔나

STATE 의 "다음 1순위 = 확대 비교 각도 표시"로 착수했다가, **전제가 뒤집혔다.**

- 각도가 안 그려지는 것은 게이트가 보수적이라서가 아니다. 게이트를 열고 강제로
  그리면 **폴 위에 세로선 하나**가 그어진다(실물 확인). 저신뢰 좌표는 틀린 자리다.
- 더 큰 것: **카드가 고른 프레임 자체가 붕괴 프레임**이었다. pdshape 오른팔꿈치
  카드의 프레임 118 = 12관절이 폴 위 한 줄로 뭉침(몸통 = 클립 중앙값의 **8%**,
  가로/세로 **0.03**). 그런데 그 프레임의 right_elbow 신뢰도는 **0.67** — 게이트 통과.
  시스템 자체 품질 라벨은 **"medium"**.
- 원인: 표시 프레임 선택이 "그 관절 confidence 최대"인데 **붕괴 프레임에서 모델이
  더 확신한다** → 붕괴가 선택을 끌어당긴다. 창(±0.22s) 후보 9개 중 **가장 나쁜 것**이
  뽑혔다. 전수 = belle 계정 카드 30장 중 4장이 그 위에 서 있었다.

## 구현 (`835b0417`, `compare_render.py`)

- `zoom_cards(freezes, user_video, ref_video, align, out_dir, workdir)` — 렌더 후처리.
  `render(..., zoom_dir=...)` 로 호출. **zoom_dir=None(기본)이면 영상 산출 무변경.**
- `_zoom_refine_rt` — 영상이 정한 rt 를 **중심으로만** 쓰고 ±0.4s 안에서 자세 거리
  (몸통 정규화 후 신뢰 관절 평균 L2) 최소인 시각으로 당김. pdshape 실측 ±1프레임.
  **창을 넓히면 종전 실패(붕괴 프레임 흡인)가 재발**하므로 좁게, 실패 시 영상 값 유지.
- `_native_frame` — 원본 해상도 프레임 1장(ffmpeg -ss). 사용자 영상 실측 2160×3840.
- `_zoom_display` / `_zoom_panel` — 표시를 원본 좌표로 다시 그림(문법·색·비율 동일).
  기준 시각이 움직이므로 기준측 사이각은 같은 함수로 재계산 + `_pair_lockstep_degrees`.
- 영상에 없던 유일한 추가 = **기준 패널 링**(영상은 학생 패널에만 그림). 멈춘 사진에서
  한쪽만 표시되면 비교가 성립하지 않아서. **사본에 그려** 영상 프레임 무접촉.
