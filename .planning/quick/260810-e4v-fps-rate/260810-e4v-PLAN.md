## 무엇이 틀렸나 (260810-cbt 실측)

`FfmpegFrameExtractor.extract` 는 **정수 step** 으로 솎으므로 실제 산출 rate 는
`src_fps / round(src_fps/target_fps)` 인데, 저장·환산은 **요청값** `target_fps` 를 쓴다.

## ★ 자리가 두 개다 (측정으로 갈림 — 한 덩어리 아님)

| | 무엇이 틀렸나 | 무엇이 고쳐지나 | 점수 |
|---|---|---|---|
| **사용자 쪽** | `atVideoSec = atFrameIdx / 9.0` (실제 9.997) | **사진·정지 앵커** (최대 16프레임@15fps) | **불변**(tally 종료 후 각인) |
| **기준 쪽** | 기준 트랙 저장 `fps=18.0` (실제 14.93) | `ceil(0.5×fps)` 경계 마진 9 → 8 프레임 | **이동** (편차 ≤0.6도 실측) |

`_pipeline_frame_fps()` 는 사용자 축만 담당한다 — 기준 쪽은 `reference_kp_fps`(저장 doc)
라서 **다른 수리**다. belle 승인한 점수 이동은 기준 쪽에서 나온다.

## 단위

### U1 — `frame_extractor` 실효 rate 를 산출·기록 (순수·산출 무변경)

- `effective_fps(src_fps, target_fps) -> float` 순수 함수 (= `src_fps / step`).
- `extract()` 가 경로별로 실측 메타 기록: `effective_fps_for(path) -> float | None`.
  **프레임 배열은 byte-동일** — 기록만 추가.
- 경로별인 이유: 한 분석에서 사용자·기준·이전 영상을 같은 인스턴스로 추출하므로
  단일 속성이면 서로 덮어쓴다(조용한 오염). 미지 경로 = `None` → 호출측 fail-open.

### U2 — 사용자 축: 사진 앵커 교정 (점수 무접촉)

- `_pipeline_frame_fps(video_path=None)` — 경로 주면 기록된 실효 rate, 없으면 종전
  `target_fps`(byte-동일 폴백).
- `atVideoSec` 산출(`app.py:2535`)에 분석 영상 경로를 전달.
- 게이트: 감점 record 의 `points`/`deviation`/`measuredValue` diff 0 · pytest 기준선 59.

### U3 — 기준 축: 경계 마진 교정 (점수 이동 — belle 승인분)

- mode1 `reference_kp_fps` 를 저장 라벨이 아니라 **기준 트랙 실효 rate** 로.
  출처 = 같은 분석에서 추출한 기준 영상(U1 기록) — 없으면 저장 라벨 폴백(fail-open).
- 산출 = **점수표**: 5 픽스처 × 관절별 편차 이동 + 감점 유무 뒤집힘 여부.
  belle 께 보고(거부권 아님 — "정당하면 괜찮다"). 확정은 Pod 재분석.

## 하지 않는 것

- 표시 순간 **규칙** 교체(최대 차이 순간 등) — 앵커 교정 후 별건.
