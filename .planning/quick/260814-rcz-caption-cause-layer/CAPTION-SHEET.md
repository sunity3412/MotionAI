### 1-3. 이 문장들이 지키는 것

| 규율 | 지킨 방법 |
|---|---|
| **새 사실 발명 0** | 두 문장 다 belle 원문의 전사. 원문은 `phrasebook.json` `_meta.causeLineProvenance` 에 함께 박제 |
| **측정 안 된 것을 측정된 것처럼 말하지 않는다** | belle 이 말한 원인(회전력·올라오는 타이밍)은 **현 데이터로 측정 불가**다. 그래서 전부 가설 어미("~일 수 있어요" / "~것으로 보여요")로만 쓰고 수치·각도·퍼센트·단정 어미는 0. 테스트가 강제 |

| **원인 없는 record 무회귀** | 문구집 67 entry 중 **2건만** 원인을 갖는다. 나머지 65건의 캡션은 **문자 하나도 바뀌지 않는다**(전 entry 스윕 테스트) |

### 1-4. 자막 3줄 클립 위험 — 실측 보고

구운 자막은 `wrap_text(...)[:3]` 로 4번째 줄을 **조용히 버린다**. 넘치면 잘리는
쪽이 행동절이라 2026-08-01 반려("자막이 결함 대신 목표를 말한다")가 재발한다.

승인 코퍼스 운영 폭(패널 608 × 2 + 8 = **1224px**, 5동작 전건 동일 — ffprobe

| 신 캡션 | 123자 · **3줄** | 132자 · **3줄** |
| 여유 | 상한에 딱 맞음 | 상한에 딱 맞음 |

★**원안 문구는 넘쳤다.** 처음 쓴 문장은 pdshape 62자(총 134자 = **4줄**),
powerspin 50자(총 148자 = **4줄**)로 둘 다 행동절이 잘렸다. 그래서 belle 원문
**의미 안에서** 축약했다 — pdshape 62→51자, powerspin 50→34자. 잘라낸 것은

## §2. 각도 표기 적용 조건 — 재고 나서 정했다

belle 물음: "각도를 표기한다고 해도 잘한 영상쪽 각도가 좀 애매해 저렇게 표기하는게
맞는지 모르겠네."

**임계를 먼저 정하지 않았다.** 판정 규칙(통과집합/반려집합/분리 마진 조건)을 표를
보기 **전에** 커밋하고(`02dfb35`), 그 다음 승인 코퍼스에서 V 가 실제로 그려진 카드
전건 + 후보 2건의 px 사이각을 운영 함수로 재서 규칙을 기계 적용했다.

결과 (상세 = `MEASURE.md`):

| 축 | 판정 |
|---|---|
| ref 사이각 / 직선근접(ref) / deficitDeg / 대조방향 | **분리 없음** |
| user 사이각 / 직선근접(user) | 분리는 되나 마진 1.53 < 필요 16.81 → **기각** |
| **양 패널 사이각 절대차 \|Δ\|** | P 최대 84.85 / N 114.40 → 마진 29.56 ≥ 필요 15.83 → **채택, 임계 99.6도** |

**이 축이 재는 것**은 "차이가 큰가"가 아니라 **두 패널이 같은 종류의 마크를
보여주는가**다. |Δ| 가 100도에 가까우면 한쪽은 반드시 직선에 붙어 각으로 읽히지
않는다.

- **반려 카드(cand01E)**: user 패널 178.9도 = **직선 하나**, ref 패널 64.5도 =
  뚜렷한 V. 두 패널이 다른 종류의 마크 → belle 의 "한쪽 각도가 애매하다".
- ★**반례로 확인**: "한쪽이 직선이다"만으로는 억제 근거가 못 된다. 피디쉐입
  오른팔꿈치는 user 177.4도인데 ref 도 167.0도라 **양쪽이 함께 직선**이고 belle 이
  통과시켰다(재료 5번). 갈리는 것은 **불일치**뿐이다.
