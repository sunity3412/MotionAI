# quick-260818-c0u — Pod 헬스 감시

## 왜

`.planning/CONTINUE-2026-08-18.md` §1: Pod 이 08-16·08-17 이틀 연속 죽었고 **두 번 다 우연히
발견**했다. 감시 없음 · 실패 조용함 · 폴백 없음(`backend/functions/pipeline/app.py`
`_delegate_to_runpod` 는 위임 실패 시 폴백 없이 `fail_analysis`). Pod 이 죽은 채로 사용자가
올리면 분석이 전량 실패한다.

DLQ 알람으로는 못 잡는다 — 파이프라인이 예외를 잡아 `fail_analysis` 로 정상 종료하므로
SQS 메시지는 DLQ 로 가지 않는다. 즉 **능동 헬스 프로브 말고는 신호가 없다.**

## 하지 않는 것

- **pilot SAM 스택 배포 금지.** `backend/template.yaml` 의 `RunpodAnalyzeUrl` 기본값이 빈
  문자열이고 `samconfig.toml` 의 parameter_overrides 에 그 값이 없다. 지금 `sam deploy` 하면
  운영 pipeline Lambda 의 `RUNPOD_ANALYZE_URL` 이 빈 문자열로 덮여 앱 분석이 전량 깨진다.
  그래서 감시는 **별도 스택**으로 간다.
- Pod 자동 재기동은 범위 밖(알림까지만).

## 작업

1. `backend/infra/podwatch.yaml` 작성
2. `backend/infra/README.md` 작성 (배포 커맨드 + 이메일 구독 확인 + Pod 교체 절차)
3. 실제 배포 후 프로브 1회 강제 실행으로 healthy=1 실측
