### 2. 카드 좌우 여백이 시안의 절반 — 카드가 44.9pt 넓다 (4개 탭 전부)

**관측** — 시안 카드 x 36.44~353.56pt (폭 317.12, 여백 9.34%), 구현 20.00~381.67pt (폭 361.67, 여백 4.98%). 피그마 노드 3개(254:680 / 254:1237 / 254:1480)가 전부 좌우 43.65px 대칭이고, 시안 PNG 행 스캔도 x=44/424 로 일치. 구현은 PIL 행 스캔·ax 프레임(`Button x:20 width:362`) 두 계기가 일치. 기기 폭 차(390→402)로 설명되는 몫은 한쪽 1.1pt 뿐이고, **남는 이탈이 한쪽 17.6pt** — BRIEF 허용치(가로 6pt)의 3배.

파생 효과: 사진이 시안 카드 폭의 76.2% → 구현 66.9%, 감점 행 초 칸이 화면에서 25.8pt 왼쪽으로 이동, 경고 본문이 시안과 다른 자리에서 끊긴다.

**원인** — `result.tsx` ScrollView contentContainer 가 전역 토큰 `spacing.screenX`(=20)를 쓴다. 시안 카드 여백 36.4pt 는 이 화면 전용 값이라 전역과 다른데, 재디자인 때 이 값만 가져오지 않았다. 컴포넌트 헤더 주석 3곳이 스스로 317.1pt 를 적어 두었으나 코드 어디에도 폭으로 들어가지 않는다.

**고칠 곳** — `app/src/app/analysis/result.tsx:2236` (`content.paddingHorizontal`), `app/src/theme/index.ts:23`

**처방** — 결과 화면 전용 `paddingHorizontal` 을 36.6pt(또는 카드 maxWidth 317.1 + 가운데 정렬)로 두고 전역 `screenX` 는 건드리지 않는다.

## 2. belle 판정 필요

시안과 구현이 다른데 어느 쪽이 맞는지 내가 정할 수 없는 것들.

**1. 페이지 배경 — 시안 #F6F6F6 vs 구현 #FFFFFF**
전체 히스토그램: 시안 #F6F6F6 비중 s1 22.4% / s2 21.1% / s3 36.7% / s4 21.3%. 구현 m1·m3·m4 에는 #F6F6F6 픽셀이 **0개**이고 #FFFFFF 가 48.6~65.0%. 세로 RLE 로도 시안 s3 는 249.5~870.6pt 전 구간 #F6F6F6, 구현은 243.3~873.0pt 전 구간 #FFFFFF.

연쇄: 이걸 흰색으로 두면 (a) 흰 카드가 면으로 안 읽히고, (b) 기준/종합 밴드가 시안에서는 안 보이던(#F6F6F6 vs #F4F4F4, 2단계) 회색 띠로 뜨고(#FFFFFF vs #F5F5F5, 10단계), (c) 항목 11(테두리 약화)의 영향이 특히 시안3에서 커진다. **한 번의 판정이 세 항목을 결정한다.**

**2. 옅은 회색 글자 3종 — 시안이 더 옅다 (되돌리면 접근성이 무너진다)**
- 요약 서브 '90점 이상이면…': 시안 **#D6D6D6** (해상도 무관 잉크피복면적 역산으로 213.3 확정) vs 구현 #ACACAC. 흰 배경 대비 **1.31:1** — WCAG 미달.

## 4. 결함 아님으로 걸러진 것 (참고)

다음 세션이 같은 것을 다시 "발견"하지 않도록 셋만 남긴다.

**1. "콘텐츠가 시안보다 27.8pt 아래로 내려갔다" — BRIEF 세로 보정식이 사면한 범위**

**2. 시안 PNG 로 아이콘·선 크기를 재면 안 된다 — AA 팽창이 실측을 뒤집는다**
교정포인트 행 화살표를 시안 PNG 로 재면 10.8×5.8pt 로 "구현(9.3×5.3)이 더 작다" 는 결론이 나오는데, 피그마 벡터(254:1285)는 **9.80×4.46pt** 이라 실제로는 구현이 0.9pt 더 크다. 같은 함정이 탭 밑줄에도 있었다 — 행 수(3px)를 그대로 pt 환산하면 2.5pt 지만 알파 적분으로 재면 **1.36pt** 이고, 구현 1.67pt 가 오히려 0.31pt 더 두껍다. **작은 도형은 피그마 벡터 bbox 또는 알파 적분으로만 재라.**

**3. "모달 카드 padding 이 6pt 넓어 본문 줄 수가 늘어난다" — 인과가 틀렸다**
