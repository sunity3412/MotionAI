# 대조 브리프 — 피그마 시안 ↔ 구현 (Sunity AI Coach 분석 결과 화면)

## 목적
피그마 `분석 보고서 디자인 업데이트` 시안 5장과 실제 앱 구현을 **한 항목씩** 맞춰
어긋난 곳을 찾는다. 09-09 세션은 "구조가 같다"까지만 봤고 치수·간격·글자·색을
맞춰본 적이 없다. 그 대조가 지금 할 일이다.

## 좌표 규약 (반드시 이해할 것)
- 시안 원본 PNG: 폭 468px = 화면 폭 **467.206 디자인단위**.
  구현은 이것을 **390pt 폭 디자인**으로 본다: `K = 390/467.206 = 0.83475`.
  즉 `시안px * 0.83475 = pt`.
- 시안 전체 화면 높이 1049px * K = **875.7pt**. 실기기(iPhone 16 Pro) 높이 874pt.
  → **세로 좌표는 사실상 1:1로 비교 가능하다.**
- 구현 스크린샷: 1206x2622px = **402pt x 874pt @3x**. `impl px / 3 = pt`.
- 가로는 시안 390pt vs 기기 402pt (12pt 넓다). 헤더/딸림 그래픽은 `s = width/390`
  으로 **비례 확대**되고, 카드류는 **고정 pt**다. 그래서 가로 6pt 정도의 좌우 여백
  차이는 설계상 정상이다. 그 이상 벌어지면 보고할 것.
- 대조 시트(`pair/*.png`)는 둘을 **같은 pt 배율(3px/pt)**로 맞춰 나란히 놓고
  50pt 간격 가로 격자를 그어 둔 것이다. 격자 숫자가 화면 상단 기준 pt다.

## 데이터 차이는 결함이 아니다
시안의 숫자·문구는 임의값이다(belle "화면만 하면돼 임의 숫자임").
구현은 실제 분석 문서를 그린다. **점수·감점 수치·문장 내용이 다른 것은 정상.**
단, 같은 doc 을 쓰도록 감점 5개짜리 문서로 맞춰 두었다 — 시안도 5개다.
행 **개수**, 칩 **개수**, 블록 **유무**는 비교 대상이다.

## 무엇을 찾나 (우선순위)
1. **누락/추가** — 시안에 있는데 구현에 없는 요소, 그 반대.
2. **세로 위치·크기** — 50pt 격자로 읽어 5pt 이상 어긋나면 수치와 함께 보고.
3. **조판 사고** — 한국어 어절이 줄바꿈으로 쪼개짐, 글자 잘림, 겹침, 2줄 될 것이 3줄.
4. **정렬** — 가운데/왼쪽 정렬이 시안과 다른 것.
5. **색·굵기·모서리** — 눈에 띄게 다른 것 (단 빨강 #FF4B33 은 정상).
6. **상태** — 시안이 그린 기본 상태(예: 펼쳐진 행)와 구현의 기본 상태가 다른가.

## 보고 규칙
- 관측을 먼저 쓴다. "시안 y=416pt, 구현 y=446pt, 30pt 아래" 처럼 **숫자로**.
- 추측·진단은 관측과 분리해서 쓴다.
- 위 '일부러 다르게 한 것'과 데이터 차이에 해당하면 **보고하지 않는다.**
- 확신이 없으면 `confidence: low` 로 표시하고 무엇을 더 재야 하는지 쓴다.

## ★ 세로 좌표 보정 — 반드시 적용할 것 (2026-09-09 세션 중 확정)

**시안에는 상태바가 그려져 있지 않다.** 구현은 이를 이렇게 푼다
(`app/src/components/result/ResultHeader.tsx:88-104`, 주석에 근거 전부):
- **곡선(빨강 헤더)** 은 기기 화면 최상단(y=0)에 고정 — 시안과 비율이 1:1.
- **글자·탭·그 아래 콘텐츠**만 상태바를 피해 `useResultTopDelta()` 만큼 내린다.

iPhone 16 Pro 실측:
```
insets.top = 59, statusGap = 4, titleTop = 39.7, s = 402/390 = 1.03077
topDelta = max(0, 59 + 4 - 39.7*1.03077) = 22.08pt
```

따라서:
- **헤더 곡선**을 잴 때는 보정 없이 시안과 직접 비교하되, 가로 확대 `s = 1.03077`
  을 곱해서 본다. (실측 확인: 시안 빨강 좌측끝 235.4pt x 1.0308 = 242.7pt,
  구현 238.7~242.0pt → 일치.)
- **타이틀·탭·콘텐츠**를 잴 때는 `구현 y - 22.08pt` 를 시안 y 와 비교하라.
  그리고 세로 방향도 `s` 만큼 커진다: 시안 y x 1.03077 + 22.08 = 구현 예상 y.

즉 예상식:
```
구현_예상_y = 시안_pt * 1.03077 + 22.08      (타이틀/탭/콘텐츠)
구현_예상_y = 시안_pt * 1.03077              (헤더 곡선)
```
**이 식으로 설명되는 차이는 결함이 아니다. 보고하지 마라.**
이 식에서 5pt 넘게 벗어나는 것만 보고하라.

검증 예 (보완운동 탭 첫 카드):
```
시안 153.6pt -> 예상 153.6*1.03077 + 22.08 = 180.4pt, 구현 실측 180.0pt -> 정상
```
