# 분석 결과 화면 — 시안 대조 수리

## 판정 (belle 2026-09-09)

> "볼드체랑 이런거 미세한건 시각적으로 좋게 조절하면서 시안대로 최대한 맞춰줘.
> 시안을 중심으로 WCAG 최대한 지켜줘"

해석 — 이 계획 전체를 지배하는 규칙:

1. **기본은 시안이다.** 대조에서 어긋난 것은 시안 값으로 되돌린다.
2. **WCAG AA(4.5:1, 비텍스트 3:1)를 어기는 시안 값은 따르지 않는다.**
   색상(hue)은 시안 그대로 두고 **명도만 낮춰** AA 를 만족하는 가장 밝은 값을 쓴다.
   아래 §2 표가 그 계산 결과다(계산식: WCAG 2.1 상대휘도).
3. **브랜드 `#FF4B33` 은 건드리지 않는다** (CLAUDE.md §4 절대 금지).
   브랜드에서 비롯된 대비 미달 2건은 고치지 않고 belle 에게 보고한다(§7).
4. 굵기·1pt 단위 같은 미세한 것은 시각 판단으로 조정한다.

## 척도

시안 화면 = **467.206 디자인단위 폭 × 1048.2 높이** = **390 × 875.7pt**, `K = 0.83475`.
헤더·점수원은 `s = 기기폭/390` 로 비례 확대된다. 카드류는 고정 pt.

### 요약 카드 내부 — 라인박스 보정

시안 치수는 벡터 **잉크** 상단인데 구현은 같은 값을 `<Text>` **라인박스** 상단(marginTop)으로
썼다. 그래서 헤드라인 +2.9 / 서브 +5.7 / 칩 +6.1 / 경고박스 +6.0pt 씩 아래로 밀렸다.
`D.headlineTop` `subTop` `chipsTop` `warnTop` 에서 **(해당 fontSize × 0.15)** 를 빼거나
라인박스 보정을 한 번 적용한다.

### 모달 세로 좌표

`ResultPointModal` 은 세로 좌표 9개가 주석에만 있고 코드는 하드코딩 `marginTop` 이다.
다른 result 컴포넌트처럼 `const D = {...}` 실측 테이블을 만들고 marginTop 을 그 차분으로 계산한다.
시안 앵커(화면 top 기준 pt): 페이저행 171.27 · 칩 205.98 · 헤드라인 263.69 · 서브 333.16 ·
사진 376.22 · 박스1 558.04 · 박스2 662.02 · CTA 779.64.

### 모달 시트가 탭을 덮는 문제

`SHEET_TOP_RATIO = 115.9 / 844` → 시트 윗변 120.0pt. 그런데 탭 라벨은 `useResultTopDelta()`
때문에 117.7~133.4pt 에 있어 **시트가 탭을 가린다.** 시안은 탭 아래 10.8pt 를 띄운다.
분모 844 도 틀렸다(시안 프레임 높이는 875.0pt).
→ 시트 top 을 **`useResultTopDelta() + 115.9 * s`** 로 바꾼다(다른 요소와 같은 규약).

## 7. 고치지 않고 belle 에게 보고할 것

브랜드 `#FF4B33` 을 바꿔야만 해결되는 대비 미달 2건. CLAUDE.md §4 가 브랜드 변경을 금지하므로
손대지 않는다.

| 항목 | 대비 | 필요 | 해결하려면 |
|---|---|---|---|
| 감점 칩 글자 `#FF4B33` on `#FCEFED` | 2.97:1 | 4.5:1 | 칩 글자를 `#C23A22` 같은 더 어두운 빨강으로 (브랜드 이탈) |
| 흰 글자 on 브랜드 빨강 (일반 크기) | 3.33:1 | 4.5:1 | 헤더 빨강을 어둡게 (브랜드 변경) — 탭은 18pt 로 우회했다 |
