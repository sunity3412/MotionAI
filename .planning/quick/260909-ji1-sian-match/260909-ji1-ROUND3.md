# 3차 — 합성 경로 실물 확인

## belle 이 짚은 것

> "항목에 시간 표기 된거랑 실제 시간이랑 차이 보여?"

행은 `8.1s`(원본 영상), 재생기는 `0:48.9`(합성본). 합성본은 감점마다 정지가
끼어 원본보다 길다 — 같은 순간인데 두 숫자가 서로를 부정했다.

**고침**: 그 화면에서는 **재생기와 같은 시계**를 쓴다. 플레이어가
`outSecOf(recordId)` 를 render prop 으로 넘기고 목록이 그 초를 찍는다.
시계를 바꿨으면 순서도 그 시계를 따라야 해서 **정렬도 바꿨다** —
원본 4.5s 감점이 합성본에서는 1:07.6 로 맨 뒤에 온다.

## 배포한 것 (앱 밖)

## 함정 (다음 세션이 밟지 말 것)

★ **복사한 doc 은 합성 경로를 못 탄다.** `renderedCompare.key` 가 원본 uid 를
가리키면 playback-url 이 canonical key 와 exact 비교에서 떨어져 **404** →
앱이 조용히 듀얼 플레이어로 강등된다. 시뮬에서 "왜 시안대로 안 나오지" 의
정체가 이것이었다 — 코드가 아니라 **데이터**. doc 을 옮길 때는 키 접두를
재작성하고 S3 객체도 같이 옮겨야 한다.

★ **`/upload-url` 은 Firestore doc 을 만들지 않는다.** doc 은 앱이
(`analysis/loading.tsx:160`) 만든다. 스크립트로 E2E 를 돌리면 `mode` 가 없어
`compare_render 스킵 (mode1+기준 영상 경로 아님) mode=None` 이 된다.

★ **시뮬 사진첩의 영상은 pdshape 가 아니다.** 둘 다 `not_pole_motion`
(angle=0). 승인 픽스처는 `belle_pdshape.mp4` — S3 `uploads/` 에만 있다.

★ **pod 에서 `pkill -f "uvicorn...server:app"` 은 자기 자신을 죽인다** (ssh
명령 문자열이 그 패턴을 포함). PID 로 죽이거나 `uvi[c]orn` 처럼 쪼갤 것.
