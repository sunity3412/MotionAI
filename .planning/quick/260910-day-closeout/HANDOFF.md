### 5-1. 내 빌드가 낡아서 멀쩡한 코드를 고치러 갔다

"못 봤어요" 줄이 시뮬에 안 나와서 **앱 정규화가 필드를 버린다**고 진단하고 수리를 지시했다.
실행자가 반증했다 — `normalize()` 는 화이트리스트 pick 이 아니라 **overlay**(`userAnalyses.ts:476`
`let result = raw.result` 로 시작) 라서 목록에 없는 키도 통과한다. HEAD 이전 코드로 실측해 `hidden=1`.

진짜 원인: **설치된 번들이 13:00, 그 줄을 넣은 커밋이 18:25.** `expo run:ios` 가 JS 번들을
캐시해 옛 판을 재설치했다.

→ **시뮬에서 "안 보인다"를 만나면 첫 명령은 이것이다:**
```
stat -f "%Sm" "$(xcrun simctl get_app_container <UDID> com.sunity.aicoach)/main.jsbundle"
```
그 시각이 해당 커밋보다 앞이면 거기서 끝. 코드는 무죄다.
강제 재번들 = DerivedData 의 `main.jsbundle` 삭제 후 재빌드.
메모리 [[verify-the-bundle-is-fresh-before-blaming-code]].

### 5-2. 이름을 바꾸니 기존 분석의 모달이 전부 빈 화면이 됐다

운동 이름을 영문 → 한글로 바꾼 직후, 모달이 **"짚인 보완 부위가 없어요"** 가 됐다.
원인: `exerciseSections.ts` 가 섹션을 **운동 이름 문자열**로 골랐다 — 저장 doc 의 이름(그때
스냅샷) 과 **지금 라이브러리**의 이름을 비교. 백엔드 dedup 키도 name 이었고, **카드 배지 조회도
같은 결함**이었다(옛 doc 의 배지가 통째로 사라지고 있었다).

**그대로 나갔으면 모든 사용자의 과거 분석이 깨졌다.**

수리: 불변 `id` 도입, 이름은 표시 전용, 옛 doc 용 **레거시 폴백을 동결 모듈**

메모리 [[display-string-is-not-a-join-key]].
