## 확정된 표기 규칙 (belle 승인)

| 언제 | 표기 | 근거 |
|---|---|---|
| 오늘 | `오늘 10:24` | 하루에 여러 번 찍는다. 시각이 구분자 — 기록 탭이 같은 이유로 시:분을 넣었다(belle 08-31, quick-260831-lcc) |
| 어제 | `어제 10:24` | 같은 날 여러 건 문제는 어제에도 동일 |
| 2~6일 전 | `3일 전` | belle 제안 그대로. 연습 앱에서는 "며칠 만이냐"가 의미 |
| 7일 이상 | `9월 3일` | 날짜로 |

**belle 안에서 내가 바꾼 것 2개 (belle 이 승인함)**
- 경계를 3일 → **7일**. 애플은 사진·메시지에서 "이번 주 안"까지 상대 표기를 쓴다.
  3일에서 끊으면 "4일 전"이 갑자기 날짜가 돼 뚝 끊긴다.
- **어제에도 시각**을 붙임.

**언어**: 이 자리는 시안이 영문 `Today` 로 고정했고 belle 이 "완전 동일하게" 라고 했었다
(`result.tsx:261-262` 주석). 그러나 belle 이 2026-09-10 에 **한글 날짜 표기를 명시적으로 요청**했으므로
그 지시가 우선한다. 주석의 근거를 새 지시로 갱신할 것 — 지우지 말고 이력이 남게 고쳐 쓸 것.

## 경계 정의 (구현자가 임의로 정하지 말 것)

- "오늘/어제"는 **경과 시간이 아니라 달력 날짜** 기준이다. 로컬 타임존의 자정 기준으로 가른다.
  (23:50 에 찍고 00:10 에 열면 "어제" 가 맞다. 20분 차이지만 날짜가 바뀌었다.)
- 일수 차이 = `floor((오늘 자정 − 그날 자정) / 86400000)`.
- 시각은 24시간제 `H:MM` 이 아니라 **`HH:MM` 2자리 고정** (기록 탭 `history.tsx:20` 과 동일 형식).
- 미래 시각(기기 시계 오차로 createdAt 이 미래)이면 **"오늘"** 로 접는다. "-1일 전" 금지.
- `createdAt` 이 없거나 유한수가 아니면 **빈 문자열**을 반환하고, 화면은 그 줄을 그리지 않는다.
  (`ResultScoreDial` 의 `label` 은 필수 prop 이므로 빈 문자열 처리를 컴포넌트가 견디는지 확인할 것.)

```ts
/**
 * 분석 시각 한 줄 표기. `nowMs` 를 인자로 받는다 — Date.now() 를 내부에서 부르면
 * 테스트가 시계에 의존하게 된다.
 */
export function formatAnalysisMoment(createdAtMs: number, nowMs: number): string;
```

규칙은 위 표 그대로. 반환 예: `'오늘 10:24'` · `'어제 23:50'` · `'3일 전'` · `'9월 3일'` · `''`.

**테스트 축 (7개)**
1. 같은 날 → `오늘 HH:MM`, 시각이 2자리로 채워짐 (`09:05`).
2. **자정을 사이에 둔 20분 차이 → `어제`** (경과시간 아닌 달력 기준임을 못박는 축).
3. 2일 전 → `2일 전`. 6일 전 → `6일 전`.
4. **7일 전 → `M월 D일`** (경계 축). 6↔7 이 갈리는지.
5. 미래 시각 → `오늘`.
6. `NaN` / `undefined` 취급값 / 음수 → `''`.
7. 연말 경계 (12월 28일 분석을 1월 3일에 열기) → 일수 계산이 연도를 넘어 맞는지.

**verify**: `cd app && node --test $(find src -path '*__tests__*' -name '*.test.ts')`
기존 전건 통과 + 신규 축 통과. (**함정**: `node --test` 에 디렉터리를 넘기면 실패한다 — 파일 목록/글롭만.
대상 모듈은 `.ts` 확장자 명시 import.)
