## 1. 원인 — 역립은 학습 분포 밖이고, crop 은 축정렬 고정

| 사실 | 근거 |
|---|---|
| crop 회전이 0 으로 하드코딩 | `rtmlib/tools/pose_estimation/pre_processings.py:159` `rot = 0` |
| RTMW-x 학습 회전 증강 ±90°, flip 은 horizontal 뿐 | RTMW 학습 config (`rotate_factor=90`, truncnorm [-1,1]) |
| → 180°(역립)는 합성으로도 도달 불가 = zero-shot | 위 둘의 논리적 귀결 |

## 2. 현행 vs 180° 회전 — belle 영상 (`user.mp4`, pdshape, 181프레임 stride 3)

| 변형 | 평균 conf | 붕괴 프레임 | 뼈위반 p90 |
|---|---|---|---|
| `prod_orig` 현행 1-pass | 0.5669 | **9** | 2.108 |
| `prod_rot` 프레임 180° 회전 (검출+포즈) | **0.7065** | **0** | **0.776** |
| `box_orig` 같은 bbox 강제, crop rot=0 | 0.5021 | 9 | 2.340 |
| `box_rot` 같은 bbox 강제, crop rot=180 | 0.5193 | **0** | 2.163 |

**분해**: 붕괴 소멸(9→0)은 **포즈 모델** 몫. conf +0.14 와 뼈위반 −63% 는
**검출기** 몫. → crop affine 만 돌리면 절반만 얻는다. **검출 전에 프레임을 돌려야** 한다.

- 붕괴 판정 = 17개 body keypoint 중 고유 좌표 ≤ 8 (여러 관절이 한 점으로 뭉갬)
- 뼈위반 = 8개 뼈의 (길이/torso)가 클립 중앙값에서 벗어난 |log 비율| p90 의 평균
- `box_*` 의 미검출 17프레임은 `wb.det_model` 직접 호출 시 빈 결과 → 0 이 평균을 끌어내린다
  (`prod_*` 는 rtmlib 가 전체 프레임 bbox 로 폴백하므로 0건)
