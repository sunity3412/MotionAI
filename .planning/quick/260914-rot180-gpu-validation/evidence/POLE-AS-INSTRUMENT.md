## 0. 결론 두 줄

1. **기존 `HoughPoleDetector` 는 이 목적에 못 쓴다.** `source='detected'` 를 보고하면서
   실제로는 카메라 롤을 못 잰다 — **`detected` 는 폴을 찾았다는 증거가 아니다.**
2. **prior 를 빼고 '평행 엣지쌍'으로 찾으면 롤이 잡힌다(평균 오차 ≈0.7°).**
   단 **폭(=미터 스케일)은 아직 못 쓴다** — 같은 영상 안에서 ±25% 흔들린다.

## 1. 기존 검출기는 롤을 못 잰다

`analysis/pole/detector.py` 는 `VERTICAL_TOLERANCE_DEG = 5.0` 으로 **수직 ±5° 안의 선만**
받는다(D-09). 그래서 카메라가 그 이상 돌면 **진짜 폴이 필터에서 탈락**하고, 남은 배경
세로 엣지(커튼 주름·창틀)를 잡은 채 `detected` 를 보고한다.

입력 프레임을 일부러 기울여 확인:

| 가한 롤 | 검출 기울기 | 따라온 양 | source |
|---|---|---|---|
| 0° | 1.70° | — | detected |
| −3° | 1.99° | **+0.29°** | detected |
| −6° | 3.89° | **+2.19°** | detected |
| +3° | 3.21° | +1.52° | detected |
| +6° | 3.55° | +1.85° | detected |
| +10° | 2.75° | **+1.05°** | detected |

**부호조차 안 맞는다** — −3° 와 +3° 가 둘 다 양수로 이동했다. 10° 를 줬는데 1° 움직인다.

곁증거: 서로 다른 두 영상에서 축이 **소수 4자리까지 동일**했다
(`0.029648` vs `0.029665`). 영상을 재는 게 아니라 같은 prior 로 수렴한다는 뜻이다.

★ **`poleAxis` 는 분석 문서 어디에도 저장되지 않는다.** 그래서 이 결함이 프로덕션에서
한 번도 드러난 적이 없다. 계기를 쓰려면 먼저 **산출을 doc 에 남겨야** 한다.

## 2. prior 없이 찾으면 잡힌다 — `evidence/pole_probe.py`

방법을 세 군데 바꿨다:

1. **시간축 median 배경** — 사람은 움직이고 폴은 고정이라 중앙값이 사람을 지운다
2. **각도 prior 제거** — 모든 방향의 긴 직선을 다 모은다
3. **쌍(pair)으로 판정** — 폴은 *평행한 두 실루엣 엣지*다. 배경 엣지는 짝이 없다.
   간격이 폴 굵기 범위인 평행쌍만 남기면 **수직 가정 없이** 폴이 걸러진다

| 가한 롤 | user.mp4 | ref.mp4 |
|---|---|---|
| −10° | **−10.33°** | **−9.90°** |
| −6° | −6.22° | −6.48° |
| −3° | −4.86° | −3.35° |
| +3° | +2.46° | +3.04° |
| +6° | +5.61° | +5.45° |
| +10° | +9.19° | +8.46° |

**평균 절대오차 ≈ 0.7°** (±10° 구간). 계기로 쓸 만하다.

두 영상 모두 기준 기울기가 **+2.3~2.5°** 로 일치한다 — 이 촬영들에 실제로 그만큼의
카메라 롤이 있거나 폴이 그만큼 안 연직이라는 뜻이다. **어느 쪽인지는 아직 모른다**(§4).

## 3. 폭(미터 스케일)은 아직 못 쓴다

| | 0° 기준 | 회전 시 범위 | 흔들림 |
|---|---|---|---|
| user.mp4 | 22.76px | 16.85 ~ 22.04 | **±25%** |
| ref.mp4 | 29.09px | 16.61 ~ 21.38 | **±30%** |

지름 45mm 가정 시 px-per-mm 가 user 0.506 / ref 0.647 로 나오는데, **두 영상이 다른
것 자체는 정상**이다(카메라 거리가 다르다). 문제는 **같은 영상 안에서 회전만 줘도
±25% 흔들린다**는 것 — 미터 단위로 쓸 정밀도가 아니다.

## 4. 다음에 확인해야 할 것 (전부 미검증)

- **실제 폴 지름을 모른다.** 40 / 45 / 50mm 중 무엇인지 belle 확인 필요.
  지름을 몰라도 **축·롤은 나온다** — 스케일만 막힌다.
- **폴이 연직이라는 보장이 없다.** 기준선 +2.4° 가 카메라 롤인지 폴 기울기인지
  가르려면 같은 스튜디오의 다른 촬영각 영상이 필요하다.
- **폭 추정 안정화** — 지금은 median 배경 한 장에서 재지만, 프레임별로 재서
  분포를 보고 강건 추정(RANSAC/trimmed mean)을 해야 한다.
- **깊이 한계는 그대로다.** px-per-mm 는 **폴이 있는 깊이의 평면에서만** 유효하다.
  폴보다 앞/뒤의 사지는 다른 배율이다 — 이 계기는 깊이를 주지 않는다.

## 5. 롤을 재면 무엇이 좋아지나 (조사 진행 중 · 잠정)

★ **주의**: 평면 회전은 **두 사지 사이의 각도를 바꾸지 않는다.** 그러므로 롤 보정이
`angle_vs_reference` 감점을 고치지는 **않는다.** 값어치가 있는 곳은 **세계 수직과
비교하는 양**뿐이다 — 즉 지금 z 가 전부 0 이라 상수 0.0 으로 죽어 있는
`axisMetrics`(몸통 기울기) 계열이다. 그 범위를 정확히 재는 것이 조사 중이다.
