# 기준 11편 회전 드리프트 전수 측정

## 왜

09-14 인계서(`.planning/quick/260914-rot180-gpu-validation/HANDOFF.md`) §6 이
"내가 먼저 할 것 (판정 불필요)" 1번으로 배정한 작업이다. belle 판정 1번
("회전 + 기준 11편 재추출을 한 묶음으로")의 근거가 **pdshape 1편**뿐이었다.

## 무엇을

1. 기준 11편을 Firestore 에서 **1회** 읽어 로컬로 (에이전트별 재스캔 금지 — 09-14 함정 1)
2. GPU 없이 잴 수 있는지 먼저 시도하고, 못 잰다는 것을 **증명**한 뒤에 Pod 을 띄운다
3. Pod 에서 11편을 `ROT180_INVERSION_ENABLED={0,1}` 두 벌로 재추출
4. pdshape 을 대조군으로 09-14 GPU 산출과 대조해 **계기를 먼저 검증**
5. 저장본 vs OFF / 저장본 vs ON / OFF vs ON 3종 비교를 전수로 산출

## 하지 않는 것

- 운영 플래그 변경 (`ROT180_INVERSION_ENABLED` 는 0 유지)
- 기준 재추출값의 Firestore 반영 (belle 판정 1번 대기)
- 감점 상한 재논의 (2026-07-24 확정, 인계서 §6 ★)
