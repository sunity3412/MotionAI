### ① 정렬 신뢰도를 정하는 축이 틀렸다

```
distance = 누적비용/(n+m),  단계비용 = ||학생 각도벡터 − 기준 각도벡터||
         = 학생과 프로의 평균 각도 차이(도)      ← 앱이 보여주려는 바로 그것
```

| 실측 (라이브 39건) | |
|---|---|
| 임계(`DISTANCE_T2`=25) 아래 | **0 / 39** — 통과 이력 0% |
| distance ↔ 종합점수 | **r = −0.53** |
| distance ↔ angle점수 | **r = −0.58** |
| 임계 출처 | `vision_veto._ALIGN_GLOBAL_T2` **값 복제** (다른 판정용) |

**못하는 학생일수록 정렬을 못 믿고, 못 믿으니 도움을 덜 받는다.** 코칭 앱에서 거꾸로다.
인과: `0/39 저신뢰 → tier=trim_only → 앵커 곡선 폐기 → warp 가 항등 → 짝이 시간정렬 없이 뽑힌다`

★ **임계만 올리는 수리는 커브핏이다.** 고칠 것은 **축** — 정렬 신뢰도는 "학생이 얼마나
다른가"와 **무관한 양**으로 재야 한다(경로 단조성·구간 기울기 클램프 위반·앵커 간격 일관성).

   현행 운영 영향 0(`start_server.sh` 가 `=1`). `/health` 정리는 계약 변경이라 별건.
