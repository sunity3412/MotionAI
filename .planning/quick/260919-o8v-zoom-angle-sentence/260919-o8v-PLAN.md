# 기계 눈이 억제한 패널에서 각도 표시를 살린다

**이번 단위는 지우개의 범위를 줄이는 일이다.** 게이트 판정은 그대로 두고
(`card_gates.py` 무접촉), 게이트가 "이 패널에서 부위를 못 찾겠다"고 말했을 때
**무엇을 지울지**만 바꾼다. 사진 장수·크롭·프레임 선정·채점 경로 전부 무접촉.

## 왜 (belle 2026-09-18 승인 — 재질문 금지)

belle 결정 3줄:

1. **사진은 9/03 규칙대로 전부 내보낸다.** 9/06 의 "게이트 확인분만 내보낸다"(사진 삭제)는 기각.
   어떤 게이트도 사진을 없앨 권한이 없다.
2. **게이트가 부위를 확인 못 해 표시가 생략된 자리에는 각도 표시를 놓는다.**
   9/06 원문 "사진 **대신** 각도"의 **"대신"을 "함께"로** 바꾼 것.
3. **"확인 안 됨" 류 문구·배지·아이콘은 쓰지 않는다** — 우리 불확실성을 수강생에게
   방송해 신뢰를 깎는다.

승인 근거 실측 3개: 사진이 0장 되는 동작은 없다 / 게이트 확인 27:9 패널 /
게이트 통과 안쪽에도 불일치 3건(게이트는 불일치를 없애지 못하고 줄일 뿐).

방향이 뒤집힌 지점을 명시해 둔다 — 종전의 두려움은 **fail-open**(틀린 표식을 살림)이었고,
09-18 판정 이후 먼저 볼 것은 **false-suppress**(맞는 표식을 지움)다
([[my-tight-crop-eye-is-unreliable-twice-wrong]]). 좁은 크롭에서 표식 위치를 사람 아닌
기계 눈이 판정하면 2연속으로 틀렸다. 그 눈에게 "각도까지 지울" 권한을 준 것이 현행이다.

## ★ 코드 실측이 과제를 좁힌다 — 재조사 금지

아래는 코드에서 직접 확인한 사실이다. 그대로 쓴다.

### 1. 각도와 원은 이미 배타적이다

`fault_zoom.py:3849-3857` (학생) / `:3891-3897` (기준):

```
u_drew_circle = False
if u_drew_legs or u_drew_angle:
    u_crop = _mark(u_img, circle=False, anchor_px=None)   # 원 안 그림
else:
    u_drew_circle = u_kind == "valid"
    u_crop = _mark(u_img, circle=u_drew_circle, anchor_px=u_anchor)
```

기준 측 원도 `if unit.criterion is not None and not r_drew_legs and not u_drew_angle:`
안에서만 그려진다. 화살표(`_draw_target_arrow`)도 `not u_drew_legs and not u_drew_angle`
분기 안에 있다.

→ **한 패널에 각도와 원(·화살표)이 동시에 존재할 수 없다.**
→ belle 규칙 2는 실제로 **"기계 눈이 억제할 때 각도까지 지우지 마라"** 로 좁혀진다.
→ 각도를 그린 패널에는 **지울 원이 애초에 없다** = 되돌릴 대상이 0이다.

### 2. 지금은 억제가 전부를 지운다 (여기가 고칠 자리)

`fault_zoom.py:3919-3924` (주석 포함 3915-3930):

```
if "user" in _supp:
    u_crop = _u_plain.copy()
    u_drew_legs = u_drew_angle = u_drew_circle = False
if "ref" in _supp:
    r_img = _r_plain.copy()
    r_drew_legs = r_drew_angle = r_drew_circle = False
```

`_u_plain`/`_r_plain` 은 **어떤 드로잉보다 먼저** 뜬 스냅샷(`:3617-3618`)이라,
되돌리면 다리 사이각·각도·원이 **전부** 사라진다.

### 3. 드로잉 순서

`:3706` 주석 명시 — ① 다리 사이각 → ② 각도 베이크 → ③ 원 마커(폴백).
**원 직전 시점의 캔버스 = "각도까지만 그려진 판"** 이고, 사실 1 때문에 그 판은
**억제 시점의 판과 같다**(각도를 그렸다면 그 뒤로 아무것도 안 그려졌으므로).
→ 새 스냅샷을 뜰 필요가 없다. 되돌리기를 **건너뛰기만** 하면 된다.

### 4. 억제 사유 두 가지 — 결과가 다르다 (섞지 말 것)

| 표시 생략 사유 | 각도 가능? | 이번 범위 |
|---|---|---|
| **기계 눈(card_gates)이 부위 확인 실패** — `suppress_marks`/`anchor_check` | 가능 (좌표는 있다) | ★ **여기만** |
| **좌표 저신뢰** (conf<0.5 → `angle_reason=user_crop_relaxed`/`ref_crop_relaxed`) | 불가 — 각도가 **애초에 안 그려졌다** | 무변경 (사진만 남는다) |

두 번째 칸은 문구로 풀 문제가 아니다. 근본 원인이 좌표 정확도다
([[keypoints-are-wrong-not-the-frame-choice]]). **건드리지 않는다.**

### 5. 인증 플래그는 그림과 어긋나면 안 된다

- `userMarked = bool(u_drew_legs or u_drew_angle or u_drew_circle)` (`:3997`)
- `refMarked = bool(r_drew_legs or r_drew_angle or r_drew_circle)` (`:3984`, criterion 카드만)
- 앱은 이 값만 보고 "왼쪽/오른쪽 사진에는 … 표시를 넣지 않았어요" 한 줄을 낸다
  (`DeductionDetailSheet.tsx:313,317`).

→ 각도를 살렸는데 플래그가 False 면 **사진에는 각도가 있는데 앱은 "표시 없음"이라 말한다.**
  각도를 남기는 경로에서는 `u_drew_angle`/`r_drew_angle` 을 **내리지 않는다**.

### 6. `pngPlain` 은 별개 산출물 — 무접촉

belle 09-09 '관절선 끄기'용으로 `_u_plain`/`_r_plain` 에서 따로 합성(`:3935-3941`).
이번 변경은 표시 판(`png`)만 건드린다.

### 7. 덤으로 닫히는 구멍 — 각도의 both-or-neither 가 억제로 깨지고 있었다

각도 베이크는 **양측 대칭**(`_u_ok and _r_ok` 일 때만 둘 다 그린다)이 불변식이다.
그런데 현행 억제는 한쪽만 걸리면 그 쪽 각도만 지운다 → **한 패널만 각도**가 남는다.
이번 변경은 그 비대칭을 구조적으로 없앤다(양측 모두 각도를 보존).
이는 [[refmarked-none-means-advisory-card]] 가 규명한 "한쪽만 동그라미"와는 **다른 건**이지만
같은 종류의 비대칭이다.
