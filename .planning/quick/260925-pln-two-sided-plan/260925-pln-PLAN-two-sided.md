| 정직한 실패 문구·재촬영 안내(§4·§5) | **SwingVision**(반면) | 오판·느린 업로드·버그 미수정으로 신뢰 붕괴 [노트북] | Pod 꺼짐을 "잠시 후 되겠지"로 덮으면 같은 길 | — |
| 3~6분 대기(§5) | **Speechling**(정면) · **SwingVision**(반면) | 사람 코치 24h 도 받아들여진다 [§0-2]. 업로드 느림은 불만 [노트북] | 문제는 시간이 아니라 **정직한 상태 표시** | 스피너 |

### B-3. 벤치가 없는 것 — 우리가 창조하는 자리

1. **공급자 개인 실행을 기준으로 자동 등록해 AI 가 채점** — 약 60곳 중 0 [§0-1]. 원리(올리면 자동으로 잰다)는 골프존·AI Golf School 에서, **기준만** 공급자 개인으로 바꾼 것. 비어 있는 이유가 "어렵기 때문"일 수 있다(§1-1 진단).
2. **2층 증명 = 본인 영상이 증명(자기 재현성)** — 증명 4종 어디에도 없다 [§0-5]. 원리는 수술 평가의 평가자 일치도 검증 [확인]에서.
3. **봉인 시험지** — 수술 평가의 전문가 대조 [확인]를 우리 운영 절차로 옮긴 것. 서비스 벤치 아님.
4. **기술 사전 / 기준 인스턴스 분리**(§7-2) — 소프트웨어 설계. 비유만: 악보(규칙) vs 레퍼런스 음원(실행) (Yousician [노트북]).
5. **공급자 바꾸기 "비교 불가" 표시** — 벤치 없음. 다른 곳은 기준이 일반이라 이 문제가 없다.
6. **링크 한 장 공급자 등록** — 폴댄스 7곳에 강사 셀프 등록 도구 언급 0 [확인, 소스 없음]. 크리에이터 콘솔의 최소판.

1·2·3 은 같은 뿌리다 — "개인 기준을 AI 가 잰다"는 자리가 비어 있고, 그 자리를 채우려면 **기준의 신뢰도를 먼저 재는 절차**가 붙어야 한다. 그래서 창조하는 것은 화면이 아니라 검증 절차다.

## 0. 한 줄 결론

공급자 한 사람의 실행 하나를 기준으로 AI 가 수요자 영상을 비교·교정하는 서비스는 스포츠·비스포츠 약 60곳 중 **0** 이다 [확인 §0-1]. 우리는 그 자리를 **앱 하나(수요자 모드 + 공급자 모드) + 학원 입구 + 정확도 운영**으로 채운다. 실증(2026-10 중순, 날짜 미정 [기억 pilot-postponed])은 그 끝 그림의 **첫 구간**이다 — 정은지 1명이 스스로 올린 영상이 사람 손 없이 기준이 되고, 수강생이 혼자 앱을 켜 점수를 확인한다(CLAUDE.md 파일럿 Step 2·3 그대로).

## 1. 끝 그림 — 완성도 높은 앱 + 그 미래를 만드는 생태계

### 1-1. 왜 이 자리가 비어 있나 (관측 → 진단 분리)

- **관측** [확인 §0-1, §D-B3]: AI 가 비교하는 곳(ELSA·BoldVoice·Yousician·골프존·Sportsbox·C-SATS·Yoodli)은 전부 **일반 기준**(원어민 모델·악보·엔진·루브릭)을 쓰고, 공급자 개인이 기준인 곳(Skillest·Onform·Trainera·폴댄스 6곳·링글·Preply·Speechling)은 전부 **사람이 본다**. 비율 약 40:60.
- **진단** [미확인]: "사람이 보는 코칭은 개인 기준, 자동 평가는 일반 기준"이라는 규칙은 **개인 기준을 AI 가 재는 것이 어렵기 때문**일 수 있다. 우리가 그 어려움을 겪고 있다는 것은 사실이다 — 같은 챔피언 영상이 실행마다 100점 미만이 나온 이력 [기억 champion-own-video-scores-under-100], GPU 종류에 따라 관절 각도가 바뀌는 관측 [기억 gpu-type-changes-pose-angles]. 그래서 끝 그림의 첫 번째 자산은 화면이 아니라 **재현성**이다(§1-5).

### 1-2. 우리 답의 모양 — "강사를 대체하는 AI" 가 아니라 "강사의 기준을 복제하는 AI"

강사가 AI 코치를 거부하는 이유 5 [확인 §0-7] 에 구조로 답한다.

| 강사 거부 이유 | 우리 구조의 답 |
|---|---|
| 맥락·개인 스타일 무시 | 기준이 **그 강사 본인의 실행**이다. 스타일이 곧 기준 |
| 저차원 지표와 품질의 단절 | 출력은 수치가 아니라 "왜 안 되는지 + 무엇이 필요한지"(CLAUDE.md Core Value) |
| 약점 위주 | 정타는 침묵(감점 0), 실수만 짚는다 — 09-25 벌림 규칙의 원칙 [기억 split-rule-final-phase-median] |
| 블랙박스 | 감점은 투명 합산, 밴드 없음 [기억 scoring-must-be-transparent-deduction-tally] |
| 감정 케어 불가 | 사람 강사가 남는다. AI 는 강사의 기준을 수강생이 혼자 연습할 때 **대신 봐 주는 눈**이다 |

현장 리서치 결론(CLAUDE.md): 일반적 답변이면 수강생이 이탈하고, 각도 수치만 보여주면 강사 철학과 충돌한다. 이 표가 그 둘을 피하는 방법이다.

### 1-3. 역할 4 — 누가 무엇을 주고 무엇을 얻나

| 역할 | 주는 것 | 얻는 것 | 끝 그림의 표면 |
|---|---|---|---|
| **수요자**(수강생·독학자) | 연습 영상, 구독료, (동의 시) 영상 학습 사용 | "내 강사 기준" 점수와 원인, 성장 기록 | 앱 수요자 모드(지금 앱) |
| **공급자**(선수·강사) | 동작별 실행 영상 1개(기준), 증명, 권리 동의 | 자기 기준으로 학생이 혼자 연습하는 도구, 학생 현황, 정산, 이름값 | 앱 공급자 모드(실증은 링크 한 장) |
| **학원** | 강사 등록 대행, 수강생 초대(학원 코드), 학원 요금 | 수강생 잔존, 강사 기준의 일관성, 수강생 현황 | 학원 콘솔(웹) |
| **플랫폼**(우리) | 분석 정확도, 심사·정산·권리 관리, 정확도 운영 | 수수료·구독·학원 요금, 봉인 시험지 재료(동의분만) | 운영 도구(지금은 스크립트) |

### 1-4. 돈의 흐름 (전부 초안 — 확정 숫자 없음)

- **수요자 → 플랫폼**: 구독. 기존 초안 = IA §6-1 Free / Basic / Pro 3단(금액은 IA 초안값, 확정 아님). 실증은 결제 없음(CLAUDE.md §2).
- **수요자 → 공급자**: 공급자의 동작 묶음(IA §6-3 "모션팩"이 이미 있다) 구매 → 플랫폼 수수료. 시장 최빈 구간 **10~20%** [확인 §0-4]. 인재·교육 마켓 평균 25.8~32.8% [확인 §0-4] 는 상한 참고.
- **학원 → 플랫폼**: 좌석 수 기반 학원 요금 [미정].
- **플랫폼 → 공급자**: 정산. 공급자 월정액은 **없음** — 코치 월정액은 Onform·Trainera·CoachNow(코치 자기 학생용 도구)만이 아니라 마켓형 Skillest 도 받는다(코치 $59/월 + 온라인 13%) [확인 §F-1]. 그래도 우리는 뺀다 — 공급자 1명(정은지)부터 시작하므로 진입 장벽이 0 이어야 한다(내 판단, Skillest 와 다른 점).
- **학원·강사가 데려온 수요자는 수수료를 낮게** — Lessonface 가 플랫폼 유입 15% / 강사 유치 4% 로 차등한다 [확인 §F-2]. 고리(§1-6)를 돈으로 인정하는 선례. 숫자는 미정(초안, belle 미승인).
- 피해야 할 것 [확인 §D-B4]: 하드웨어 의존(Mirror·Peloton), 정산 구조 급변(클래스101), 음원 저작권(1MILLION).

### 1-5. 권리의 흐름

- 영상물 저작권은 제작 주체 귀속이 원칙 [확인 §0-9] → **공급자 본인 촬영 = 공급자 소유**, 플랫폼은 **이용 허락**(분석 기준으로 사용 · 앱 내 재생 · 프레임 추출·표시 · 썸네일)을 받는다.
- 초상·성명 사용은 **서면 동의** [확인 §0-9] → 등록 폼의 동의문(§6).
- 학습 사용(플라이휠)은 **별도 체크, 기본 꺼짐**. 사람 영상은 동의 없이 학습 후보에 못 들어간다 [기억 human-videos-stay-out-of-manifest].
- 철회: 새 분석에 그 기준을 더 쓰지 않고 영상 재생을 막는다. 이미 끝난 수요자 분석 doc 의 기준 스냅샷(각도·이름)은 **수요자 기록**이라 남긴다(초안). 조인 키는 표시 문자열이 아니라 불변 id [기억 display-string-is-not-a-join-key].
- 기준 영상은 **무음**으로 받는다 — 음악·안무 라이선스(싱크·마스터) [확인 §B-3(2)] 를 처음부터 피한다.

### 1-6. 공급자가 늘수록 수요자가 좋아지는 고리

```
공급자 1명 ─ 동작 N개 ─→ 수요자가 "내 강사 기준" 점수 ─→ 혼자 연습이 된다 ─→ 잔존
      ▲                                                                  │
      │                                                                  ▼
  강사가 자기 동작을 올린다 ◀── 학원이 강사를 등록(학원 코드) ◀── 학원 도입
      │
      └─→ (동의분) 학생 영상 + 강사 정답 = 봉인 시험지 재료 ─→ 정확도 ─→ 신뢰 ─→ 도입
```

고리의 한계 두 줄(관측): 플라이휠이 학습하는 것은 **결함 짚는 눈**이지 관절 좌표가 아니다 [기억 flywheel-trains-the-eye-not-the-coordinates]. 재학습은 이번 파일럿에 안 닿는다 [기억 retraining-does-not-reach-this-pilot]. 그래서 고리의 첫 바퀴는 학습이 아니라 **봉인 시험지**(공급자 정답 + 학생 영상)로 돈다.

### 1-7. 끝 그림 앱의 표면 (요약)

- **수요자 모드**: 로그인 관문(소셜·회원가입·게스트) → 홈(내 공급자 + 동작 + 올리기 + 최근·성장) → 촬영/업로드 → 대기 → 결과(요약·동작비교·교정포인트·보완운동) → 기록·성장 → 마이(공급자 바꾸기·구독·동의 관리).
- **공급자 모드**: 진입(초대/자발) → 증명 3층 → 동작 등록(촬영/파일 · 선언 4개 · 동의 · 자동 등록 · 자기 재현성 확인) → 내 동작 관리(재촬영·교체·비활성) → 학생 현황 → 정산 → 권리 관리.
- **학원 콘솔(웹)**: 강사 등록 대행 · 학원 코드 · 수강생 현황(동의분) · 요금.
- **플랫폼 운영**: 심사 큐 · 정산 · 봉인 시험지 · GPU 한 종류 고정 · Pod 상시/자동 기동.

## 2. 전제

1. **기준 = 공급자 실행 하나.** 일반 기준(IPSF 평균·교과서)이 아니다. 그래서 점수는 "그 공급자와 얼마나 같은가"이고, 공급자를 바꾸면 점수는 **비교 불가**다(§5 "공급자 바꾸기").
2. **정확도 우선.** 트레이드오프가 생기면 정확도(CLAUDE.md Core Value). 새 동작이 자동 등록돼도 그 채점이 맞는지는 **봉인 시험지로만** 안다(§7-3).
3. **문서는 멀리, 코드는 단계.** 실증까지 코드는 분석만(belle 09-19), 기획은 끝 그림(belle 09-25). 둘은 충돌하지 않는다 — 이 구분은 내 해석.
4. 정은지 추가 영상이 오면 이 문서보다 **봉인 시험지 2회가 먼저**(`backend/scripts/sealed_test.py`, 서 있는 자세에서 시작 요청).

## 3. 시장조사 근거 5 (전부 §0 [확인])

1. **같은 구조 0.** 스포츠·비스포츠 약 60곳. AI 비교는 일반 기준, 개인 기준은 사람 [§0-1].
2. **가장 가까운 셋.** Skillest(양면 마켓 + 비동기 영상, 코치 마크업에 AI 뼈대) · 골프존 GDR AI(프로 영상 나란히 + 50자세, 무료) · Speechling(성우 시연 ↔ 학생 녹음 나란히, 사람 코치 24h). 공급자 앱 방향 = Trainera(코치 100% 수령) [§0-2].
3. **수수료 최빈 10~20%** [§0-4]. **공급자 증명 4종**(자격·심사·후기·무검증) [§0-5].
4. **강사 거부 이유 5 · 정확도 불만 4형**(너무 엄격·오판·블랙박스·진단 없는 숫자) [§0-7] — 우리 핵심 가치와 같은 결론.
5. **Peloton 은 "강사 먼저" 홈과 강사 브랜드화만** [§0-10]. 카메라 자세 피드백은 소스 없음.

폴댄스 온라인 7곳은 전부 일방향 VOD, AI 0, 학생 영상 피드백은 PDA Online 뿐 [§0-3] — 우리 종목 안에서도 자리는 비어 있다.

## 4. 공급자 여정 — 전 경우의 수

각 행은 **끝 그림 → 실증 기간** 두 층. 실증 공급자 = 정은지 1명(+ 학원 강사 몇, 미정).

| 상황 | 끝 그림 | 실증 기간 |
|---|---|---|
| 진입 — 초대 | 플랫폼/학원이 링크로 초대. 링크에 학원·역할이 실려 있다 | 정은지에게 링크 1장 |
| 진입 — 자발 | 앱 마이 → "내 동작을 기준으로 올리기" → 공급자 모드 신청 | 없음 |

## 6. 공급자 증명 3층 + 권리 동의

시장의 증명 4종(자격·심사·후기·무검증) [확인 §0-5] 중 우리에게만 있는 것이 **2층**이다.

1. **1층 서류(선택)** — 자격·경력. 프로필 뱃지로만 표시. 폴댄스는 자체 자격 과정 또는 챔피언 이름값 [확인 §0-5].
2. **2층 본인 실행 영상이 증명(필수)** — 올린 영상을 분석기가 잰다. 등록 시 자동으로 (a) 못 잰 부위 (b) 자기 기준 대비 재현성 점수 (c) 검출 품질을 돌려준다. 재현성이 낮으면 기준으로 못 쓴다 → 재촬영. **이것이 심사이자 품질 게이트**다(§7-3).
3. **3층 후기·추천(누적)** — Skillest 형 공개 후기 [확인 §0-5]. 실증에는 없음.

**권리 동의(폼 문안, 끝 그림 기준으로 지금 쓴다)**
- [필수] 초상·성명 사용 동의(앱 내 표시·재생) [확인 §0-9]
- [필수] 영상 이용 허락 — 분석 기준 사용 · 프레임 추출·표시 · 썸네일
- [필수] 무음 영상 확인(음악·안무 라이선스 회피)
- [선택, 기본 꺼짐] 학습 사용 동의
- 철회 절차 한 줄 + 철회 시 수요자 기록 스냅샷 유지 고지

실증 기간: 정은지 1명. 동의는 링크 페이지 체크로 받고, 문안은 위 그대로.

## 7. 공급자 도구와 업로드 (Q1·Q2 끝 그림)

### 7-1. Q1 — 같은 앱의 모드에서 시작, 분리는 조건부

- 관측 [확인 §A]: 코치 전용 앱을 가진 곳(Onform·CoachNow·Trainera)은 **코치가 월정액을 내는 도구**, 마켓(Skillest)은 코치도 같은 앱, 폴댄스 7곳은 공급자 도구가 없다(운영자가 올린다).
- 끝 그림: 공급자에게 **자기 도구가 있다**(등록·재촬영·교체 · 학생 현황 · 정산 · 권리). 별도 앱인지 모드인지는 **공급자 수와 기능 폭**으로 정한다. 분리 조건 = 공급자 수십 명 + 학생 현황·정산. 그 전까지 같은 앱의 모드(Expo 라우트 그룹 하나, 역할 클레임으로 게이트).
- 실증: 링크 한 장 = 공급자 모드의 첫 화면. 항목: 동작 이름(기술 사전에서 고르기 또는 새 이름) · 선언 4개 · 촬영/파일 · 동의 · 업로드 → 결과(등록됨 / 실패 4형 / 재현성).

### 7-2. Q2 — 뒤쪽 자동화 4칸 + 폼이 대신 받는 선언 4개

오늘의 등록은 손 3단계다(§9-2). 끝 그림의 뒤쪽 4칸:

| 칸 | 내용 | 실증 |
|---|---|---|
| ① `reference/` 용 presigned PUT | 지금은 `uploads/*` 만 (§9-3). 올리면 학생 분석이 시작되므로 접두사가 달라야 한다 | 필요 |
| ② 업로드 트리거 → Pod 각도 추출 자동 | 지금은 `extract_reference_angles.py` 손 실행. angles 없으면 mode1 이 죽는다(§9-2) | 필요 |
| ③ Gemini A `clip_range` → 상단 `clipRange` 승격 | 지금은 `geminiA` 안에만. 런타임은 상단 `clipRange` 만 읽는다(§9-2) | clipRange 손 입력 유지 가능 |
| ④ name / athleteName / level 을 폼에서 | 없으면 앱 picker 가 버린다(§9-2) | 필요 |

폼이 **코드에 박힌 선언을 대신 받는다**(끝 그림):

| 선언 | 지금 코드에 박힌 곳 |
|---|---|
| 동작 이름(기술 사전 선택) | `REGISTERED_MOTIONS` 10개 고정(§9-4) |
| 스플릿 동작인가 | `SPLIT_LINE_ELEMENTS={"ref-power-spin"}`(§9-4) |
| 유지 구간이 있는가 | criteria yaml `hold_moment` 유무(§9-4) |
| 서 있는 자세에서 시작했는가 | 높이 자 바닥 = 서 있는 시작 전제 [기억 nnt §3] |

**기술 사전과 기준 인스턴스를 분리한다(설계, 내 초안).** 지금은 `ref-power-spin` 하나가 기술(criteria yaml·문구집·스플릿 여부)과 정은지의 실행(각도·clipRange·영상)을 겸한다. 공급자가 둘이 되는 순간 "power-spin 의 규칙"은 공유하고 "누구의 power-spin 인가"는 따로여야 한다. 폼의 "동작 이름"은 기술 사전에서 고르고, 기준 doc 은 `공급자 id + 기술 key + 버전`을 갖는다. 새 기술(사전에 없음)은 기본 경로(§7-3)로만 돈다.

입구 3개(링크 · 앱 모드 · 학원 콘솔)는 같은 뒤쪽 4칸을 쓴다. 끝 그림에는 셋 다 있다.

### 7-3. 새 동작이 자동 등록되면 무엇이 되고 무엇이 안 되나 (관측, §9-4)

새 기술 key 가 기본으로 받는 것: 벌림 감점 없음 · 신전 기준 없음(8관절 전부 BENT_OK) · Gemini 분류 "unregistered" · 문구집 `__common__` 폴백 · 안전 기본 분기 · 접점·앵커·썸네일 없음. 즉 **reference_relative(기하) + Gemini 지목 + "못 잰 부위 한 줄"** 로만 돈다. 그것이 얼마나 맞는지는 **봉인 시험지**로만 안다 — 그래서 §6 의 2층(자기 재현성)이 등록 절차의 일부여야 한다. 기술 사전을 채우는 것(criteria yaml·문구집·접점)은 공급자가 아니라 **플랫폼 운영**의 일이고, 실증 뒤 단계다.
