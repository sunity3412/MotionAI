## 1. 핵심 페인포인트

### 1-1. 자세 분석의 어려움

- **힘 포인트를 모른다** — "어디에 힘을 줘야 동작 수행이 가능한지 분석이 힘들다"
- **몸 쓰는 방향을 모른다** — "정확한 몸의 움직임 방향, 정확한 동작이 이루어지기 전까지 혼자 감잡기가 어렵다. 여러 번 통해 찾아야 한다"
- **어느 관절/근육이 문제인지 모른다** — "어디 관절 혹은 근육에 더 중점을 두어야 목표 기술에 도달할 수 있는지 혼자 파악하기 힘들다"
- **실패 원인을 모른다** — 동작이 안 될 때 왜 안 되는지 스스로 진단 불가

### 1-2. 피드백 수용의 한계

- **이론과 실전의 괴리** — "영상으로 보는 것과 피드백을 들어도 막상 실제로 다시 해볼 땐 안 와닿아서 어렵다"
- **개선 방법을 모른다** — "안 되는 부분을 개선하려면 어떻게 해야 할지 모르겠다. 손의 위치를 더 아래/위로 올린다던지, 다리를 무릎 위아래로 놓는다던지"
- **선생님 설명 이해 부족** — "설명을 잘 해주시지만 이해 부족"

### 1-3. 체형 개인화 부재

- **체형 차이** — "선생님과 체형이 다르다 보니 체형별 장점을 살리는 방법이 궁금하다"
- **체육 기초 없음** — "체육을(근육 움직임), 가동성을 깊이가 없어 어떻게 몸을 쓰면 동작이(기술이) 잘 나타날지 모름. 그래서 몸을 잘 쓰게 알려주는 선생님을 찾아다니고 있음"
- **디테일 분석 어려움** — 자세의 각도, 미세한 차이를 스스로 잡기 어려움

## 2. 원하는 것 (Wants)

### 2-1. 분석 기능

- **자세의 각도** — 관절 각도 수치로 현재 자세 객관화
- **동작 정확도 및 디테일 분석** — 단순 점수가 아닌 구체적인 부위별 피드백
- **실패 원인 분석** — "왜 안 되는지" 원인 제공
- **힘 포인트 시각화** — 어디에 힘을 줘야 하는지 구체적 가이드

### 2-2. 개인화 코칭

- **체형 맞춤 정보** — 내 몸에 맞춰 동작에 필요한 스트레칭, 힘 기르는 운동 동작, 동작에 따른 타깃 근육
- **쉐이프에 필요한 정보** — 유연성, 힘, 밸런스, 코어, 내전근, 전완근, 광배, 후굴, 전굴 퍼센테이지 등
- **개별 동작 성공 팁** — 동작별로 내 수준에 맞는 구체적인 팁

### 2-3. 성장 추적

- **자세 교정의 개선이 실제 점수로** — 노력이 수치로 보여야 동기부여
- **지속적인 성장 확인** — "개선됐는지 안 됐는지"를 객관적으로 확인

## 4. 개발 반영 우선순위

### P0 — 파일럿 전 필수

- [ ] **분석 결과에 관절 각도 수치 표시** — "현재 87° → 기준 110°" 형태로 구체화
  - `result.tsx` angleGuide 이미 구현됨, UI 노출 강화 필요
- [ ] **실패 원인 Top-3 명확히** — KISMAM Top-3가 "무릎 신전 부족" 수준이 아니라 "왜 이 동작이 안 되는지" 언어로 번역
  - Cerebras 프롬프트 개선 필요
- [ ] **분석 정확도** — 수강생이 "AI가 일반 답변만 한다"는 인식을 깨는 것이 신뢰의 핵심

### P1 — 조기 반영

- [ ] **체형 정보 입력 + 맞춤 피드백** — 키/몸무게/유연성 수준 입력 → 코칭 텍스트 개인화
  - Cerebras 프롬프트에 체형 파라미터 주입
- [ ] **타깃 근육 시각화** — 동작별로 "이 근육을 써야 해요" 시각적 표시
- [ ] **성장 델타 강조** — mode3 개선 후 "지난 분석보다 무릎 신전 8° 개선" 형태로 변화 수치화

### P2 — 이후 로드맵

- [ ] **체형별 스트레칭/보조 운동 추천** — "이 동작을 위한 준비 운동"
- [ ] **동작 성공 팁 카드** — 레벨별, 체형별로 분기
- [ ] **프라이버시 설명 화면** — 영상 처리 흐름 + 삭제 시점 명시 (우려 해소)

## 5. 강사(선수) · 학원 운영자 니즈 및 우려

> 이 그룹은 수강생의 직접 사용자와 다르다. **도입 결정권자이자 동시에 가장 큰 저항 세력**이 될 수 있다.
> 이들을 설득하지 못하면 학원 파일럿이 막힌다.

### 5-1. 강사(선수) 관점 페인포인트

- **각도보다 본질이 중요** — "폴댄스 포징은 각도가 중요한 건 아닙니다. 개개인의 신체적 조건에 따라 쉐잎은 다다릅니다. 자신의 힘과 유연성의 한계를 모른 채 자세의 완성도만 쫓아가는 게 가장 큰 문제점입니다"
  - → **AI가 각도 수치만 보여주면 강사 철학과 충돌한다.** 수치는 보조 수단, 핵심은 "힘과 유연성 한계 인식"
- **신체 부위별 독립 제어** — "각 신체 부위를 별개로 힘을 주고 푸는 방법을 어려워하고 미세한 각도 또는 본인의 몸에 맞는 움직임을 찾는 것을 어려워하는 것 같음"
- **이해와 실행의 괴리** — "머리로는 이해하더라도 폴 위로 올라가면 바닥에 있을 때보다 자유롭지 못해 디테일한 모양/각도/어느 곳을 밀어내고 당겨야 하는지 실행이 어려운 것 같습니다"
- **개인차 적용 불가** — "수강생마다의 신체 컨디션 및 센스가 달라 같은 피드백을 해도 적용될 수 있고 없고의 어려움"
- **기본기 표준화 부재** — "모든 학문에 논술이 뒷받쳐줘 자리를 잡아가듯이 폴댄스도 어느 정도의 기본 베이직 기초가 명인되어 학원 또는 강사 제각각의 수업 티칭으로 회원들에 건강과 안전에 문제점들이 조금이나마 방안되면 좋겠습니다"
- **부상 예방** — "영상으로 피득백하기에 전문반들이 혼자 연습이나 대회 개인 연습 시 다치는 경우에 도움이 되지 않을까. 힘이 강한 쪽으로 쓰려다 보니 통증 호소자에게 조금 더 도움이 되는 세밀한 분석을 잘 해낸다면 활용도가 높을 것 같습니다"

### 5-2. 학원 운영자 관점 니즈

- **수강생 성장 데이터베이스** — "대회에서 보다 정확한 기준이 될 수 있을 거 같고 운영하는 입장으로 수강생의 성장 데이터베이스로 활용성이 좋을 것 같음"
- **객관적 개선 확인 도구** — "수강생들이 영상을 찍을 때 영상 속의 모습으로 개선점을 찾는 것이 실제보다 자세히 보이기 때문에 어렵습니다. 분석 서비스를 이용하면 한 번에 눈으로 확인 가능하니 보다 빠르고 정확하게 잘못된 점을 찾고 개선이 가능할 것 같습니다"
- **기술 데이터 기반 표준화** — "기술 동작/방법 등 여러 데이터를 확립 후 정확한 방법을 산출해주시기 바랍니다"
- **앱으로 영상 다운로드** — "어플리케이션을 통해 시연자가 간편하게 본인 영상을 다운받고 볼 수 있으면 좋을 것 같습니다"
- **누적 성장 기록** — "어플화한다면 조작이 쉽고 분석한 데이터가 일시적이 아니라 계속 쌓여서 성장기록처럼 본인의 실력에 대한 피드백 기록이 되면 좋겠음. 같은 동작을 여러 번 분석하면 전에 분석한 기록과의 차이도 나타나면 좋겠음"

### 5-3. 강사/운영자 우려 — ⚠️ 이탈 및 도입 거부 리스크

| 우려 | 영향 | 기술 반영 방안 |
|------|------|---------------|
| **"AI가 완벽하면 강사가 필요 없어진다"** — "AI의 도입으로 티칭이 완벽하다면 더 이상의 인력은 필요하지 않아지지 않을까 하는 우려" | **매우 높음 — 도입 거부 원인** | AI를 "강사 보조 도구"로 포지셔닝. 강사 판단을 대체하지 않고 수강생 데이터를 강사에게 제공하는 구조 명시 |
| **분석 자료 무분별 배포** — "오너의 입장에서는 기술력과 노하우가 주요 수익원입니다. 분석 자료가 무분별하게 배포될까 그게 가장 큰 걱정입니다" | **높음** | 분석 결과 공유 제한 기능, 학원별 데이터 격리 |
| **분석 정확도 신뢰 부족** — "폴댄스 경우에는 고정되어 있는 폴도 있지만 돌아가는 폴도 있어서 인물을 제대로 찾고 분석이 정확하게 되어야 신뢰가 생길 것 같습니다" | **높음** | 스피닝 폴 대응 — NLF 3D 추적이 핵심, 파이프라인 정확도가 신뢰의 전부 |
| **강사 전문성 의심** — "대회 현장에서의 저지들에 대한 전문성 의심. 운영하는 곳에서 강사진들의 자질 또는 전문성 의심" | 중간 | 분석 결과가 강사의 피드백을 뒷받침하는 도구로 활용 → 강사 권위 강화 |
| **부상 유발 가능성** — "무리하게 따라하다가 부상 발생 등" | **높음** | 레벨 경고, 현재 유연성/힘 수준 대비 무리한 동작 시 경고 문구 |
| **정답 없는 스포츠** — "정답이 정해져 있지 않은 스포츠의 세계입니다. 누군가의 티칭이 옳다 그릇다 할 수 없지만, 적어도 일반인이 운동 삼아 접근하는 수준까지의 레벨은 80% 정도의 확고한 방법이 성립되었으면 좋겠다" | 중간 | "기준 모션은 하나의 참고일 뿐, 개인 신체 조건에 따라 다를 수 있음" 명시 |

## 6. 기술 반영 방안 — GSD 설계 필수 검토 항목

> ⚠️ **GSD에게 강조**: 아래 항목들은 단순 UI 개선이 아니라 파이프라인 설계와
> 직결된다. 구현 전 반드시 이 섹션을 검토하고 설계에 반영할 것.

### 6-1. 분석 철학 전환 (강사 니즈 반영)

```
현재: 관절 각도 수치 → KISMAM 점수
필요: 관절 각도는 보조 수단. 핵심 출력은 "힘 방향 + 유연성 한계 + 신체 부위별 제어"

Cerebras 프롬프트 개선 방향:
  - "무릎 신전 부족" (X) → "무릎을 더 펴려면 햄스트링 유연성이 필요합니다.
    현재 각도 기준으로 이 스트레칭이 도움됩니다" (O)
  - 각도 수치는 참고로만, 원인 → 해결 순서로 피드백 구성
```

### 6-2. 스피닝 폴 대응 (신뢰 확보 핵심)

```
현재 파이프라인: NLF 3D + 시간축 보간
추가 필요: 스피닝 폴 환경에서 인체 추적 안정성 검증
  - 폴이 회전할 때 배경 움직임 vs 인체 움직임 분리
  - verify_nlf_pipeline.py에 스피닝 폴 영상 추가 테스트 케이스 필요
  → 이게 안 되면 강사/운영자 신뢰를 얻을 수 없다
```

### 6-3. 부상 예방 경고 시스템

```
P1 구현 항목:
  - 레벨 대비 무리한 동작 감지 → "현재 유연성 수준에서 이 동작은 부상 위험이 있습니다"
  - 힘이 강한 쪽으로 쏠리는 패턴 감지 (좌우 불균형 → 통증 예측)
  - 후굴 동작: 요추 과신전 경고

기술 구현 포인트:
  - kismam 점수 외에 "위험도 스코어" 별도 산출
  - 온보딩 시 유연성/힘 수준 입력 → 동작별 적합도 체크
```

### 6-4. 강사 도구로서의 포지셔닝 (AI 대체 우려 해소)

```
강사가 불안해하는 이유: AI가 자신의 역할을 대체할 것 같다
해소 방향: AI는 수강생 데이터를 강사에게 제공하는 도구

구현 항목 (P2):
  - 학원 운영자 대시보드: 수강생 성장 데이터 일괄 조회
  - 강사용 리포트: "이 수강생은 무릎 신전이 3주째 개선 중, 햄스트링 집중 필요"
  - 분석 결과 공유 제한: 수강생 본인 + 담당 강사만 열람 가능 옵션
```

### 6-5. 누적 성장 기록 강화 (운영자 니즈 반영)

  - 같은 동작 반복 분석 시 회차별 개선 그래프

    → CloudFront 서명 URL로 앱 내 다운로드 버튼 구현

## 8. 설계 원칙 (전체 이해관계자에서 도출)

```
1. 수치는 보조, 원인이 핵심 — "고관절 72°"보다 "왜 이 각도가 안 나오는지, 무엇이 필요한지"
2. 원인 → 해결 순서 — 점수보다 "왜 안 됐는지 + 어떻게 개선하는지" 한 세트
3. 체형 인식 — 선생님 시범과 내 몸이 다름을 전제로 피드백 설계
4. 신뢰 구축 — 첫 분석이 "전문가 수준으로 구체적"이어야 AI 불신을 깬다
5. 강사 보조 포지션 — AI는 강사를 대체하지 않고 수강생 데이터를 강사에게 제공
6. 부상 예방 내재화 — 분석 결과에 항상 "이 동작의 위험 요소"를 포함
7. 데이터 투명성 — 영상/신체 데이터 처리 방식을 명확히 보여줄 것
8. 누적이 가치 — 1회 분석이 아니라 쌓이는 기록이 수강생과 운영자를 묶어둔다
```
