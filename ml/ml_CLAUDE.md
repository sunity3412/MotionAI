## 폴스포츠 CV 핵심 제약 (설계 이유)

```
폴스포츠는 일반 CV 알고리즘이 가장 자주 실패하는 케이스:

① 극심한 폐색(Occlusion): 폴(기둥)이 신체를 가림
   → MediaPipe 단독 사용 금지. 팔다리 좌우 혼동, 연결 손실.

② 상하 반전(Inversion): 뒤집힌 자세
   → 표준 포즈 추정기 인식률 급락. Perspective Rotation 필요.

③ 고속 회전(Spin): 빠른 회전 동작
   → 프레임 간 관절 연속성 깨짐.

→ 2D 포즈 추정(ViTPose 포함)은 접힌 인버트에서 천장 확인(plan.md #7-follow).
   3D HMR 백본 NLF 로 전환 — 인체 prior 로 가려진 관절을 3D 복원하고,
   시간축 보간으로 단일 프레임이 못 푸는 폐색 구간을 시퀀스로 메운다.
```

## 모델 선택 근거

| 모델 | 역할 | 단계 |
|------|------|------|
| MediaPipe BlazePose | 폐색 취약 — 사용 안 함 | - |
| YOLO11n | 인체 bbox 탐지 (NLF 입력 박스) | 현행 |
| NLF (Neural Localizer Fields) | 3D 포즈 백본 — 17 COCO joint 3D + 불확실도 | 현행 |
| ViTPose-S/H (2D) | 폴 폐색·인버트 천장 — 폐기 | - |

## 파이프라인 구조

```
영상 입력
  → ffmpeg 프레임 추출
  → YOLO11 (인체 bbox 탐지 — NLF 입력 박스)
  → NLF (박스마다 17 COCO joint 3D 좌표 + per-joint 불확실도)
  → 3D 관절각 계산 (compute_joint_angles — 투영 왜곡 자유)
  → 시간축 폐색 보간 (temporal — 불확실도로 접힌 프레임 복원)
  → FastDTW MotionDTW (기준 모션과 비교)
  → KISMAM 점수 계산 (0~100)
  → Cerebras LLM (코칭 피드백 텍스트 생성)
  → 상위 3개 교정 포인트 추출
```

## MotionDTW 2단계 동기화

```
1단계: 슬라이딩 윈도우 FastDTW → 동작 구간 탐색 (준비/대기 구간 제거)
2단계: 키프레임 정렬 → 기준 모션과 세밀 매칭 (O(N) FastDTW)

입력 특징 벡터: F = [Θ(각도), α·Θ̇(각속도), β·Θ̈(각가속도)]
좌표만 비교하면 속도 오류 발생 → 반드시 다중 모달 사용
```

## 점수 계산

```python
# 관절별 가중치 유클리디안 거리
D(R_i, I_j) = sqrt(sum(w_k * (R_ik - I_jk)^2 for k in joints))

# KISMAM 종합 점수 → Z-score 정규화 → 앱 표시 0~100
```

## 기준 모션 등록 흐름

```
관리자가 정은지 선수 영상 업로드
  → 동일 파이프라인으로 키포인트 추출
  → { 기술명, 선수명, 레벨, 키프레임 데이터 } JSON으로 Firestore 저장
  → 앱에서 기준 모션 목록으로 노출
```

## Mode별 측정 방식

**Mode 1 — 전문가 비교**
```
기준: 정은지 선수 키프레임 데이터
측정: MotionDTW로 관절 각도 편차 계산
출력: 유사도 점수(0~100) + "고관절이 20° 부족해요" 수준 피드백
```

**Mode 3 — 자기 성장 추적**
```
기준: 본인 이전 분석 기록
측정: 관절 각도 절대값 + 좌우 대칭 + 밸런스
출력: "지난주보다 팔 신전이 8° 개선됐어요"
의존성 없음 — 첫 영상부터 절대값 측정 가능, 두 번째부터 비교
```

## KISMAM — 수치 → 코칭 언어 변환

```
1. Z-score: 사용자 관절 데이터가 정상 범위에서 벗어난 정도 계산
2. 가중치 행렬: 편차 점수를 특정 문제 발생 확률로 매핑
3. Top-3 도출: "무릎 신전 부족", "팔꿈치 과신전" 등 코칭 용어로 변환
4. Cerebras LLM: KISMAM 결과를 프롬프트로 → 자연어 훈련 가이드 생성
```
